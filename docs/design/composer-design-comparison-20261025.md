## Nodu 有效规格与具体问题

以下 C 值来自当前源码和构建产物，均使用 CSS px。

| 元素 | 当前 C | 建议 P | 理由 |
|---|---|---|---|
| 侧栏最小宽 | 260 | 保留 260；常用 320–400 | 不靠增宽侧栏掩盖窄布局问题 |
| Composer 外间距 | 上4、左右12、下12 | 保留 | 已能和工作台建立稳定间隔 |
| 外框 | 1px、radius16 | 1px、radius12 | 减弱卡片感；不是核心功能缺陷 |
| 上下文行 | 实际上7、左右8、gap4 | 上8、左右12、gap4 | 与输入框使用统一内容轴 |
| Chip | 高24、radius5、文件名12px | 保留；+N 明确12/18 | 修复同一行字号不一致 |
| 输入区 | 14/22；padding12/14/10；56–180 | 14/22；padding12/12/10；56–180 | 保留中文阅读面积，统一左右12 |
| 工具栏 | 高28控件；左右8/底8；整行wrap | 保留尺寸；单行固定四槽 | 控件坐标不随名称和配置状态跳动 |
| 模式 | 原生select去外观；12/18 | 与模型使用同套弹层；弱背景 | 保持菜单、焦点与键盘体验一致 |

| 未配置 | 额外增加「配置」按钮 | 模型槽直接显示「配置模型」 | 同一职责只占一个槽位 |
| 发送/停止 | 28×28、不缩；图标16/13 | 保留尺寸与反色；独立固定槽 | 同位置、同命中区域；不追求更小 |
| 消息正文 | 13/20.8，输入14/22 | 统一14/22 | 减少阅读区到输入区的字号跳变 |
| 错误详情 | composer上方，详情可展开 | 保留位置；错误短行+动作 | 不让错误文字挤占底部控制栏 |

### 问题 A：6px 对齐偏差有明确的层叠根因

ContextPicker 第99行同时使用 `nodu-ai-context-row nodu-chat-context-row`。

- `tutor-context.css:3` 写的是左右14px、gap6。
- `tutor.css:50` 写的是左右8px、gap4。
- 构建 `bundle.css` 中前者约20105行，后者约23701行；同等 specificity 后者覆盖。
- 因此 chip 外边线是8px，输入首字是14px，相差6px。

后续只保留一个组件级规则或明确作用域，不能继续依靠 import 顺序。对齐定义为「chip 外边缘与输入首字基线」，不是要求 chip 内部文字跨过文件图标后仍与输入同轴。

### 问题 B：整行换行缺乏稳定约束

当前底栏为 `flex-wrap:wrap`。左右padding、边框和外边距扣除后，可用宽度约为侧栏宽−42px。260px 侧栏下约218px；长模型名与额外配置按钮会竞争空间。具体在哪个字符串断行仍需实机测量，但代码没有保证发送固定在同一行。

建议单行四槽：

```text
┌──────────────────────────────────────────┐
│  [file.c:24–40 ×]  [+4]                  │  ← 12px内容轴
│                                          │
│  输入文字…                               │  ← 同一12px轴
│                                          │
│ [+] [教学 ▾] [可缩短的模型名      ▾] [↑] │
└──────────────────────────────────────────┘
     固定   固定         弹性          固定
```

候选布局为 `28px max-content minmax(0,1fr) 28px`、gap4。模式约53–58px，按真实字体测量；在260px侧栏下模型槽仍有约92–97px。发送和模式不收缩，模型名省略；模型菜单内始终显示完整名称和供应商。

### 问题 C：字体继承导致 +N 比文件名大

公共 `.scope-widget button { font: inherit }` 可以覆盖单类字体声明。当前模型/配置有更具体规则，chip 文件名也有作用域；`+N` 则可能继承面板14/22。目标要求文件名、删除后的计数、底部文字均明确12/18，避免加载顺序决定视觉。

## 面积与增长预算

当前无错误且底栏单行时，composer 外框高度：

- 无上下文：约94 = 输入56 + 底栏28 + 底padding8 + border2。
- 有上下文：约125 =94 + chip24 + 顶padding7。
- 有上下文、输入到上限：约249。

目标保留输入高度，仅把上下文上边距改8：约94 / 126 / 250。**本方案不会把输入框压扁来制造“紧凑”感。** 主要收益是对齐、稳定控制行、明确权重和一致字号。

文本高度仍根据实际 scrollHeight 更新；达到180px后只在文字区滚动，不把工具栏滚走。狭窄高度窗口优先保留至少60px阅读区；若视口高度不足，未来可按可用空间降低输入上限，但不得低于56px。

## 状态与交互合同

| 状态 | UI 行为 |
|---|---|
| 无上下文 | 完全移除标签行占位；输入和底栏位置规则不变 |
| 1个文件 | 一枚24px chip，文件名可截断，完整路径在tooltip/菜单 |
| 多个文件 | 保留当前1/2枚+N聚合策略；不能增长成多排标签墙 |
| 长模型名 | 只截断名称，箭头与发送保留；不自动缩小字体 |
| 未配置 | 弹性模型槽显示「配置模型」；点击进入现有设置，无额外说明段落 |
| 生成中 | 同一28px槽把发送切为停止；保留已有草稿输入；发送新消息仍遵循现有忙碌限制，不承诺队列 |
| 失败 | 错误附近显示重试/详情；不将完整错误塞进底栏 |
| 聚焦输入 | 单一外框焦点色；无内外双框或光晕 |
| 键盘聚焦控件 | 仍有独立清晰焦点；不能用全局outline:none抹掉 |
| 菜单打开 | 继续使用body portal/fixed定位、8px视口避让、6px锚点间隔；方向键、Home/End、Escape与返回焦点保持 |

关闭态的模式胶囊可以用现有前景5%混色；模型采用透明底、弱文字，仅hover增强。供应商、模式行为等说明只在展开菜单中出现。

## 侧栏外围布局

- 不再新增第二行模型/状态工具栏；会话头保留 Theia 原生高度，图标命中区统一28px。
- 标题可用当前会话名，溢出省略，完整标题可查看；本轮不扩展多Agent页签。
- 消息区保留左右12px，正文统一14/22；代码块独立横向滚动，不能撑宽消息或整个侧栏。
- 当前有上下文的composer约125px并不异常；同一视口下，优先修复整行wrap导致的不确定高度。
- 教学任务摘要若后续加入，只占一条可展开状态行，不与额外的模型头、永久提示、完整计划长期叠加。

## 实施顺序与验收

1. **最高优先级：** 清理上下文重复规则、明确+N字体、底栏固定槽位、缺配置合并进模型槽。
2. **第二优先级：** 正文/输入字号统一，模式菜单与模型菜单统一行为，外框radius12。
3. **随后：** 会话标题、消息与空态的细节；保留现有滚动位置、草稿、IME与停止重试行为。

一次验收覆盖三档侧栏宽260/320/400，明暗主题，0/1/6上下文，短/长模型名，正常/未配置/生成中/失败，以及1/3/8行输入。不是对所有组合穷举，采用覆盖这些边界的代表组合。

可核验标准：

- 上下文外边缘与输入首字的设计轴偏差≤1 CSS px。
- 正常/未配置/生成中/长模型名切换时，发送槽到外框右、下边缘距离不变；停止不导致重新排版。
- 260px侧栏底栏始终单行，不出现横向页面滚动。
- 默认无上下文约94px、有上下文约126px；多行文字的增长可预测，上限180px。
- Chip与+N均12/18，正文与输入均14/22，不受公共button规则覆盖。
- 菜单不被外框裁切，鼠标和键盘均能打开、选择、关闭并回到触发按钮。
- 屏幕缩放后重新量测逻辑像素；不可直接拿Retina截图像素当CSS px。
