# STM32 串口交互设计

状态：**设计提案；未改应用实现，未完成实板验收。**

日期：2026-10-22。父方案：[K210 / STM32 底部面板 UI 设计](PROPOSAL.md)。

本轮按用户最新范围收敛为：**手动选择串口 → 设置波特率 → 点击连接 → 收发数据 → 手动断开。** ST-LINK 只作为下载器；本轮不考虑它的虚拟串口，不做端口与下载器自动关联、自动重连或下载后自动恢复。

## 1. STM32 的交互方式

STM32 采用一套独立于 K210 的底部 UI。普通 STM32 C / HAL 工程没有 Python 解释器，固定为“构建与下载 / 串口监视 / 终端”三个入口；文字居中、尺寸、颜色、停靠规则及基础阅读组件共用，内容和工具栏按 STM32 场景组织：

| 页面 | 内容 | 输入 |
| --- | --- | --- |
| 构建与下载 | IDE 发起的编译、下载、校验与复位日志 | 只读 |
| 串口监视 | 固件经 UART 发出的打印，以及用户主动发送的数据 | TEXT / HEX 发送栏 |
| 终端 | 本机 zsh、PowerShell 等 Shell | 真正的 PTY 输入 |

**程序运行时可以收发串口数据；发送内容有什么作用，由固件决定。** `status`、`led on` 是下图采用的示例固件命令，不是 IDE、STM32 或 HAL 默认支持的命令。只实现 `printf()` 的程序可能只会输出，没有解析输入的能力。

本例串口使用板载或外置 CH340。SWD 是 ST-LINK 的调试/下载接口，不是 UART；SPI 也不作为串口监视的模式。没有选择 UART、不接 USB 转串口或固件不打印，都不阻止 ST-LINK / SWD 下载。

## 2. 手动连接与界面

首次进入时，端口下拉显示“选择串口”，波特率可编辑；未选端口时“连接”禁用。刷新只更新候选列表，不自动选中或连接。选择端口后仍需点击“连接”。

```text
编辑器：main.c                               下载器 ST-LINK/V2
────────────────────── 可拖动分隔线 ───────────────────────────
  构建与下载      串口监视      终端                    ⋯   □   ⌄
              ━━━━━━━━
  [CH340 · COM5 ▾]  [115200 ▾]  ● 已连接  [断开]    查找  跟随  清空
────────────────────────────────────────────────────────────────
  17:06:32.112  RX   Temperature: 24.6 C
  17:06:34.230  TX   status
  17:06:34.245  RX   led=off, sampling=1000 ms
  17:06:35.870  TX   led on
  17:06:35.881  RX   led=on
────────────────────────────────────────────────────────────────
  [TEXT ▾] [输入要发送给固件的内容…                  ] [LF ▾] [发送]
```

连接成功后，“连接”改为“断开”；端口、波特率在连接期间不可直接切换，需先断开，再修改并连接。这样没有隐含的重新打开端口动作。断开后保留日志和草稿，发送禁用。

- 标签固定为 104 × 32 px，文字以内容框中心定位；活动下划线 80 × 2 px，水平居中。
- 按钮、下拉选中值及分段控件的文字水平、垂直居中。图标与文字作为整体居中；下拉箭头预留空间，不把选中值挤偏。
- 日志、输入草稿与长路径左对齐。控件居中不应用到等宽正文。
- 端口显示设备短名和系统路径/编号，例如 `CH340 · COM5`；完整路径可从 tooltip 查看。下拉项以系统枚举结果为准，不预置不存在的串口。
- 下载器状态与 UART 状态分别显示。“ST-LINK 已识别目标”不等于“COM5 已连接”；UART 断开不把下载器标为失联。
- 正文铺满面板，RX / TX 用窄列和文字区分，时间戳可关闭。时间仅表示主机收到/写入数据的时刻，不声称是固件采样时间。
- 不自动解释未知协议。文本中的 `ok`、`error` 不直接生成“LED 已开启”“命令执行成功”等结论。

## 3. TEXT、HEX 与发送规则

| 项目 | 首版约定 |
| --- | --- |
| 默认输入 | TEXT、空草稿；不预填命令，不在连接时自动发送 |
| TEXT 编码 | 首版 UTF-8；采用流式接收解码，保留跨数据块的残余字节，避免拆包汉字乱码 |
| 行尾 | 无、LF、CR、CRLF；使用用户明确选择的值。未配置时为“无”，发送栏直接显示；图中 LF 是用户已选示例 |
| HEX 接收 | 显示原始接收字节，不能把已经解码的字符串转成十六进制冒充原始数据 |
| HEX 发送 | 输入明确的字节对，例如 `01 03 00 00`；校验非法字符和奇数位，发送前显示字节数；默认不追加文本行尾 |
| 手动提交 | Enter 发送、Shift+Enter 换行；中文输入法组字时 Enter 不发送。按钮和键盘共用校验 |
| 发送反馈 | 主机完整写入后才显示 TX 成功回显；表示字节已写出，不表示固件已解析或执行。进行中、失败或部分写入分别标明 |
| 失败 | 保留草稿，显示真实错误；不自动重试、不向别的端口补发 |
| 正常运行中 | 串口已连接且未被下载占用时允许收发；没有“先停止程序才能发送”的 Python REPL 限制 |
| 历史 | 首版不做跨会话历史；之后若加入，只把选中内容放回草稿，必须再次手动发送 |

TEXT / HEX 的接收显示和发送模式应分别清楚标注。改变接收显示方式不发送数据；切换发送模式不立即把草稿当成另一种字节序列提交。HEX 模式下行尾控件禁用并写“无附加字节”。原始字节接口未完成前不展示假的 HEX 开关。

其他文本编码、定时发送、命令宏、协议自动解析与自动回复均不纳入本轮。任何连接、断开、切标签或下载结束都不自动发送或重放旧内容。

## 4. 基础阅读与状态

保留查找、跟随、清空、选中复制和时间戳开关。上滚时停止跟随，继续接收；新数据提示使用真实增量，点击后回到底部。清空仅清当前显示，不停止固件，不关闭端口。缓冲移除旧数据时提示历史不完整；无输出本身不是故障。

| 状态 | 显示 | 操作 |
| --- | --- | --- |
| 未选择 | “选择串口开始监视” | 选端口、波特率；连接/发送不可用 |
| 已选择、未连接 | `CH340 · COM5 · 未连接` | 连接；草稿可编辑 |
| 连接中 | “正在连接 COM5…” | 不重复连接、不发送 |
| 已连接、无数据 | “已连接 · 等待数据” | 正常发送、断开；不判为运行失败 |
| 正在接收 | “已连接”及真实 RX | 阅读、手动发送 |
| 手动断开/拔线 | “已断开”，保留日志和草稿 | 用户刷新、重新选择并连接；不自动重连 |
| 被其他会话占用 | 已知占用者或“端口被其他程序使用” | 重试或选择其他端口；不自动结束占用者 |
| UART ISP 下载中 | “串口正用于下载 · 发送已暂停” | 查看下载日志；草稿保留 |
| 写入校验完成、等待 BOOT 恢复 | “恢复 BOOT 并复位后，请手动连接串口” | 查看板卡说明；未连接前发送禁用 |
| UART ISP 失败/取消 | “下载未完成 · 串口保持断开” | 查看日志、重试下载；完成必要板卡恢复后可手动连接 |

收起、展开、最大化和切换标签都不改变连接或任务。UART 接收与下载器分别表达事实；不把“收到一行数据”解释为刚下载的新固件已正常运行。

## 5. 下载时怎么处理

### SWD 下载：保留用户已有 UART 连接

ST-LINK / SWD 是单独的下载通道，UART 监视保持当前状态；编译、下载、校验日志进“构建与下载”，固件 UART 数据继续进“串口监视”。固件可能在下载/复位时暂停或重启，所以收不到回复不直接判串口故障。

本轮不自动关联 ST-LINK 与 COM5；界面不能声称两者一定属于同一块板，也不自动开关用户选定的 UART。需要用户更换端口时，走明确的断开、选择、连接流程。

### UART ISP：先让出，完成后手动连接

用户对正被本窗口监视的同一端口发起 ISP 下载时，显示“COM5 正用于串口监视，下载需要先断开”，操作为“断开监视并继续下载”。确认后保留日志/草稿，禁用发送并把端口交给下载任务。其他窗口或进程占用时只显示占用，不静默抢占。

```text
下载期间
  COM5 正用于下载 · 发送已暂停                 查看下载日志
  原有日志和未发送草稿保留。

写入校验完成后
  写入校验完成。恢复 BOOT 配置并复位后，请手动连接串口。
  [ CH340 · COM5 ▾ ] [ 115200 ▾ ] [ 连接 ]
```

“写入校验完成”不是“程序正在运行”。需要恢复 BOOT 配置时，先提供当前板卡的操作说明；用户完成恢复并复位，再主动点击“连接”。下载任务必须已结束并释放端口；不能在 `needsBootRestore` 返回后自动重开串口。

下载失败、取消或拔线后保持断开，提供真实日志与重试入口。用户后续连接前仍需完成适用的 BOOT/复位操作；不假定未完成写入的程序可正常运行。恢复监视后无输出也不直接判失败，更不重发旧草稿。

## 6. 首版范围与验收

本轮仅做手动监视：端口枚举/选择、波特率、连接/断开、UTF-8 TEXT、原始 HEX、行尾、主动发送和基础阅读。原始字节通道与 UI 要一起交付；没有真实接口的控件不能表现为可用。

以下能力不在本轮：ST-LINK 虚拟串口方案、下载器与 UART 自动关联、自动重连/恢复、自动发送/重试、定时发送、协议解析、多设备并排、长期录制和跨会话发送历史。

验收重点：

1. 用户必须选择端口并点击连接；刷新、切页、下载结束不建立新连接。
2. STM32 无 Python 输入提示；构建与下载、UART 收发和本机 Shell 不混流。
3. 主机写入结果不冒充设备执行结果；未知协议保持原文。
4. 端口断开、占用、下载中均禁发且保留草稿；重新连接不重放历史。
5. 同 UART ISP 先显式断开监视；写入校验后提示恢复 BOOT 和复位，再由用户手动连接。
6. 无 UART 不阻止 SWD 下载；无 UART 输出不等于下载失败。
7. 中文输入法、跨包 UTF-8、HEX 字节校验、行尾和最后一行可见性均得到验证。
8. 标签、按钮、下拉文字居中；日志和草稿左对齐；窄面板下连接与发送操作可达。
