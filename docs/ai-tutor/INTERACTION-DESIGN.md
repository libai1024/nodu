# 教学与提问交互方案

2026-10-23 评审草案，等待与用户共同定稿。本文件与 [逐行跟写协议](LINE-GUIDANCE.md) 是最新交互决定，替代初稿的“步骤 / 对话”顶层导航。此次交付是设计与可交互示例；AI 回复、代码审阅和结果均为模拟，产品尚未接入。

## 1. 推荐方案与取舍

采用一个 AI 右栏、两种对话模式、三种直接作用于编辑区的辅助：代码高光、浮动批注、代码虚影。保留现有 Nodu 的字体、蓝色、边框、按钮和深浅主题。学习的中心是学生正在写的代码。

| 方案 | 优点 | 问题 | 选择 |
| --- | --- | --- | --- |
| 步骤、聊天、批注全部浮动 | 靠近代码 | 多窗遮挡、焦点混乱、窗口缩小时难管理 | 不采用 |
| 所有辅助只放右栏 | 安静、容易布局 | 讲解与对应代码分离，频繁往返阅读 | 不采用 |
| 右栏组织对话，编辑器显示当前辅助 | 讲解对应代码，步骤可收起，沿用工作台 | 需处理锚点、过期、浮层避让 | 推荐 |

界面只用必要的标签和当前反馈；不增加第二个 AI 顶级入口，不增加常驻解释段、装饰性二级标题或中点拼接文案。以下文档说明不直接搬进产品界面。

```text
┌───────────────────────── Nodu ──────────────── [AI ▾] ┐
│ 文件 │ sht30.c                        │ [教学] [提问] │
│      │ ③ if (sensor_receive(...) ...)│ 7/13 读取数据 │
│      │       return SENSOR_IO_ERROR; │ [检查本步]    │
│      │                               │ 全部步骤  ⌄  │
│      │ ⑦ if (sht30_crc8(...) ...) {   │              │
│      │   ↑ 实际代码虚影              │ AI 对话      │
│      │                               │              │
│      │     [当前行的短批注]          │ [继续提问…]  │
└──────────────────────────────────────────────────────┘
```

色板沿用原型：编辑区 `#14171c`、侧栏 `#181b21`、边框 `#343a45`、正文 `#e7eaef`、Nodu 蓝 `#2f5bff`、辅助高光 `#8fa8ff` 的低透明背景。正文沿用系统中文字体，代码使用项目等宽字体；没有单独的大标题字体。签名交互是“讲解指向代码，学生亲手完成”。

## 2. 教学与提问

| 行为 | 教学 | 提问 |
| --- | --- | --- |
| 对话输入 | 围绕当前学习目标，也能追问原理 | 直接回答当前问题，可引用选中代码 |
| 当前步骤 | 顶部显示进度、任务和检查按钮 | 隐藏课程区，不推进步骤 |
| 高光与批注 | AI 可通过结构化展示工具提供 | 只提供可点击的代码引用，不自动加教学标记 |
| 虚影 | 默认启用，显示当前行实际代码 | 隐藏，不写入文件 |
| 逐行审阅 | 完成行自动提交 AI，按行反馈 | 不自动提交教学检查 |
| 编译与硬件 | 沿用用户手动触发的原工作流 | 同左 |

教学必须能直接聊天，不能让用户为了提问而离开当前步骤。两种模式共用一个会话界面，但分别保存消息列表/上下文预算；切换不会静默把完整教学历史发到另一模式。用户可显式引用当前步骤或选中代码。

切到提问：保存教学会话，增加 teachingEpoch，停止新自动审阅，取消未完成教学请求并拒绝旧 epoch 的结果应用；隐藏教学装饰。切回教学：恢复进度与偏好，已变化依赖标为待检查，按新快照进入队列；不直接沿用旧通过标记，不把提问回复当课程完成依据。

暂停教学与切模式是不同操作。暂停停掉自动请求并隐藏虚影，已有批注保留为可读历史并显示过期状态；恢复时重新核对快照。普通提问仍可使用。关闭右栏只是布局变化，教学仍可在编辑器进行；右上角按钮的可见状态为“AI 教学”或“AI 已暂停”，不用微小圆点猜状态。

## 3. 编辑器中的三种辅助

### 高光

AI 可以请求强调一个符号/小段代码，使用浅背景与边线，不覆盖语法颜色、不建立真实选区、不移动光标、不自动滚动用户正在编辑的位置。默认一个当前关注点，最多三个关联范围，其他说明保存在对话里。点击对话中的文件行引用才定位并滚动。

错误诊断继续用现有诊断体系；教学高光不能全部染红，也不能冒充编译错误。范围与 snapshot、符号、摘要绑定；相关代码改动后旧标记失效。删除函数、切文件和计划改版均不能用旧行号硬贴。

### 浮动批注

行旁出现轻量批注标记。悬停标记或相关高光 250 ms，或者键盘聚焦后按 Enter，展开短批注；正文允许 1–3 句、代码引用和资料引用。鼠标可以移入浮层，离开后延迟关闭；Esc 关闭并把键盘焦点还给触发标记。一次只展开一条。

允许手动钉住批注。钉住只固定当前注释，不跟着光标跳；滚动时重新避让或退化为编辑器中的注释区。自动批注不抢焦点；AI 新增批注只显示标记，学生主动查看后才展开。所有批注在教学对话里有同等内容，不能只有鼠标才能读到。

优先放在相关代码下方的空白处，不能遮挡输入行、选区、补全列表、诊断浮层、底部面板和步骤浮窗。没有可用空间时用 view zone 或右栏引用，不缩小字体硬挤。窄版改为行下展开区。注释是教学元数据，不插入 `//`、不改源码、不进入复制或保存内容。

### 虚影跟写

默认显示下一行真实代码，和源码同字号、同基线；敲入的部分变为真实字符，剩余部分是灰色后缀。不是“这里实现 CRC”的任务意图。没有一键填入或 Tab 接受。用户写出另一种实现时隐藏不匹配的后缀，AI 按语义审阅，再根据实际代码生成后续候选。

Enter 完成行后自动检查：等待输入 → 检查中 → AI 已检查 / 需修改 / 待上下文 / 不可用。正确结果只留轻量标记，不弹祝贺、不刷屏、不自动播放讲解。问题说明指出一个具体修改方向；点击行标记可查看更多。学生可以继续自由编辑，不被网络锁住。

完整事件、批处理、输入法、多行代码、过期和取消约定见 [LINE-GUIDANCE](LINE-GUIDANCE.md)。AI 已检查、编译通过、运行已验证是三项独立事实。

## 4. 步骤与检查按钮

**需要检查按钮；步骤浮窗有用，但默认关闭。** 默认在右栏教学模式顶部显示一行任务与进度，下方放当前条件和“检查本步”。完整课程折叠，不同时显示全套大纲、目标、说明、提示层级。

检查本步读取当前源码规则、逐行审阅以及已有编译/测试/运行证据，返回具体缺项。仍有逐行请求排队时显示“行检查未完成”，不重复提交同一行，也不把未返回结果算作失败。缺少构建时显示“待编译”，缺少硬件结果时显示“待运行”；不能点击一次就悄悄执行编译、烧录、复位或连接串口。通过后用户选择“下一步”，不因某行通过跳步。需要真实测试时继续使用已有测试入口。

可选步骤浮窗是当前步骤的缩略视图，只有任务、进度、检查本步、关闭；不放聊天和整套大纲。由顶部 AI 菜单手动钉住，适合收起右栏或宽屏专注编码。初始放编辑器空白边角，允许吸附边缘和键盘恢复位置，不默认追踪光标。右栏收起/展开不强制改变这个偏好。

小窗口不足以同时展示代码和浮窗时，自动变成编辑器顶部单行条；只改变呈现方式，不停教学、不丢状态。步骤浮窗和右栏条件使用同一 store，不能各自维护检查结果。原型展示自由空间里的浮卡及窄版顶部条，不声称已经完成 Monaco 视口避让与拖拽。

## 5. 右上角快速控制

复用现有学习助手入口，收敛为一个分体式 **AI** 组件：

- 主按钮：展开/收起同一个 AI 右栏；标签带当前教学/暂停状态。
- 下拉：显示虚影、代码高光、浮动批注、步骤浮窗四项复选开关；最后一项是暂停/继续教学。
- 提问模式中四项教学显示控制暂不可用，但保留偏好；切回教学恢复。
- 隐藏虚影只控制显示，完成行检查仍进行。停止自动请求应使用“暂停教学”，文案不混用“关闭 AI”。

只保留这一套快速设置，不在右栏再复制四个眼睛/图钉按钮。菜单支持上下键、Home/End、空格、Esc 与焦点恢复。深浅主题、设置、右栏开关均不启动硬件操作。

## 6. 进一步的教学设计

机械跟写能帮助入门，但“敲完”并不证明理解。增加以下短环节，不能把每行都变成答题弹窗：

| 环节 | 直观表现 | 时机 | 范围 |
| --- | --- | --- | --- |
| 看一眼控制流 | 询问“CRC 不匹配会走哪条分支？”，点击选项后高光对应分支 | 关键逻辑处，按课程设计 | 首期轻量可选 |
| 跟写后小改写 | 学过温度 CRC 后尝试写湿度 CRC；可选择“自己写”暂时隐藏虚影 | 当前片段稳定后 | 首期课程内容；用户主动选择 |
| 结果对应代码 | 测试的期望/实际值可定位失败条件；串口消息仅在有可验证来源映射时定位 | 已有真实结果 | 测试映射 M6，串口精确映射后续 |
| 请求不同强度的帮助 | “解释本行”“给个例子”“继续跟写”按需出现在对话操作中 | 学生主动求助 | 首期，不建第三种顶层模式 |
| 回顾一次原因 | 步骤末尾用一句话解释为什么处理 CRC/超时；记录自述而非自动评分 | 每个概念一次 | 课程可选 |

“先读/预测，再运行、解释和修改”参考 [Raspberry Pi 教学原则](https://www.raspberrypi.org/teach/pedagogy) 与 [PRIMM](https://primmportal.com/)。短反馈以任务和下一步为中心，频率要由课堂观察校准，参考 [EEF 反馈综述](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/feedback)。这些是设计依据，不是本产品已验证的教学效果。

不自动撤掉用户要求的虚影；“自己写”是一段任务内可随时恢复的显示偏好，不另设复杂学习模式。也不把输入速度、照抄相似度或 AI 判断作为掌握程度的评分。

## 7. 展示协议与实现边界

AI 可以调用白名单 `showCodeFocus` 和 `showCodeNote` 展示工具，由 Node 校验、前端渲染。它们与只读代码查询共享作用域；不授予源码编辑、DOM、任意命令或硬件权限。

```ts
type TutorMode = 'teach' | 'ask';
interface TeachingPresentation {
  presentationId: string;
  sessionId: string;
  teachingEpoch: number;
  planHash: string;
  stepId: string;
  snapshotId: string;
  target: { sourceSliceId: string; symbolId?: string;
    startUtf16: number; endUtf16: number; contentDigest: string };
  kind: 'focus' | 'note';
  reason: 'explain' | 'review' | 'predict';
  text?: string;
  citationIds: string[];
  relatedPresentationIds: string[];
}
```

startUtf16/endUtf16 是相对 sourceSlice 文本的 UTF-16 半开区间 [start,end)，由宿主按版本快照换算成编辑器位置。范围必须来自本次允许读取的 sourceSlice，界限、大小、摘要和引用逐项验证；未知文件不显示。输出 schema 限制文本长度和范围数，采用纯文本/受限 Markdown。只接受完整结构化事件，不边流式输出边创建半截标记。前端检查 mode、epoch、documentVersion、planHash，抛弃过期结果。

- 前端：`TutorModeController`、`TutorPresentationController`、`TutorOverlayLayout`；Monaco decorations 表示高光，hover/content widget 表示批注，view zone 用于避让；ghost 继续独立 controller。面板、浮窗和顶部 AI 菜单共享状态。
- Node：负责模式/epoch、展示工具参数验证、来源范围、会话隔离与逐行队列；继续使用受控模型网关。仅保存课程/对话/展示元数据。
- Rust：继续解析符号、语句边界、依赖和失效范围，提供结构化定位信息；不负责 UI 浮层，不新增第二套模型请求或硬件连接。
- 依赖：复用 Theia 自带 Monaco、React、现有浮层/按钮与图标；不因这组交互引入第二套编辑器、全局 UI 框架或重型教学引擎。精确 API 在 M0 按捆绑版本核对。

## 8. 验收清单

| 范围 | 必测 |
| --- | --- |
| 模式 | 教学也能发消息；提问无自动检查；切回恢复进度；迟到响应不改变模式 |
| 高光 | 不移动光标/真实选区；保留语法色；头文件/函数变更后不贴旧锚点 |
| 批注 | 悬停可进入浮层；键盘可展开；一次一个；Esc 还焦点；钉住/取消；不遮输入行 |
| 虚影 | 实际代码、部分输入、不同正确写法；Enter 自动审阅；不自动写入文件 |
| 步骤 | 默认固定、可选浮窗、小窗口顶部条；按钮只检查现有证据；不跳步 |
| 快捷控制 | 一个 AI 入口；四项显示开关独立；暂停停止请求；关闭面板不停止跟写 |
| 教学 | 预测只出现在关键点；改写自愿；不能将行通过标记为工程/课程掌握 |
| 无障碍 | 键盘、中文 IME、屏幕阅读器、200% 缩放、减少动画；输入焦点不被新消息抢占 |

交互稿中的固定 CRC 判定只为了演示成功、错误与过期，不是正式 AI 实现。真实模型、Monaco、多行粘贴、拖拽避让、IME 与平台辅助技术的验收仍列入实施阶段。
