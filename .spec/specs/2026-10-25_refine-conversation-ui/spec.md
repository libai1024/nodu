# Nodu 会话界面对照优化与视觉验收 - 项目范围

## 1. 问题定义
- **项目目标**：依据 2026-10-25 Cursor/Nodu 实际 UI 对照，提高会话辨识、管理和视觉层级，并完成真实组件与桌面复核。
- **目标用户**：使用 Nodu 专业模式的嵌入式学习者。
- **核心价值**：无需反复打开对话即可识别任务，安全重命名和归档，保留草稿与教学状态。

## 2. 假设与待确认
### 2.1 已确认事实
- 集成 HEAD ba63cd6 已有200px会话栏、14/22聊天排版和新版composer；用户明确要求实施并视觉检查。
- 现有会话标题来自首条问题；缺少相对时间、重命名和归档。
### 2.2 关键假设
- 本轮是既有界面精修，不重做教学/硬件工作台。
- 本地重命名和可恢复归档属于已对照指出的会话管理需求，无需调用模型。
### 2.3 待确认问题
- 无。

提交与推送不在本轮授权范围，完成后保留未提交改动。
### 2.4 可选解释与取舍
- 选择可恢复归档，不实现永久删除；真实消息状态，不伪造工具过程。

## 3. 功能范围
### 3.1 核心功能（MVP）
- 短标题展示、上下文/草稿回退命名、搜索提示与空状态。
- 相对时间、真实消息状态与摘要，200px列表和260px聊天最小宽度不退化。
- 本地重命名、归档与恢复；旧schema记录兼容、保存失败反馈和跨窗口保护。
- 标题栏操作、弹层、键盘焦点及深浅色一致性。
### 3.2 扩展功能
- 无。
### 3.3 不在范围内
- 多会话tab、真实Agent执行器、Review审批、账户套餐、模型请求、硬件操作、全文Markdown重构、全局主题重设计。

## 4. 最小实现路径
- 扩展现有会话缓存元信息，复用既有React和弹出层；不新增依赖。
- 以现有消息状态派生列表标识；无额外网络状态机。
- 视觉验收一轮覆盖深浅色和窄面板，最多一次针对性纠偏。

## 5. 技术决策
- 技术栈：Theia/React/TypeScript，node:test。
- 允许改动：会话存储、tutor前端model/history/controls/widget、对应CSS/测试/视觉fixture和本任务文档。
- 不应触碰：用户真实聊天内容、外部测试工程main.c、既有未跟踪设计稿、服务商密钥、硬件/教学策略。
- Git integration branch：`codex/nodu-02-integration`
- 使用 --skip-git-branch：用户要求修改刚验证的最新集成界面；该分支未绑定其他活动包，不切回较旧main；既有三个未跟踪设计文档路径原样保留，不stash、不清理、不提交。

### 5.4 编排策略
- route: build
- immediate blocker: 主线程负责UI/model整合、构建与验收。
- ownership: GPT-6 sidecar独占common/tutor/tutor-conversation.ts与test/tutor-conversations.cjs；主线程独占其他前端、CSS、测试及文档。
- waiting strategy: UI按约定API实现，存储结果完成后主线程整合，不重复扫描存储实现。
- verification gate: TypeScript、tutor和workbench回归、深浅色/窄面板真实组件视觉检查及桌面加载。

## 6. 成功标准与验证方式
- 旧对话兼容且管理不丢失内容：node:test存储与model测试。
- 搜索、归档切换、重命名和键盘导航：生产组件handler测试与浏览器GUI。
- 深浅色、260px聊天、200px列表无溢出/裁切：真实组件fixture截图与DOM尺寸检查；桌面最新构建复核。
- 不调用模型/硬件：测试服务无发送断言与操作记录。

## 7. 风险与约束
- 多窗口旧快照可能覆盖元信息：专用元信息写入并在普通save中合并最新值；测试锁定。
- 视觉对照使用明确标为验收样例的隔离fixture，不污染用户profile。
- 检查最多2轮；无新增项或验证均通过即停止，不无限微调。
