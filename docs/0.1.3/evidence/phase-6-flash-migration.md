# Phase 6 evidence — firmware/flash path migrated to Rust

Scope: `nodu_device_worker.py` firmware commands + `nodu_firmware.py` +
`nodu_flash_probe.py` + the exercised kflash.py 1.1.6 MAIXLoader paths →
`desktop/native/crates/nodu-kflash/` (protocol/format layer) and
`desktop/native/crates/nodu-device/src/flash.rs` (worker orchestration).

## Differential coverage (offline, byte-level)

Python reference fixtures generated by `tools/diff/flash_fixtures.py`
(from the venv Python `~/.nodu/python/bin/python3`, pyserial available) →
`crates/nodu-kflash/tests/fixtures/python-expected.json` (~860 KB, 20
sections). Rust replays each case in `tests/diff.rs` — **18/18 pass**:

SLIP encode/decode, fixed ROM packets, ACK validation, ROM upload packets,
CRC32 vectors, strict `json.loads` (duplicate-key detection) and
`json.dumps` (indent/compact/sort_keys byte-identical), raw deflate via the
system zlib (CPython shares it), KFPKG packaging and restore-package
validation, boot-region parse, dump-script generation, backup frame
metadata, `py_int_base` (Python `int(x, 16)` semantics: ASCII whitespace
incl. `\x0b`, `+`/`-`, `0x_1f`, single inner underscores, rejects leading/
trailing/double underscores and `-_1f`), `BackupReceiver` scenarios.

Scripted serial sessions (`tests/session.rs`, transcripts from
`tools/diff/flash_sessions.py` driving Python `probe()`/`flash_image()`
against a fake transport) — **2/2 pass**, byte-for-byte on every serial
write, DTR/RTS edge, and baud-rate change:

- `probe_happy` — reset → SLIP link → RAM stub upload → DE/JEDEC read →
  return-to-boot → proof JSON.
- `flash_happy` — greeting → baud change → ISP stub install → dio write →
  reboot.

## Real bugs caught by the differential tests

- `rom_nop_request` emitted 15 bytes vs Python's 14 (`0xC2` + 13 zeros).
- `validate_ack` accepted an empty payload for an unrecognised op because
  the empty-payload comparison short-circuited before the op whitelist.
- kflash greeting wrote `0xC2` + 13 zeros; upstream writes `0xC2` + 12.
- The D2 flash-greeting and D5 reboot packets had the same +1 zero byte.
- `py_int_base` rejected Python-legal inputs (`0x_1f`, inner underscores,
  `\x0b` whitespace) and accepted none the reverse.
- `crc32` unit vector hardcoded a wrong constant (`0x96FB369C`; the real
  `binascii.crc32(8 zero bytes)` is `0x6522DF69`).
- `crates/nodu-kflash/assets/isp_prog.bin` at crate root was the 16,512-byte
  kflash ISP programmer, not the reviewed 8,672-byte probe stub
  (`probe.bin`, `dcc96436…`). `probe::stub_image()` now embeds the correct
  `src/assets/probe.bin` and fails the session test before this fix.

## Worker integration (`flash.rs`)

`prepareFirmware` / `backupDevice` / `flashFirmware` now dispatch into Rust
with the Python command semantics preserved:

- `session_id`/`requestNonce` binding, `flash_capacity_verified` state key
  (emitted as `flashCapacityVerified`), `capabilities.firmware = true`.
- Preservation before RAM probing: boot-header bounds, bounded `/flash` +
  `/sd` inventory, per-file snapshot with 64 KiB ranges and ≤3 retries,
  16 MiB prefix *candidate* (never a capacity certificate), reuse of a prior
  `.pre-probe` cache only after remote size+SHA re-checks, transfer
  preflight limited to one 64 KiB range hint, private dirs/files (0700/0600,
  `O_EXCL`), symlink rejection, `manifest.json` written at each stage.
- Probe: `probe::probe` owns the port while `PortLock` stays held; the
  installed firmware is always re-entered afterwards (25 s bounded,
  `restoring_io` bypasses cancellation) and the proof is bound to port,
  session and nonce before `flash_capacity_verified` is set.
- Backup: `with_fast_backup_serial` keeps the established REPL baud and
  always restores it + re-enters raw REPL (bounded, uncancellable); the
  backup pump is the Python line state machine (stdout/stderr framing,
  bounded trace with metadata only — no raw payload in diagnostics);
  diagnostics written to `<dest>.diagnostics.json` on failure.
- Flash: requires verified JEDEC proof + this-session verified backup whose
  manifest matches the proof; re-validates recovery package + remote boot/
  full-flash SHA + every preserved file and the file-tree shape; sets
  `flash_in_progress` (blocks stop/disconnect and queued requests like
  Python); writes manifest `flashVerification` on both paths; post-flash
  reconnect at the *original* baud, `os.uname` identity refresh, boot-header
  + payload SHA256 + boot-region SHA256 (header + image + prefix) checks.
- `backup_record` invalidation matches Python: cleared by `execute`,
  `runScript`, `writeFile`, `_close`, reconnect, and failed flash checks.
- `FirmwareError`/`ProbeError` surface as device errors; `ProtocolError`
  keeps its class so `handle()`'s stream-poisoned recovery still applies.
- `download` uses `curl` with per-read stall and total bounds (equivalent
  of `urlopen(timeout=20)` + the Python worker's overall bound).
- `manifest['restore']` commands name `python3 -m kflash …` (the Rust
  sidecar is not a `kflash` CLI); advisory-only text.

  Rust-side `do_backupDevice` transcript yet (needs a smarter mock board
