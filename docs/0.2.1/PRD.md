# Nodu 0.2.1 PRD：STM32 HAL 嵌入式 C 开发

日期：2026-10-22。状态：**待评审**。范围依据：[0.2 STM32 HAL 调研](../0.2/README.md)（P0 验证在 `spec/2026-10-20_validate-stm32-hal` 工作树，未提交）、[AI 教学设计](../0.2/AI-TUTOR-DESIGN.md)、[0.1.4 交接](../0.1.4/HANDOFF.md)。

优先级：**P0** 为 0.2.1 发布必须；**P1** 为应有，不阻塞发布时可延到 0.2.2；**P2** 为后续版本。

## 1. 背景

Nodu 目前只支持 K210 的 MicroPython 工作流：编辑脚本、送入 RAM 运行、管理板端文件、看相机画面。产品定位是嵌入式入门学习 IDE，而高校和培训课程的主线是 STM32 与 C 语言。学生现在要分别安装 CubeIDE（或 Keil、CubeMX 加 VS Code 插件）、编译器、ST-LINK 驱动和串口助手，第一次点亮之前就会在环境配置上卡住。

P0 验证已经证明默认工具组合可行：CMake / Ninja / Arm GCC 14.2 加官方 HAL，能完成 F103C8 与 F407ZG 的实际构建，并能通过 ST-LINK 识别和完整备份 F407（1 MiB，9.9 s）。写入与串口 ISP 四条实物路径尚未通过，见 [PLAN.md](PLAN.md) M0。

## 2. 目标与非目标

### 2.1 目标

1. **装好就能写 C。** 学生不需要安装 CubeIDE、CubeMX、Keil 或手动配置 PATH，也不需要先学 CMake。
2. **第一次点亮。** 从新建工程到 LED 闪烁、串口打印 Hello，全程在 Nodu 内完成。
3. **出错时知道改哪里。** 编译错误定位到行，附中文解释和修改方向；下载失败时指出是 USB、接线、供电、BOOT 设置还是芯片不匹配。
4. **不毁板、不丢数据。** 写入前核对芯片，首次写入前备份原程序；不修改选项字节，不解除读保护。
5. **工程不被锁定。** 工程是普通 CMake 工程，可导出后在终端、VS Code、CI 中构建；课程工程可移植。
6. **为 AI 教学打底。** 构建结果和运行结果绑定源码版本，供 0.2 教学辅助使用。

### 2.2 非目标

| 不做 | 原因与去向 |
| --- | --- |
| 断点调试、单步、变量与外设寄存器查看 | 适配器尚未选型（GDB 未带 Python，不能用 GDB 内置 DAP），放下一阶段，0.2.1 只预留接口 |
| 图形化引脚与时钟配置（CubeMX 式） | 体量大；HAL 配置通过 `hal_conf.h` 和代码完成，本身就是学习内容 |
| F1 / F4 以外的系列、ESP32、其他架构 | 每个系列都需要 SDK 包、板卡包和实测；0.2.1 只覆盖两颗芯片 |
| FreeRTOS、FatFs、LVGL 等中间件 | 课程后期内容，见调研 §7 |
| AI 教学辅助 | 依赖本版的构建与运行记录，在 0.2 后续版本推进 |
| Linux | 现有交付只有 macOS 与 Windows |
| 修改选项字节、解除读保护、整片擦除 | 风险高、初学者很少需要；读保护只检测并说明 |
| Keil / IAR 工程导入 | 编译器不同，转换不可靠 |

## 4. 支持范围

### 4.1 芯片与板卡

| 板卡包 | 芯片 | 首版内容 | 依赖的核对 |
| --- | --- | --- | --- |
| 正点原子探索者 F407 | STM32F407ZGT6，Cortex-M4F，1 MB Flash，128 KB SRAM + 64 KB CCM | 空工程、串口打印、LED 闪烁；时钟 HSE 8 MHz → 168 MHz | LED 引脚与极性、调试串口（板载 USB 转串口与跳线）、BOOT 跳线、HSE 频率与一键下载电路，均需实物核对（M0） |
| 通用 F103C8 | STM32F103C8T6，Cortex-M3，64 KB Flash，20 KB SRAM | 空工程、串口打印（USART1 PA9/PA10，与 ROM 引导串口一致）；时钟用 HSI 64 MHz，不假设外部晶振 | 用户实际板型（D6）；确认后再增加 LED、按键模板 |

板卡包里的每个引脚事实都带“已核对 / 未核对”标记。模板只使用已核对的事实；未核对的模板在新建向导里不显示。

### 4.2 下载方式

| 方式 | 工具 | 硬件 | 说明 |
| --- | --- | --- | --- |
| ST-LINK（SWD） | OpenOCD 0.12.0 | ST-LINK V2 / V2-1 / V3 及兼容下载器 | 默认方式；自动复位，不需要拨跳线 |
| 串口 ISP | stm32flash 0.7 | USB 转 TTL 串口（3.3 V），或板载 USB 转串口 | 使用芯片 ROM 引导程序；手动设置 BOOT0 并按复位。一键下载电路只在板卡包声明且实测通过后启用 |

### 4.3 主机平台

macOS 13 及以上（arm64、x64）与 Windows 10 / 11 x64。macOS 版本下限沿用 Electron 42 的要求，具体以打包时为准。每个平台都要在实物主机上完成两颗芯片 × 两种下载方式的验收，不能用一个平台的结果代替另一个。

## 6. 非功能需求

| 类别 | 要求 | 验证方式 |
| --- | --- | --- |
| 离线 | 工具包安装完成后，新建、编辑、补全、编译、下载、串口均不需要网络 | 断网后完成 S1 |
| 性能 | 首次打开工程到补全可用 ≤ 10 s；LED 示例增量编译（改一行）≤ 3 s；F407 写入 16 KB 程序并校验 ≤ 10 s（不含首次备份，P0 实测整片读出 1 MB 约 10 s）；参考机型 M 系列 Mac 与 4 核 x64 笔记本 | 计时记录（每项取 5 次中位数） |
| 体积 | 应用安装包增量 ≤ 30 MB（插件宿主、clangd 扩展与界面代码）；工具包下载 ≤ 150 MB（每平台）；安装后 ≤ 450 MB | 打包清单 |

## 9. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| P0 实物下载路径（写入、串口 ISP）尚未通过 | 方案基础未证实 | M0 最先完成；不通过时先修正下载设计，再进入界面实现 |
| 插件宿主体积、启动时间或 Theia 1.76 兼容性不满足 | clangd 接入方式改变 | M2 原型测量；不满足时改用自写 LSP 客户端（约多两周） |
| 兼容 ST-LINK 与兼容芯片（CKS32、GD32、APM32 等） | 识别失败或写入异常 | 识别 IDCODE 与设备 ID，提示并默认拒绝；收集常见型号的实测样本 |
| Windows ST-LINK 驱动缺失 | 无法检测下载器 | 检测并给出官方驱动说明；串口 ISP 作为备用路径 |
| 探索者板修订版差异（LED 引脚、串口跳线、晶振） | 模板现象不对 | 板卡包事实逐条核对，标注适用的板子修订版 |
| 工具包镜像不可用或很慢 | 首次使用卡住 | 离线包；多镜像；断点续传 |
| 工具链体积 | 下载时间长 | 只保留 v7-m 与 v7e-m+fp 多库，去掉 C++ / Fortran 前端与 LTO 工具；按 P0 实测约 141 MB 未压缩 |
| 品牌与 C 功能并行修改同一批界面文件 | 合并冲突 | 品牌只改设计令牌、图标和品牌组件；C 功能只新增组件和工具栏数据源，见 [PLAN.md](PLAN.md) §3 |
