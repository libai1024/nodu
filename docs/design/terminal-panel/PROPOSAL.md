# K210 / STM32 底部面板 UI 设计方案

状态：**方案已确认，首轮实现、构建、界面验证及本轮独立复核已完成。** 实际实现、测试证据与剩余边界见 [实现记录](IMPLEMENTATION.md)。最新用户要求优先：移除非必要的常驻解释文案，常用操作采用图标、tooltip 与无障碍名称，保留重要错误和需要行动的信息。下文保留设计阶段的目标与图稿说明，不代表所有提案项均已实现或完成实板验收。

日期：2026-10-22。分支：`codex/terminal-panel-ui`。基线：`749a2a9`。

范围：按用户最新要求，**K210 一套 UI，STM32 一套 UI**。两套面板分别按平台任务设计，共用控件与阅读规范。此前四标签通用面板的提议由本版替代。

本轮补充约束：STM32 首版仅手动选择串口、波特率并点击连接；ST-LINK 仅用于下载，不接入其虚拟串口，不自动匹配、关联或重连。串口 ISP 完成且 BOOT/复位恢复后，由用户手动重新连接。

## 1. 建议方向

**K210 围绕 MaixPy 运行和 Python 交互；STM32 围绕构建、下载和手动串口收发。**

主结构采用 VS Code 的底部标签与渐进会话管理；串口交互参考 Arduino；设备连接、运行和 Python 排错遵循 MaixPy 的使用场景；从 ZCode / Codex 借鉴项目上下文清晰、面板显隐与任务生命周期分离的交互。颜色、字体、图标仍使用 Nodu 现有设计系统。

| 平台 | 固定标签顺序 | 主要工作流程 |
| --- | --- | --- |
| K210 / MaixPy | **运行输出 · Python 交互 · 终端** | 连接开发板 → 运行/停止脚本 → 阅读输出或执行 Python |
| STM32 / C | **构建与下载 · 串口监视 · 终端** | 构建/下载固件；手动选串口和波特率 → 连接 → 收发 |

平台由当前工程类型确定，页头只显示当前平台的三个标签。K210 默认进入“运行输出”，STM32 默认进入“构建与下载”；同一工程内记住最后使用的页。切换工程时恢复各自标签和草稿，不把 COM 端口或 Python 历史串到另一个工程。工程类型未确定时先完成工程配置，不根据插入的 USB 设备猜平台。切换工程不会静默连接或发送；进行中的任务保留原工程归属，释放连接走显式操作。

两套 UI 各有上下文、输入方式、状态机和禁用条件；共用停靠容器、字体、尺寸、对齐、查找、滚动和可访问性规范。K210 不显示 STM32 串口工具；STM32 不显示 Python 交互。切标签只是切视图，不连接端口、不停止脚本、不重新执行命令。

REPL 是 Read–Eval–Print Loop（读取、求值/执行、输出、循环），用于输入一小段代码并立即查看结果。为初学者降低术语门槛，标签使用“Python 交互”，tooltip 写“Python 交互（REPL）”。普通 STM32 C 固件的交互走“串口监视”，命令由固件解析，详见 [STM32 串口交互方案](STM32-SERIAL.md)。

`zcode` 暂按 **智谱 / Z.ai ZCode** 理解，`maxipy ide` 按 **MaixPy IDE** 理解；ZCode 不等于 Zed。若用户指另一款 Zcode，只需调整参考分析，核心方案仍可评审。

## 2. 现状与需要解决的问题

已检查当前 Electron 窗口及源码；截图中的窗口为浅色主题，右侧帧缓冲打开，底部串行终端未连接。

| 当前表现 | 对使用的影响 | 本方案处理 |
| --- | --- | --- |
| 底部默认仅 160 px；内部又有标题、padding、带边框输出框和输入栏 | 真正能读的日志太少，像一个放大的表单 | 输出铺满面板；仅保留顶部分隔线，默认高度提升到约 28% |
| 简洁模式隐藏底部 Theia 标签栏 | 同时打开设备日志和多个终端时，缺少清楚的切换入口 | 每个平台内，简洁/专业布局使用相同导航 |
| 简洁模式“串行终端”有 REPL，专业模式同一入口只有 OutputChannel | 切布局会改变功能与操作位置 | 功能、草稿、连接、滚动位置跨布局保持一致 |
| REPL 初始文本是 `print(42)`；未连接时输入灰掉 | 用户不知道为何不能输入，也容易把示例误认成已输入命令 | 空草稿、真实 placeholder、就地说明禁用原因 |
| 命令回显是 system 日志，但控制台过滤 system | 看得到结果，找不到刚刚输入的命令 | REPL 显示命令与结果的完整往返 |
| “串行终端”“串口终端”“输出”混用 | 不清楚内容属于开发板还是本机 Shell | 按平台分成两套导航；每页显示目标与操作名称 |
| 已有滚动跟随，但没有新输出数量与缓冲截断提示 | 阅读旧日志时不知道新增多少，也不知道历史已经不完整 | 新输出提示、恢复跟随、明确缓冲保留范围 |

当前设备日志是 `text / stream / time`，不是原始字节，也没有可靠的运行/命令归属。现有原始串口终端是另一条 xterm + Rust 进程路径，且有端口占用检查。设计不能把“新标签”当成“已经支持的新数据通道”。

## 4. 信息架构与布局

```text
K210 / MaixPy
──────────────────── 可拖动分隔线 ────────────────────────────
 运行输出      Python 交互      终端                    ⋯  最大化  收起
 main.py ▾     K210 · 已连接 · 运行中                  查找  跟随  清空
 连续程序输出 / traceback
 Python 交互页才显示：>>> 输入 Python 代码…                    执行
```

```text
STM32 / C
──────────────────── 可拖动分隔线 ────────────────────────────
 构建与下载    串口监视         终端                    ⋯  最大化  收起
 CH340 · COM5 ▾     115200 ▾     已连接                  查找  跟随  断开
 时间            RX/TX   串口原始收发内容
 TEXT ▾   发送内容…                                      LF ▾  发送
```

以上为各自不同页的结构摘要。完整 K210 页见 [K210 图稿](terminal-panel-wireframes.svg)，STM32 页见 [STM32 图稿](stm32-serial.svg)。

两层工具栏的职责固定：

- **第一行是面板导航**：按当前平台显示三个标签，右侧为更多、最大化、收起。标签用文本和 2 px 活动下划线，不用胶囊按钮。不再重复一个“串行终端”大标题。
- **第二行是当前内容的上下文**：左侧显示来源、目标和状态；K210 右侧显示查找、跟随、清空；STM32 左侧就地选择端口、波特率和连接，右侧显示阅读工具，宽度不足时清空与时间戳移入更多。低频动作放更多菜单。终端页用自己的会话工具替换阅读工具。
- **正文是主要区域**：无内嵌卡片边框、无每行背景、无聊天气泡。时间和方向只是可选的窄列，正文左对齐。
- **输入栏只在需要时出现**：“Python 交互”明确显示 `>>>` 和“执行”；串口明确显示“发送内容”、行尾、“发送”；Shell 的 `$` / `PS>` 来自真正的 Shell。

面板沿用当前 Theia 底部停靠区域，初版不移动侧边帧缓冲与文件树。最大化只扩大底部区域，恢复后回到用户上次高度。关闭按钮语义是“收起面板”，销毁会话另有明确动作。

### 尺寸与窄宽处理

| 项目 | 建议规范 |
| --- | --- |
| 默认高度 | 工作区可用高度的约 28%，限制在 220–320 px；按工作区记忆 |
| 最小可拖动高度 | 180 px；再缩小使用收起，避免出现只剩工具栏的面板 |
| 标签栏 / 上下文栏 | 标签均 32 px；K210 上下文 28 px，STM32 上下文 40 px 以容纳连接控件；正文与输入之间仅 1 px 分隔线 |
| 标签控件 | 默认每项 104×32 px，文字在各自命中区内水平、垂直居中；不把整组标签摊满面板 |
| 活动指示线 | 80×2 px，与标签中心同轴，左右各内缩 12 px；状态变化不改变标签宽度 |
| 单行输入栏 | K210 40 px，STM32 54 px；多行可展开到 4 行，继续输入时内部滚动 |
| 正文 | 13 px 等宽字体，20 px 行高；正文左右 padding 12 px |
| 图标 | 16 px；命中区至少 28×28 px；标签和下拉命中高度至少 28 px |
| 面板宽度 ≥ 900 px | 完整设备短名、端口尾部、状态；三个阅读工具直出 |
| 600–899 px | 缩短来源名；完整端口放 tooltip；清空移入更多 |
| < 600 px | 隐藏次要路径；三个标签仍可到达，极窄时“终端”入溢出菜单；不横向裁掉输入栏 |
| < 480 px | 上下文条只保留目标选择与状态，阅读工具进入更多；多会话侧栏收起成下拉 |

以面板实际容器宽度判断，不以整窗宽度判断。验收至少覆盖 1440×900、980×720，以及两侧面板同时打开后约 460 px 的底部可用宽度。

### 对齐与控件细节（第二轮修订）

上一版图把文字放在固定左坐标，再独立绘制宽下划线，导致标签视觉偏左；按钮也用了固定左内边距。此轮统一为有明确边界的控件，文字与图标按控件中心定位。

| 对象 | 具体规则 |
| --- | --- |
| 两套 UI 的每个标签 | 104×32 px；文字中心为 `(52,16)`，水平与垂直居中。字号 13 px；英文与中文共用同一行盒，不为短名称“终端”另设左对齐 |
| 选中线 | 底部 80×2 px；中心与文字及标签一致。选中/悬停/聚焦均不改变控件尺寸 |
| 状态点/计数 | 固定保留槽或尾部叠加槽；出现/消失不推移标签文本中心；计数超出位数使用 `99+` |
| 标题栏工具 | 各 28×28 px，16 px 图标在中心；控件间距 4 px，右内边距 8 px；与标签共用 y=16 中轴 |
| 上下文工具 | 每个文字动作有独立命中区，文字居中；不用空格拼出“查找 跟随 清空” |
| 发送 / 执行 | K210 执行高 26 px，STM32 发送高 30 px，最小宽 60 px；文字双向居中。箭头如有，图标+文字作为一个整体居中，间距 6 px |
| 上下文 | 来源左对齐，状态组、动作组各有独立布局；同排文字的行盒垂直居中，长端口省略不挤压操作 |
| 输入行 | 文本、行尾下拉、发送按钮共用中轴；多行时输入顶对齐、动作与底部基线一致 |
| 选中状态 | 文字前景 + 下划线，不仅依赖颜色。hover 用现有 hover 表面；键盘 focus 用 2 px 内收轮廓；disabled 有原因提示 |
| 窄宽 | 保持控件命中区与文字居中；不足时将低优先级标签放视图溢出菜单，不挤成不等高或截断文字的标签 |

正文、代码、日志和表格仍左对齐；居中规则适用于标签、按钮与图标控件。矢量图使用中心锚点绘制，实际实现应由 flex/grid 居中，不依靠手调空格或文字坐标。

## 5. 两套平台界面

### 5.1 K210 · 运行输出

```text
 运行输出       Python 交互       终端                          ⋯  □  ⌄
 main.py ▾   K210 · 已连接   运行中                  查找  ↓  清空
 ── 本窗口运行 · 16:42:08 · main.py ─────────────────────────────
 Camera initialized
 fps: 24.7   objects: 1
 fps: 24.9   objects: 1
 Traceback (most recent call last):
   File "main.py", line 28  ← 可定位链接
 ValueError: invalid threshold
```

- 收纳 K210 脚本输出与相关设备操作日志。来源选择器只显示真实来源；STM32 构建与下载日志归 STM32 专用页面。
- 当前运行摘要是薄分隔行，包含文件、开始时间和真实状态；不把每次运行变成大卡片。仅有前端依据时写“本窗口运行”，不伪造全局运行编号或可靠归属。
- K210 `print()` 与 Python 错误出现在这里。REPL 命令产生的响应在可靠归属建立后进入 REPL，不混进当前脚本结果。
- 正常文本使用正文色；stderr 是错误/诊断流样式，不等价于“全是 Python 异常”。错误关键行红色，路径和行号带可点击样式，颜色之外有文本依据。
- 原始文本完整保留。展开诊断解释只能是额外信息，不能替换工具原文。
- 仅在路径、行号及源版本可核实时跳转；否则保留可复制原文。沿用现有 Traceback 版本检查。
- 无输入栏。停止程序继续使用顶层“停止”，面板收起与清空均不停止程序。

### 5.2 K210 · Python 交互（REPL）

```text
 运行输出       Python 交互       终端                          ⋯  □  ⌄
 K210 · MaixPy ▾    已连接 · 可执行                   查找  ↓  清空
 >>> import os
 >>> os.listdir('/')
 ['boot.py', 'main.py']
 >>> print(6 * 7)
 42
 ──────────────────────────────────────────────────────────────
 >>> 输入 Python 代码…                               执行 ↵
```

- REPL 是受 IDE 管理的 Python 命令执行视图。输入 `>>>` 提示符只是视觉标识，不伪装成本机 Shell 或原始串口控制字符终端。
- 命令与响应按提交顺序连续排列；多行命令用 `...` 延续提示，不为每条命令创建卡片。
- Enter 执行、Shift+Enter 换行；多行编辑时 `⌘/Ctrl+Enter` 执行本段。该快捷键只在 REPL 编辑器获得焦点时生效，不能同时触发运行整个脚本。
- 单行输入上下键查历史；多行仅在光标处于首/末行边界时进入历史。执行后清空已提交草稿并保留历史；执行失败保留草稿。
- 运行中仍可编辑草稿，执行禁用，旁边写“程序运行中，停止后可执行”；“停止程序”是独立显式动作，点击“Python 交互”标签不停止程序。
- 未连接时写“连接开发板后执行 Python”，提供“选择开发板”；不支持 REPL 的设备显示实际能力说明，不提供假的可点击输入。
- 本机历史仅限当前工作区和设备会话，清空显示不自动清除历史；菜单分别提供“清空显示”和“清除输入历史”。

### 5.3 两个平台各自的终端

以下展示 K210 的终端页；STM32 使用同样的 Shell 主体，上方仍保留“构建与下载 / 串口监视 / 终端”导航。

```text
 运行输出       Python 交互       终端                          ⋯  □  ⌄
 zsh · green-tracker ▾   本机                     + ▾  分屏  结束
 ~/Projects/green-tracker
 $ git status --short
  M main.py
 $
```

- 复用 Theia/xterm 的真实 PTY，不另外实现一个 textarea Shell。
- 默认会话在当前工作区目录启动。单会话只显示短名称；多会话在足够宽时显示约 150 px 侧栏，窄时用下拉切换。
- 保留新建、配置选择、分屏、重命名、结束与终端搜索。结束会话使用垃圾桶/“结束”入口，收起面板使用向下折叠图标。
- 不向 Shell 注入项目运行快捷键。Ctrl+C、Ctrl+R、Ctrl+E 应遵守当前终端类型；原始串口/网络终端的控制字节规则单独注册。
- TCP/UDP 原始终端保留在高级会话配置内，名称带“TCP 客户端”等类型；不要标成本机 zsh。

### 5.4 STM32 · 构建与下载

- 第一标签为“构建与下载”，容纳编译、链接、烧写及校验的连续工具输出，页内用来源选择区分任务。错误关联真实文件与行号，状态明确区分构建失败、下载失败和校验成功。
- 上下文展示当前工程、目标芯片和下载方式；“构建 / 下载 / 取消”只在适用状态出现。下载成功只说明写入/校验完成，不能推断用户固件运行正常或串口已连接。
- ST-LINK 仅是下载器；串口页独立手动配置。SWD 下载不主动断开独立 UART，没有串口也可以构建/下载。
- 串口 ISP 使用同一端口时需先让出串口，保留日志与草稿、禁用发送；写入校验完成后提示用户恢复 BOOT 并复位，再由用户手动连接。

### 5.5 STM32 · 串口监视

- 手动选择端口与波特率，点击“连接”；已连接显示“断开”。提供刷新端口列表，记住上次选择仅作为候选，不自动连接、不自动匹配或重连，不接入 ST-LINK 虚拟串口。
- 状态明确为未连接、连接中、已连接、已断开、被占用、下载占用；“已连接但没有数据”不等于程序失败。手动连接失败保留选择并显示错误及重试入口。
- 正文使用时间、RX/TX 与连续数据区；支持 TEXT / HEX，文本行尾选择无 / LF / CR / CRLF；HEX 基于原始字节，发送校验字节对，默认不加文本行尾。
- 程序运行时允许发送；发送条件取决于串口连接和占用状态，不沿用 K210“运行中不能执行 Python”的限制。
- 命令由用户固件解析；`status`、`led on` 只是示例，不是 IDE 内建命令。TX 记录表示主机写入成功，不代表设备已执行。
- Enter 发送、Shift+Enter 换行；中文输入法组字时不发送。失败保留草稿，不自动重发。TEXT/HEX、行尾、清空、跟随均有明确状态。
- 详细界面、状态转换和硬件边界见 [STM32 专门方案](STM32-SERIAL.md)。

## 6. 状态、阅读与反馈

| 场景 | 界面表现 | 行为 |
| --- | --- | --- |
| 首次无数据 | 一行说明 + 当前页唯一下一步，如“选择端口开始监视” | 不显示预填 `print(42)` 或装饰插图 |
| 已连接、未运行 | 连接文字“已连接”；运行状态“空闲” | 连接绿点不代表程序正在运行 |
| 正在运行 | 来源旁“运行中”，非活动标签小状态点 | 隐藏面板后继续运行 |
| 查阅历史 | 滚动位置/文本选区保持，右下出现“↓ 新输出 24” | 点击回到底部并恢复跟随 |
| 暂停显示 | 工具态写“显示已暂停 · 接收继续”，有恢复入口 | 不发送停止或断开命令；缓冲上限仍有效 |
| 拔线 / 断连 | 保留已有文本，顶部紧凑状态条“设备已断开” | 串口发送和 REPL 执行禁用；草稿保留；不假称会自动重连 |
| 端口占用 | 显示端口和已知占用来源，提供去对应页/切换入口 | 不自动杀进程、不静默抢端口 |
| 错误到达 | 当前页错误行可见；其他页用错误徽标提示 | 不因每个 stderr 抢焦点；用户主动发起运行的首次失败可展开输出并保留编辑器焦点 |
| 用户本次已收起 | 顶层面板按钮提示错误/运行状态 | 同次运行不反复弹开 |
| 缓冲截断 | 正文最上方“更早的输出已移出缓冲” | 不编造丢失行数；导出注明仅当前保留内容 |
| 清空显示 | 清空当前页/来源的可见缓冲 | 不影响其他页，不停止采集、不删文件、不清除 REPL 历史 |

“跟随”和“暂停显示”是两个动作。默认直出跟随；暂停显示放更多菜单以避免初学者误以为暂停了设备。新输出计数只能使用真实增量；未按完整行组装前以“条”计，不把事件数写成行数。

查找使用页内查找条：关键字、匹配数、前后跳转、关闭。默认在当前保留内容中查找，隐藏旧结果时不声称搜索了完整历史。日志过滤改变可见内容，复制菜单区分“复制选中内容 / 复制可见内容 / 导出当前缓冲”。

## 7. 视觉与键盘规范

- 延续 Nodu 浅色白底与冷灰工具栏、深色芯片墨工作台；复用 `brand/src/tokens.cjs` 与 Theia 语义令牌。本文和线框图中的色值为现有令牌解析值，应用代码不新建硬编码调色板。
- UI 使用现有 Scope Plex / 中文系统字体；输出、路径和命令使用 Scope Plex Mono，正文 13/20。浅色正文与深色正文均保持可读对比度。
- 蓝色只用于选中、焦点、主要执行/发送动作与进行中状态。连接成功、错误、警告同时有文字；正常日志不铺满绿色。
- 分隔线 1 px、控件圆角 3–4 px、无大阴影。去掉终端正文周围的内层框与卡片留白。图标使用现有 Codicon。
- 底部显隐沿用 Theia `core.toggle.bottom.panel`（⌘/Ctrl+J）；全局“终端”命令按当前平台键位解析后在菜单显示，不新增冲突的硬编码组合。
- 当焦点位于输出/串口/REPL 日志区时，⌘/Ctrl+F 查当前页，Esc 关闭查找并返回原焦点。Shell 的查找与快捷键复用 TerminalService。
- 标签按 tablist 语义实现：左右方向键移动、Home/End 首尾、Enter 激活；切标签不自动把焦点送进会执行命令的输入框。
- 拖动分隔线之外，提供键盘可操作的“增大 / 缩小 / 最大化 / 恢复”；焦点轮廓 2 px；图标有 tooltip、可访问名称与开关状态。
- 高频串口内容不逐条进入 aria-live；连接/失败等低频状态可播报，原始输出仍可键盘浏览和选择。

## 10. 设计验收标准

1. 新用户能从标签和上下文判断：当前看的是程序、端口、Python 交互还是本机 Shell。
2. K210 显示“运行输出 / Python 交互 / 终端”，STM32 显示“构建与下载 / 串口监视 / 终端”；简洁/专业切换不改变当前平台能力，会话、草稿、滚动与选区保留。
3. 280 px 高面板中，K210 输出正文约 220 px、Python 正文约 180 px；STM32 串口正文约 154 px。以真实控件占用验收最后一行完整可见，窄屏仍能发送/执行并找到更多操作。
4. 收起/展开/最大化/切标签都不调用连接、断开、执行、停止、销毁会话。
5. 中文输入法、多行草稿、粘贴长文本、重复发送、REPL 失败等有明确行为。
6. 高频输出下，选中文本可复制，上滚不被抢回底部，最后一行不被输入栏或横向滚动条遮住。
7. 断连、运行中、设备忙、不支持、端口占用分别给出准确文案；不存在不可解释的灰输入框。
8. 当前缓冲的搜索/复制/导出范围准确；已丢弃历史可见提示，不能声称日志完整。
9. 原始收发、REPL、系统 Shell 的控制字符与全局运行快捷键不串台。
10. 标签、按钮文字在各自命中区内双向居中，活动线与文字同轴；出现计数/状态不会引起文字位移。
11. STM32 只手动选串口、设置波特率和连接；不自动打开、不关联 ST-LINK、不自动重连；ISP 后恢复 BOOT 并复位，再手动连接。
12. 浅色/深色、1440×900/980×720、约 460 px 面板宽度，以及键盘导航均按同一结构验证。
