# Nodu 0.3 账号、AI 服务商与设备授权 - 项目范围

## 1. 问题定义
- **项目目标**：在现有 Nodu IDE 与多服务商 AI 能力上，增加官方账号服务与独立设备授权的自定义服务两条路径，并明确所有模型请求的许可、并发、计费和撤销边界。
- **目标用户**：使用 Nodu 的学习者、拥有自定义模型服务的用户，以及管理官方额度和单机许可证的运营人员。
- **核心价值**：官方服务可审计、可运营，自定义服务保持密钥和请求直连隐私；未启用 AI 时仍可编辑、编译、烧录、串口和本地确定性检查。

**2026-10-25 用户已授权执行 spec:run，并要求主 agent 安排多个 GPT 子智能体写代码、每 10 分钟汇报。** 规划快照见 `analysis.md` 与 `validation.json`；本轮按任务依赖实施可执行部分，主线程负责公共接口、集成与独立验收。真实商业授权、跨仓创建/发布、收费模型、生产服务和隐私敏感硬件采集仍遵守 D1–D6；不自动 commit/push。只有实际验证完成的任务可勾选，外部阻塞不得绕过。进度事实保存在 `execution-status.md` 和 `progress/`。

## 3. 功能范围

### 3.1 核心功能（MVP）
- [ ] 官方账号：外部浏览器 PKCE、短期 access、refresh 轮换/撤销、多窗口 single-flight、官方模型目录与额度原因。
- [ ] 自定义许可：管理员批次、一次兑换、设备证明、续租、离线余期、撤销水位、恢复/换绑/解除绑定。
- [ ] 统一 AI 边界：官方/自定义显式路由，所有生成和模型测试共用门禁；入队与实际发送前双重校验，取消和迟到结果隔离。
- [ ] 增量服务商能力：复用三协议，补 usage/能力/稳定错误、地址规范化和网络策略、凭据生命周期、revision CAS 与旧配置迁移。
- [ ] 官方云运营：共享接纳槽、预算预占、冻结价格、唯一结算 owner、核算/冲正、管理审计和安全的支付开关。
- [ ] 桌面体验与发行：紧凑账号/服务商/授权设置、未启用空态、键盘/窄窗/主题、目标平台身份与打包、升级/回滚验证。

### 3.2 扩展功能
- 后置：学校/团队多席位、教师云面板、分销结算、企业 SSO、远程 Web 授权、更多原生模型协议、自动化高级换绑。
- 硬件 attestation 若被确定为强制条件，必须回到 P0 收窄支持矩阵；不能同时“后置证明”又对外承诺已具备。

### 3.3 不在范围内
- 本轮允许按任务 boundary 编写代码、同步契约和运行隔离测试；不运行真实模型/支付/授权/硬件身份采集请求，不读取任何真实凭据。依赖优先从本机同锁版本隔离复制，必要下载须仅用于开发测试。
- 不改编译/烧录/串口/板卡协议和停止语义；不把电脑授权绑定到 STM32、ST-LINK 或串口。
- 不创建或发布云仓库、DNS、生产密钥、商户、部署资源；后续云任务必须先有独立仓库任务包和分支授权。
- 不更改课程内容、虚影算法或用户代码，不同步源码到云端，不添加任意工具执行/脚本/签名 oracle。
- 不自动把现有 GLM Key 上传为官方渠道，不自动赠永久许可，不因官方余额不足切到用户密钥。
- 不执行 commit、push、merge、归档完成或删除分支，也不修改其他活动任务包。

## 4. 最小实现路径
- 先校正基线和六项契约缺口，再用最小 PoC 验证上游结算、桌面登录、三平台设备身份；避免先把 UI 接到尚未确定的权限模型上。
- 云端条件满足后采用模块化单体；复用上游账号和唯一钱包。外部云工作由独立任务包承接，桌面通过版本化 HTTP 契约集成。
- 本地保留 `TutorModelProvider.complete`，在其前增加受控 Gateway 和调度器；复用已有三协议，不重复实现 SSE/parser/settings CRUD。
- 账号与许可证独立建模，按连接选择 provider；将账户/许可失效与教学 epoch、profile 修改、单窗选择分开，不用一个全局版本取消一切。
- 先用假上游和测试构造器跑故障场景，再少量验证真实协议/usage；生产不得包含“总是允许”开关，也不重放可能已生成的请求。
- 暂不引入微服务、第二密码库/钱包、插件化协议 DSL、跨产品统一身份框架或全平台证明系统；这些并不帮助首版闭合账号/许可/资金边界。

### 5.1 代码落点与兼容
- `desktop/scope-extension/src/common/{account,ai,licensing}/`：新增公开投影、RPC 白名单、错误/版本和 profile 契约；兼容既有 tutor API。
- `desktop/scope-extension/src/node/{account,ai,licensing}/`：账号、vault、许可客户端、受控 Gateway、调度器；复用 `node/tutor/tutor-ai-settings-store.ts` 和 `tutor-model-gateway.ts`。
- `desktop/scope-extension/src/browser/`：在现有 AI 设置和模型选择器增加官方/自定义/设备入口；不新建常驻运营栏。
- `desktop/native/crates/nodu-identity/`：独立受限身份 sidecar，不复用 `nodu-embedded` 进程。平台 FFI 若不可避免需小范围审查，禁止放松 workspace 的 unsafe 禁令。

### 5.2 必须先闭合的契约
- G1：入队冻结快照；取槽后重查身份、配置、有效 lease/撤销水位；异步云校验返回后发送前再次对比版本。online_required 每请求新校验，默认离线策略不被悄悄改成强联网。
- G2：区分 license revision、binding revision、本地 access revision；拒绝和恢复响应带可核验的版本/作用域，最高撤销水位不可被旧成功响应或旧缓存覆盖。
- G3：以可信 RPC connection 绑定窗口；选择 CAS、共享 profile CAS 和账号/许可全局失效分开。单窗切换不取消其他窗口，共享 profile 改动只影响使用它的请求。
- G4：refresh 端点不套用一般写接口的自动幂等重试；默认严格重放撤销 family，丢失轮换响应且无法安全恢复时重新登录。跨副本消费必须原子。
- G5：冻结官方 request/attempt/settlement 状态机及幂等摘要；锁定唯一扣款 owner、relay 扣费处理和结算 CAS，避免实时回调/对账/outbox 重放造成双扣。
- G6：数据库未决占位和 Redis 租约有一致准入协议；带 fencing/owner 版本，Redis 恢复后先对账，未确认停止的旧请求不能因 TTL 失效而重售槽。

### 5.3 关键不变量
- 所有生成路径（chat、line、step、goal 生成/AI 检查、模型测试）都经过同一 gate；远程模型发现也采用显式授权/数据策略。`inspectBuffer`/AST/WASI 的纯本地路径不被账号 gate 误关。
- 客户端不能自报账号、权限、绑定或官方上游 URL；官方 token 永不发给 custom origin，自定义 key 不进入账号/许可 API。
- 只有网络不可达等可恢复故障可用 lease 剩余期；明确撤销/签名错误/设备不匹配/时钟异常不可回退。新请求失效时只取消 AI，不影响硬件任务。
- 用户价格与渠道成本分开，使用精确整数/decimal 和不重叠 token 桶，接受时冻结价格；usage 缺失是待核算，不是免费成功。

### 5.4 编排策略
- route: build
- immediate blocker: 先完成 task-contract，主线程持有统一执行快照/发送前门禁、资金/slot 契约、公共测试入口和文档；其余任务遵循依赖。
- ownership: GPT 侧车独占 account 契约、license 契约、provider profile 契约各自文件和测试；GPT 上游探针独占 P0 研究证据；安全评审 lane 只读。每次委派明确 goal/scope/excluded/output/verify，文件范围见 execution-status.md。
- waiting strategy: 干净边界并行；共享池失败按精简一次重试/主线程吸收规则处理，不静默改模型；阶段进度落盘用于每 10 分钟只读汇报。
- verification gate: 主线程实际 compile/测试通过后才验收任务；子智能体自报不自动勾选。安全评审发现写回修复；D1–D6 未具备时记录阻塞，完整产品完成校验保持未通过。
