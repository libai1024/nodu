# 代码虚影跟写与逐行 AI 检查

2026-10-23 修订。用户明确要求：编辑器展示实际代码虚影，让学生对着敲；完成一行后 AI 检查一行。本文件替换初版“默认显示步骤意图、模型只按需审阅”的交互决定，其他证据身份和硬件边界保持不变。双模式、高光批注和快速开关的最新约定见[教学交互设计](INTERACTION-DESIGN.md)。本文件的自动检查只在教学模式未暂停时生效。

## 1. 用户看到的流程

1. 光标所在的待实现位置显示下一行真实代码虚影，例如 `if (sht30_crc8(data, 2) != data[2]) {`，不是“在这里检查 CRC”的文字说明。
2. 学生亲手输入。已经输入的内容是正常源码，尚未输入的后缀保持灰色。没有 Tab 一键接受、点击填入或自动应用；Tab 仍用于原编辑器缩进。
3. 按 Enter 完成该行后，行号旁显示“检查中”。AI 收到这一行和必要上下文，自动检查，不要求另外点“检查”。
4. 检查通过后，该行出现轻量“AI 已检查”标记，下一行虚影继续显示。完整行检查包含学习目的和语义，不是只比较文字。
5. 有问题时，在该行保留一个短反馈并允许直接修改。按 Enter 再提交，或修改完成后离开该行时重检。学生也可以展开右栏询问原因。
6. 学生继续自由输入不受阻止。指导模式默认等待本行结果后再提供下一行虚影；AI 延迟不能锁住编辑器、撤销、保存或编译。

教学面板同时保留对话，顶部显示当前步骤及“检查本步”，整体条件与全部步骤按需展开；正文中的意图、原理和资料只放在用户展开的解释中。默认编辑区不再出现意图提示卡。整步编译/测试与逐行 AI 反馈是不同层级：某行检查通过不等于工程可编译，也不代表硬件验证通过。

## 2. 虚影内容从哪里来

课程维护者预审代码演进路径，按步骤提供 GuidanceFragment；每个 fragment 包含可显示的候选代码行、所需符号、目标约束、引用和完整函数/块上下文。首期虚影优先用课程版本内的候选，参数从已确认的芯片、SDK、接口和接线配置解析；缺少关键参数时不把猜测代码显示为可照抄答案。

学生采用另一种有效实现时，AI 根据实际代码提出下一行候选；先校验候选所用 API 和上下文，再渲染为虚影。候选不写入文本模型。不能永远机械播放一份标准答案，否则学生改了变量名、错误处理方式或控制流就会越写越错。

原 L0–L3 改为解释的辅助层次，退出默认教学主流程。当前行的代码虚影默认可见，不再以“查看参考实现”确认框挡住它，也不把每行跟写都记作“主动查看完整参考”。只有用户主动展开完整函数/整步参考时才记录该动作。

## 3. 逐行完成事件

| 事件 | 处理 |
| --- | --- |
| 输入法组合中、普通按键 | 只更新虚影后缀；不提交模型 |
| Enter，旧行有新增/修改内容 | 捕获旧行结束时的文档快照，提交 `reviewLine`；排除换行后自动缩进 |
| 修改已有行后移到另一行/保存 | 在该行 350 ms 稳定后提交新版本；与 Enter 事件去重 |
| 仅自动缩进、格式化、撤销到原内容 | 若内容/语义上下文摘要没变，不新增相同请求；旧有效结果可以复用 |
| 多行粘贴 | 分别建立每行检查项；可一次请求返回多条结果，但不能只检查最后一行 |
| 注释/空行 | 不作为可执行教学代码，不虚报“AI 通过”；可显示无标记 |
| 跨行函数调用、表达式、宏、未闭合代码块 | 对本行返回通过/待补上下文/问题之一；需完整语句或块时保留待检查，不因暂时不完整立即报错 |
| AI 不可用或额度不足 | 显示“AI 检查不可用”，保留虚影和本地检查，允许学生继续；不冒充 AI 已检查 |

“完成一行”是前端明确的编辑事件，不用光标停留时长猜测。每条可执行或结构性代码行都建立记录；`if (...) {` 可以检查条件与进入块的合理性，但块整体还没完成时只给局部结论。闭合 `}` 触发受影响块的复查，让之前待上下文的行重新取得结论。

## 4. 接口、队列与过期

```ts
interface LineReviewRequest {
  sessionId: string;
  teachingEpoch: number;     // 切模式、暂停、切工程后拒绝旧值
  lineId: string;             // decoration/锚点身份，不是易变的行号
  revision: number;           // 同一行第几次提交
  reason: 'enter' | 'leave-line' | 'save' | 'paste' | 'context-completed';
  snapshotId: string;
  planHash: string;
  stepId: string;
  fragmentId: string;
  candidateDigest: string;
  lineRange: { start: number; end: number }; // 已定义位置编码
  sourceSliceIds: string[];  // 本行、函数、相关声明、条件、资料
}
interface LineReviewResult {
  teachingEpoch: number;
  lineId: string;
  revision: number;
  snapshotId: string;
  verdict: 'pass' | 'needs-change' | 'needs-context' | 'unavailable';
  reasonCode: string;
  feedback?: string;         // 短反馈，长解释按需展开
  citations: string[];
  dependencyDigests: Record<string, string>;
  nextCandidate?: { code: string; fragmentId: string; basisIds: string[] };
}
```

新增 RPC `reviewLine`，新增事件 `line.review.started/completed/cancelled` 与 `guidance.candidate`。模型输出经 schema 校验后才能更新行标记；下一行候选还须经过 API/引用检查。候选中包含代码不授予文件写入权限。

每工程一个逐行审阅队列，单行仅保留最新 revision，但不得因学生继续输入下一行而丢掉上一行的检查。默认一次一个模型请求；短时间多个完成事件可在 150 ms 内合并为 batch，返回逐行 ID 与结果。上限 20 条待检查行，超过时保留每行“待检查”并暂停自动提交、提供继续检查操作，不能静默丢弃。

同一行再次修改，取消该行旧版本请求；若请求包含其他行，取消结果应用或把该行设 stale，不丢掉其他有效行结果。依赖的声明/宏/控制流变化也使相关行 stale，只有 unrelated 修改不应全部取消。响应必须核对 lineId/revision/planHash/teachingEpoch/依赖摘要；行号移动用 decoration 重映射，不能把旧错误贴到新行。

本地语法/规则先运行，为 AI 提供确定信息；它不能替代用户要求的逐行 AI 语义检查。每次首次完成或实质修改的有效行提交 AI；完全相同的快照与模型/提示版本可复用已存在结果，日志标 cache。每行请求不重复发送整份课程或仓库，提供本行、所属语句/函数、依赖声明和相关目标；缺上下文时先追加允许的内容，仍不足则 needs-context。

逐行检查建议初始时限 8 秒，超时返回 unavailable，不强制等待默认聊天的 90 秒。体验目标为常见简单行 P95 3 秒内完成，须用实际候选模型验证，不作为当前性能承诺。默认不展示 token/费用小字，预算不足时明确提示，不悄悄降为字符比对。开启云端跟写时，设置界面明确每行完成会发送所选代码上下文；隐藏虚影仅改变显示，不停止自动检查；“暂停教学”或切到提问停止新教学请求，取消旧 epoch 结果应用。恢复教学时保留已输入内容，按新快照重检期间修改过的相关行。

## 5. 前端与 Rust 的具体改动

- 新 `tutor-guidance-controller.ts`：候选行、输入前缀、行 decoration、下一行推进；不使用默认 Tab 接受的 InlineCompletionsProvider。
- 新 `tutor-line-review.ts`：Enter/离行/粘贴/组合输入事件、行 ID、队列状态；避免与 Monaco undo/自动缩进混淆。
- 原 view zone 用于需要额外行高的候选行，行内后缀可用只读 decoration/injected text；不能只在 overlay 中放一个意图段落。与真实字符同字体、同字号、同基线，灰色虚影可读且不参与选择/复制/保存。
- 新 `TutorLineReviewCoordinator`：后端生成审阅上下文、批处理与去重；复用模型网关的凭证和预算。
- Rust 增加 `classifyLineContext`：用 tree-sitter 判断语句边界、依赖作用域与不完整结构，提供局部诊断和待上下文区间，不把它命名为 AI 检查。
- 主体 store 新增 lineReview 投影和 source dependency，完成记录仍由整步 contract 决定；逐行 pass 不绕过编译/测试。

当学生写法与候选不同，停止字符消除式后缀展示，保留学生输入并进行语义审阅；通过后用实际代码重算下一行。不能把查表 CRC、反向条件、变量改名等正确写法标成“未照抄”。若课程要求特定训练方法，约束必须先写进课程目标。

## 6. 原型与验收

交互稿提供真实可输入的示例行，灰色代码后缀随输入消失；Enter 后显示短暂检查状态，再展示演示结果/下一行。原型检查使用固定规则模拟，没有连接 AI，页面持续注明模拟数据；不能用这一演示宣称模型逐行审阅已实现。

新增验收：逐字输入、反向等价条件、错误条件、回车后立刻修改、换行/缩进/中文输入法、多行调用、粘贴三行、修改上游宏、连续五行、取消、离线、预算耗尽、切工程迟到结果。要求每一项代码行均有对应状态，编辑器不被网络阻塞；AI 行通过和工程/硬件通过有清晰区别。

本次修订把跟写从旧方案的候选变为主路径，M1 前端和 M5 模型调度各增加约 2–3 人日。加入双模式、高光批注、可选步骤浮窗与专门验收后，当前首期总工作量为 48–72 人日；分项见[路线图](ROADMAP.md)，仍需 M0 原型校准。
