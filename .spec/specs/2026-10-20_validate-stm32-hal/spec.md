# STM32 HAL P0 验证

## 1. 问题定义
- **项目目标**：固定工具与官方 HAL/CMSIS，实际构建 F103C8/F407ZG，逐项记录 ST-LINK/UART 下载证据。
- **目标用户**：Nodu 开发者与嵌入式课程学生。
- **核心价值**：为后续集成提供可复现命令、产物与硬件结果。

## 2. 假设与待确认
### 2.1 已确认事实
- macOS arm64；用户已连接 F407 ST-LINK；当前串口为 K210。
- 主 checkout 有其他改动，本任务采用干净 managed worktree。
### 2.2 关键假设
- 最小实验使用内部 HSI 与 RAM heartbeat，降低未知晶振和板载器件依赖。
### 2.3 待确认问题
- 无

当前已知外部约束：用户已尝试接入 F103 下载器，但主机尚未枚举；STM32 UART 连接未具备，下载项保持未验证。
### 2.4 可选解释与取舍
- 固定 CMake/Ninja/GCC 与 SDK；模拟结果不替代实物下载。

## 3. 功能范围
### 3.1 核心功能
- 两芯片 HAL 工程、工具/SDK 版本锁、ELF/BIN/HEX、容量与目标检查。
- OpenOCD/stm32flash 适配命令，F407 ST-LINK 识别、原 Flash 备份、写入、读回和运行观察。
### 3.2 扩展功能
- 无。
### 3.3 不在范围内
- UI 集成、RTOS、课程制作、跨平台发行包和插件宿主。

## 4. 最小实现路径
- 配置脚本位于 tools/stm32-p0；下载物、SDK、构建和设备备份位于忽略的 .local/stm32-p0。
- 直接调用官方 HAL，固定源码和工具摘要。
- 本轮不引入完整包管理器、自写下载协议或 UI 框架，聚焦可复现验证。

## 5. 技术决策
- Git integration branch：`spec/2026-10-20_validate-stm32-hal`
- 从用户当前 HEAD 的干净独立工作树创建；初始化使用 --skip-git-branch，因分支已创建，避免切换另一 checkout 的 main。
- 允许改动：tools/stm32-p0、此任务包、专属 .gitignore 规则；根据用户后续要求更新 docs/0.2 的 STM32 开发文档及 docs/README.md 导航。
- 不触碰：主 checkout 用户改动、现有 UI/K210 和 K210 串口。
### 5.4 编排策略
- route: build
- 主线程负责工程、工具、构建、设备与验收；只读 sidecar 核对官方来源与引脚，不修改文件或访问设备，主线程核验其结果。

## 6. 成功标准与验证方式
- 两芯片实际编译链接，ELF 架构/容量正确。
- 工具版本输出、官方摘要和 SDK commit 可追溯。
- 每条硬件路径记录身份、写入读回和运行；缺硬件保持未通过。

## 7. 风险与约束
- 写入前识别目标并备份 Flash，不自动解除保护或修改 option bytes。
- 外部硬件条件不满足时不能归档为全部完成。
