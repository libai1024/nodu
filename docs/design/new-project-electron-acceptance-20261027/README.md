# 新建项目：独立 Electron 界面验收

日期：2026-10-27。平台：macOS Apple Silicon，Retina 2×。本轮验证共享表单在启动台和 IDE 居中窗口中的实际表现。结论：**布局、表单行为和真实创建路径通过；发现的 Arduino 主文件未自动打开问题已修复并通过一次定向复验。**

## 隔离与方法

使用单独的 `Nodu New Project Check.app`，bundle ID `dev.nodu.new-project-check-20261027`，端口 `24386`，应用/配置/临时项目均在 `/private/tmp/nodu-new-project-electron-20261027-tDbP3p`。没有操作已有的 24379 预览、Nodu Review、用户 Arduino 数据或物理串口。

本记录是本地编译产物的 Electron 验收，不是最终安装包验收。Arduino home 来自本轮已通过冷测的测试环境 APFS 副本；这个 UI 测试不重复声称空 home 冷启动。冷启动的网络隔离和真实编译证据见 [离线验收](../esp32-arduino-offline-acceptance-20261027/)。

全部界面操作通过 CUA 原生应用 API 完成，包括菜单、输入、点击、拖动窗口边缘、滚动和快捷键。没有 Playwright、CDP、AppleScript 或 DOM 注入。文件系统读取仅用于确认实际生成内容及归档。截图由 CUA 原样保存为 JPEG，并附 AX 文本；未修改截图像素。

## 发现与集中修复

从 IDE 新建 `ui_esp32_c3` 后，文件正确生成且工作区正确切换，但中心编辑区为空、运行入口禁用（14）。等待后仍未自动打开主文件。通过文件抽屉手动打开 `ui_esp32_c3.ino` 后立即显示代码、运行入口可用（15）。集中修复后重启同一个独立应用/profile，再从最近项目打开原 C3：已有主文件恢复（19）。随后从 IDE 菜单创建全新的 `ui_esp32_c3_fixed`，没有打开文件抽屉或点击任何源码文件，中央立即出现同名 `.ino`，编辑器获得焦点，运行入口可用（20）。通过编辑器写入测试注释并保存，磁盘内容与画面一致（22）。一次定向复验通过，没有重复已经通过的布局路径，也没有执行运行、烧写或打开物理串口。21 保留第一次编辑按键定位不符合预期的中间状态，22 已通过界面恢复为有效 C++ 源码；这不是产品错误。
