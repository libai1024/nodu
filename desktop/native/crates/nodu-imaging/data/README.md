# Pinned image data

These binary arrays are generated by `tools/refs/import-imaging.py` from Git
objects at `openmv/qt-creator@af179e44cddf396a5ab618792d71e9de5cc67032`.
The importer verifies each array's length and SHA-256 before writing anything.
Application builds consume these committed files and do not fetch references.

- `lab_table.bin`, `yuv_table.bin`: 65,536 triples of signed 8-bit values from
  `src/plugins/openmv/histogram/{lab_tab,yuv_tab}.c`, in the original byte-reversed
  RGB565 index order.
- `rb528_table.bin`, `g628_table.bin`, `rb825_table.bin`, `g826_table.bin`: unsigned
  8-bit quantization tables from `src/plugins/openmv/histogram/rgb2rgb_tab.c`.
- `tag*.bin`: little-endian 64-bit code words from
  `src/plugins/openmv/tools/tag*.c`; family dimensions and code counts are checked
  by the importer.

Full notices are retained in `desktop/THIRD-PARTY-NOTICES.md`.

The complete LAB/YUV arrays match the complete-array branch of MaixPy-v1
`d8901fd2272f000226f1c1037c1eb7c412b88e66`. That firmware also has a conditional
compressed-table implementation. Matching the original IDE algorithm does not
establish equality with every firmware build, nor with sensor pixels before
lossy JPEG compression.
