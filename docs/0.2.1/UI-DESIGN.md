# Nodu 0.2.1 界面设计：嵌入式 C 工作台

日期：2026-10-22。状态：**待评审，未实现。** 需求编号见 [PRD.md](PRD.md)，效果图见 [mockups/](mockups/README.md)。

## 1. 原则

沿用 0.1.x 已确认的原则，只在 C 开发需要的地方扩展：

| 原则 | 在 C 工作台中的体现 |
| --- | --- |
| 以代码为中心 | 简洁模式默认只显示编辑器；问题、串口、文件都是按需打开的面板 |
| 每项功能一个可见入口 | 编译只在工具栏和 ⌘B；下载方式只在设备弹层；备份与恢复只在设备弹层 |
| 界面不放过程说明 | 只在需要学生动手时显示引导卡（BOOT0、驱动），完成即消失 |
| 按项目类型切换，不并排堆功能 | K210 项目与 C 工程用同一工作台、不同工具栏配置；同时可见的控件不超过 9 个 |
| 状态有颜色，也有文字和图标 | 写入中同时显示琥珀色、“勿断电”文字和进度百分比 |
| 品牌只来自设计令牌 | 本文只使用语义令牌（§10），色值由品牌会话决定 |

## 2. 信息架构

| 区域 | K210 MicroPython 项目（不变） | STM32 C 工程（新增） |
| --- | --- | --- |
| 工具栏左侧 | 项目 ▾、运行 ▾、停止、设备 | 项目 ▾、**编译**、运行 ▾、停止、设备 |
| 工具栏中部 | 设备错误提示 | **任务条**：编译、下载的步骤与结果；设备错误提示 |
| 工具栏右侧 | 文件列表、串行终端、帧缓冲、更多 | 文件列表、**问题与串口**、更多 |
| 左侧栏 | 资源管理器；专业模式另有开发板文件、搜索 | 资源管理器；专业模式另有**大纲**、搜索 |
| 底部面板 | 串行终端（简洁）/ 输出（专业） | **问题 · 串口监视器 · 编译输出** 三个标签 |
| 右侧栏 | 帧缓冲 | 空（调试阶段放外设与变量） |
| 设备弹层 | 串口、板型、复位方式、文件、固件 | 开发板、下载方式、下载器 / 串口、芯片信息、备份与恢复、工具包 |
| 状态栏 | 固件版本、串口、FPS | 开发板与芯片、Flash 占用、下载方式、行列 |
| 主区（无项目时） | — | **开始页** |

C 工程的工具栏可见控件：项目、编译、运行、更多运行方式、停止、设备、文件列表、问题与串口、更多，共 9 个，与 0.1.4 的 K210 工具栏数量相同。去掉的是帧缓冲开关（C 工程没有相机流），新增的是编译。

## 3. 工具栏

### 3.1 布局

```
┌────────────────────────────────────────────────────────────────────────────────────────────┐
│ [n] [▢ blink-f407 ▾] [⚒ 编译] [▶ 运行|▾] [■]  [● 探索者 F407 · ST-LINK ▾]   ··任务条··   [▤] [▭²] [⋯] │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 高度、间距、圆角沿用 0.1.4（44 px，控件 26–28 px）。品牌标志为单色镂空版，状态点保持界面里唯一的彩色圆点（品牌提案 04）。
- **编译** 是次要按钮（描边样式）：不接板也能用，所以与“运行”分开。“运行”保持主色实心按钮，学生最终要的结果是程序在板上运行。
- 问题与串口开关的图标右上角显示错误数徽标（例如红色 `2`），没有错误时不显示。

### 3.2 编译按钮的状态

| 状态 | 外观 | 可用操作 |
| --- | --- | --- |
| 空闲 | `⚒ 编译` | 点击编译；⌘B |
| 编译中 | 旋转图标 + `编译中`，`aria-busy` | 停止按钮变为红色可用 |
| 工具包未安装 | `⚒ 编译` 正常显示 | 点击打开工具包安装对话框（§5.3），不禁用按钮，避免学生不知道为什么点不了 |
| 工程未信任 | `⚒ 编译` 正常显示 | 点击打开信任确认 |

### 3.3 运行按钮与“更多运行方式”

“运行”执行完整流程：保存 → 编译（需要时）→ 下载 → 复位运行 → 打开串口监视器（F1）。▾ 菜单：

```
运行（编译并下载）            ⌘R
────────────────────────────
下载方式                      ▸  ● ST-LINK（SWD）
                                 ○ 串口（ISP）
复位开发板
清理并重新编译
────────────────────────────
备份与恢复…
```

“下载方式”同时出现在设备弹层里，两处修改的是同一个 `nodu.json` 字段。这是本设计中唯一的重复入口，保留它是因为切换下载方式常常发生在下载失败之后，而失败时学生的注意力在运行按钮附近。

### 3.4 项目 ▾

```
新建项目…                     ⌘⇧N
打开…                         ⌘O
示例                          ▸
最近的项目                    ▸
────────────────────────────
新建文件                      ⌘N
新建模块（.c + .h）…
────────────────────────────
保存                          ⌘S
另存为…
导出独立工程…
工程设置…
```

K210 项目的项目菜单不变；“新建项目…”在两种项目里都有，并进入同一个向导（§5.2）。

### 3.5 任务条（工具栏中部）

任务条只在有任务或刚有结果时出现，显示当前任务的步骤：

```
编译中 · main.c                                         （编译）
✓ 编译  ✓ 识别  ● 写入 42%  ○ 校验  ○ 运行              （运行，ST-LINK）
✓ 编译  ✓ 识别  ● 备份出厂程序 63%  ○ 写入 …            （首次下载某颗芯片）
✓ 编译成功 · Flash 3.5 KB / 1 MB · 1.8 s               （4 s 后淡出）
✕ 2 个错误 · 1 个警告                                   （点击打开“问题”）
✕ 下载失败 · 未检测到下载器                              （点击打开诊断卡）
● 运行中 · 串口已连接                                    （4 s 后淡出）
```

- 点击正在进行的任务条，打开“编译输出”。
- 宽度不足（窗口 < 1100 px）时只显示当前步骤和百分比；< 760 px 时隐藏，设备 chip 仍显示状态色。
- `role="status"` 加 `aria-live="polite"`；结果变化时屏幕阅读器读出“编译成功”“2 个错误”等文字。

### 3.6 设备 chip

| 状态 | 状态点 | 文字 |
| --- | --- | --- |
| 未检测到 | 灰，虚线边框 | `选择开发板` 或 `探索者 F407 · 未连接` |
| 检测中 | 主色，脉冲 | `探索者 F407 · 检测中` |
| 已连接 | 绿 | `探索者 F407 · ST-LINK` / `探索者 F407 · COM5` |
| 写入中 | 琥珀 | `写入中 · 勿断电` |
| 出错 | 红 | `探索者 F407 · 未检测到下载器` |

“已连接”表示下载器（或串口）存在，并且最近一次识别到的芯片与工程一致。状态色与品牌提案的状态语义一致：连接中使用主色，琥珀只表示风险。

## 4. 设备弹层（C 工程）

设备弹层沿用 0.1.4 的常驻浮层（收起不卸载、表单状态保留），内容按工程类型切换：

```
┌ 开发板 ─────────────────────────────────────┐
│ 正点原子 探索者 F407                  [更换]│   ← 板卡包；更换只在同芯片内（P2）
│ STM32F407ZGT6 · 1 MB Flash · 192 KB RAM      │
├ 下载方式 ───────────────────────────────────┤
│ (●) ST-LINK（SWD）   ( ) 串口（ISP）         │
│ 下载器  [ST-LINK V2 · 0670FF…         ▾][↻]│   ← 串口方式时为“串口 [COM5 ▾]”
├ 芯片 ───────────────────────────────────────┤
│ ✓ STM32F407 · 设备 ID 0x413 · 1024 KB        │
│   唯一 ID 3A0021…  · 目标电压 3.15 V         │
│   [识别]  [复位开发板]                        │
├ 备份与恢复 ─────────────────────────────────┤
│ 出厂程序 · 2026-10-22 15:30 · 1 MB  [恢复…]  │
│ 显示全部备份（3）                            │
├─────────────────────────────────────────────┤
│ STM32 工具包 2026.11.0 · 已安装        [管理]│
└─────────────────────────────────────────────┘
```

- 简洁模式只显示“开发板”“下载方式”“芯片”三节；“备份与恢复”和工具包行在专业模式显示。烧写进行中或刚出现备份时，简洁模式也显示备份节（与 0.1.4 固件区的规则一致）。
- “芯片”节在每次运行时自动刷新，“识别”只用于手动检查接线。
- 芯片与工程不一致时，该节显示红色说明：`板上是 STM32F103（64 KB），工程目标是 STM32F407。请换板，或新建 F103 工程。`
- 多个下载器时，下拉框按序列号区分，并记住上次的选择。

## 5. 开始页与新建向导

### 5.1 开始页（U3）

没有打开项目时，主区显示开始页（效果图 01）：

```
           [n] nodu  见微
           从第一行代码，到第一次点亮。

   ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
   │ ＋ 新建项目    │ │ ▢ 打开项目    │ │ ✦ 示例        │
   └──────────────┘ └──────────────┘ └──────────────┘

   最近的项目
   blink-f407        STM32 · 探索者 F407     ~/Nodu/blink-f407     昨天
   green-tracker     K210 · MicroPython      ~/Nodu/green-tracker  10 月 20 日
```

- 主张文案来自品牌提案；最终文案以品牌会话为准。
- 最近项目显示项目类型，点击直接打开；路径过长时中间省略。
- 开始页是一个普通编辑器标签，可以关闭；关闭后通过 项目 ▾ → 新建项目 / 打开 进入同样的功能。

### 5.2 新建项目向导（P1）

单页对话框，三列从左到右选择（效果图 02）：

| 列 | 内容 |
| --- | --- |
| 项目类型 | `STM32 · C 语言（HAL）`、`K210 · MicroPython` |
| 开发板 | 卡片：板子照片或线框图、名称、芯片、标签（“推荐”“已验证”）；未核对完的板子不出现 |
| 模板 | `空工程`、`串口打印 Hello`、`LED 闪烁`；每项一句现象说明（“LED0 每 0.5 秒闪烁一次，串口同步打印”）；模板依赖的板级事实未核对时不显示 |

底部：项目名（默认为模板名加板子，例如 `blink-f407`）、位置（默认 `~/Nodu/`）、`创建` 按钮。名称只允许字母、数字、`-` 与 `_`，避免 CMake 目标名和路径问题；位置可以包含中文。

点击创建：

1. 工具包已安装 → 生成工程 → 打开工程 → 后台执行 CMake 配置 → 打开 `Core/Src/main.c`。
2. 工具包未安装 → 先进入工具包安装（§5.3），安装完成后继续第 1 步；取消安装时仍生成工程，可以编辑，但不能编译。

K210 项目沿用现有的新建流程，向导只是统一入口。

对话框（效果图 03）：

- 安装中显示总进度、当前组件、速度与剩余时间；“取消”保留已下载部分，下次继续。

## 6. 编辑器

- 标签：工程文件正常显示；SDK 文件显示锁形图标与“只读 · HAL F4 1.28.3”（E4）。
- 波浪线：clangd 实时诊断用细波浪线；编译诊断用粗波浪线，悬停时同时显示中文解释和原文。
- 悬停 HAL 函数：签名、官方注释的第一段（`@brief`）、所在头文件；不显示长篇注释，“打开定义”进入只读源码。
- 状态栏右侧：`探索者 F407 · STM32F407ZG`、`Flash 0.3 %`、`ST-LINK`、`行 12, 列 5`、`C`。点击 Flash 占用打开编译输出中的容量报告。
- 补全列表中的 HAL 函数显示参数提示；clangd 的“自动插入头文件”关闭（E5）。

## 7. 底部面板：问题 · 串口监视器 · 编译输出

C 工程的底部面板是一个带三个标签的区域，由工具栏的“问题与串口”开关控制（效果图 04）。

### 7.1 问题

```
问题  2 ✕  1 ⚠                                   [仅错误] [展开全部]
▾ Core/Src/main.c                                              2
  ✕ 12:5  HAL_GPIO_TogglePn 未声明                         编译
         使用前没有看到它的声明。检查拼写，或包含声明它的头文件。
         你是不是要用 HAL_GPIO_TogglePin？                      ← clangd 建议（有时才显示）
         原文：implicit declaration of function 'HAL_GPIO_TogglePn'
  ⚠ 18:9  变量 count 未使用                                 实时
▾ App/led.c                                                    1
  ✕ 7:1   缺少分号                                          编译
```

- 每项第一行：图标、行列、中文标题、来源（`编译` / `实时`）。第二行起：中文解释与修改方向；最后一行是编译器原文，等宽字体、降低对比度。
- 没有匹配到规则的诊断，第一行直接显示原文，不编造解释。
- 点击跳转到行；`F8` / `⇧F8` 在问题之间移动（Theia 现有行为）。
- 编译后修改过的文件，其编译诊断显示为“已过期”（降低不透明度，B10）。
- 简洁模式下，编译出错时自动打开“问题”一次（U6）；学生手动关闭后，本次会话不再自动打开，与 0.1.4 串行终端和帧缓冲的自动展开规则相同。
- 专业模式使用 Theia 自带的“问题”视图，中文解释作为诊断的相关信息显示；简洁模式使用 Nodu 的精简列表。两者读取同一个 marker 数据。

### 7.2 串口监视器

```
串口监视器   [COM5 · 115200 ▾]  ● 已连接     [时间] [HEX] [UTF-8 ▾] [⏸] [⧉] [⌫] [⤓]
── 运行 #12 · 15:30:12 · f862810 ──────────────────────────────────────
Hello from Nodu #0
Hello from Nodu #1
LED on
──────────────────────────────────────────────────────────────────────
>_ [发送内容…                                         ] [LF ▾] [发送]
```

- 连接参数（串口、波特率）集中在标题旁的一个下拉；修改写回 `nodu.json`。
- 运行分隔行（M2）使用主色细线和等宽小字；点击分隔行可以折叠这次运行的输出。
- 图标按钮依次为：时间戳、十六进制、编码、暂停滚动、复制、清空、保存为文件。简洁模式只保留暂停、复制、清空，其余在“⋯”中。
- 串口被占用时显示 `COM5 被 K210 设备连接占用`，并提供“断开 K210 设备”按钮（只有占用者是本窗口时才显示）。
- 断开时显示 `开发板已断开 · 等待重新连接`，输出保留（M6）。
- 串口 ISP 下载期间，监视器显示 `串口正用于下载 · 完成后自动恢复`，输入框禁用。
- 输入框沿用 0.1.4 串行终端的键盘规则：Enter 发送，Shift+Enter 换行，输入法组字时 Enter 不发送。

### 7.3 编译输出

原始日志：CMake 与 Ninja 的输出、下载步骤的工具原文。顶部一行是最近一次任务的摘要（成功或失败、用时、容量）。专业模式下也作为 Theia 输出频道 `Nodu · 编译` 存在。日志不过滤，但 ANSI 颜色被去掉。

### 7.4 容量报告

编译成功后，编译输出顶部显示：

```
✓ 编译成功 · 1.8 s
Flash  ▕█░░░░░░░░░░░░░░░░░░▏  3.5 KB / 1 MB   0.3 %
RAM    ▕█░░░░░░░░░░░░░░░░░░▏  1.9 KB / 128 KB 1.5 %
```

条形用主色，超过 90 % 时用警告色并在任务条提示。数值同时用文字给出，不只依赖条形长度。

## 8. 下载流程

### 8.1 ST-LINK：一键运行

学生只点“运行”。正常情况下不出现任何对话框，进度在任务条中显示（§3.5），设备 chip 在写入阶段变为琥珀色 `写入中 · 勿断电`。完成后：

1. 任务条显示 `● 运行中 · 串口已连接`。
2. 底部面板切到串口监视器，插入运行分隔行。
3. 设备 chip 回到绿色。

### 8.2 首次写入某颗芯片

识别到一颗没有备份记录的芯片时，任务条在“写入”前插入“备份出厂程序”步骤，并在任务条下方弹出一次说明气泡：

```
这是 Nodu 第一次写入这块板子，先备份板上原有的程序（约 10 秒）。
以后可以在 设备 → 备份与恢复 中恢复。                   [跳过备份…] [知道了]
```

“跳过备份…”需要二次确认：`跳过后，板上原有的程序将无法恢复。` 按钮为 `取消` / `跳过并写入`。

### 8.3 串口 ISP：引导卡

下载方式为串口时，“运行”在编译完成后打开引导卡（效果图 05）。引导卡是停靠在编辑器右下方的非模态卡片，不遮挡工具栏和串口监视器：

```
┌ 让开发板进入下载模式 ─────────────── 1 / 2 ─┐
│  [板子线框图：BOOT0 跳线高亮，箭头指向 3.3V]  │
│                                              │
│  1  把 BOOT0 跳线接到 3.3V（BOOT1 保持接 GND）│
│  2  按一下 RESET 键                          │
│                                              │
│  ◌ 等待开发板应答…  已等待 8 秒               │
│                                       [取消] │
└──────────────────────────────────────────────┘
```

- 检测到 ROM 应答后，卡片自动进入“写入”步骤，显示进度；学生不需要点“下一步”。
- 写入并校验完成后切到第 2 页：`把 BOOT0 跳线接回 GND，再按一下 RESET 键`。Nodu 打开串口监视器等待输出；检测到第一行输出后卡片自动关闭。30 s 没有输出时，卡片显示“没有看到输出？”并列出检查项（BOOT0 是否已接回、波特率是否正确），不判定为失败：程序本身可能不打印。
- 板子线框图来自板卡包（`boot.image`）。没有线框图的板卡包只显示文字步骤。
- 60 s 没有检测到应答时，卡片显示诊断（§8.5），保留“重试”。
- 有一键下载电路并已实测的板卡包（F12）不显示第 1 页，任务条中直接显示进度。

### 8.4 写入中途取消或断开

| 情况 | 界面 |
| --- | --- |
| 写入中点击停止 | 停止按钮提示 `写入完成当前扇区后停止`；停止后任务条 `✕ 已停止 · 板上程序不完整，需要重新下载` |
| 写入中拔掉 USB | 设备 chip 变红；任务条 `✕ 写入中断 · 板上程序不完整`；重新插上后，运行按钮可直接重试 |
| 校验不一致 | 任务条 `✕ 写入校验失败`，诊断卡给出“重新下载；若反复失败，降低下载速度或检查供电” |

### 8.5 诊断卡

下载失败时，点击任务条打开诊断卡。诊断卡按检测顺序列出每一项的结果，第一项失败处展开说明（效果图 06）：

```
┌ 下载失败：未检测到下载器 ────────────────────────────┐
│ ✕ 电脑检测到 ST-LINK                                 │
│     USB 中没有找到 ST-LINK。                          │
│     · 换一根能传数据的 USB 线（有些线只能充电）       │
│     · 直接插电脑，不经过 USB 集线器                    │
│     · Windows：安装 ST-LINK 驱动 →                    │
│ ○ 开发板供电（目标电压）                              │
│ ○ 芯片应答（SWDIO / SWCLK / GND 接线）               │
│ ○ 芯片型号与工程一致                                 │
│                                                      │
│ [改用串口下载]  [查看日志]                 [重试]    │
└──────────────────────────────────────────────────────┘
```

| 检查项 | 失败时的标题 | 说明要点 |
| --- | --- | --- |
| 下载器 | 未检测到下载器 | 数据线、USB 口、集线器、Windows 驱动 |
| 目标电压 | 开发板没有供电 | 开发板需要单独供电，或下载器的 3.3V 已接到开发板 |
| 芯片应答 | 芯片没有应答 | SWDIO、SWCLK、GND 接线；程序可能关闭了调试引脚，可按住 RESET 再点重试，或改用串口下载 |
| 芯片型号 | 开发板与工程不一致 | 显示板上芯片与工程目标 |
| 读保护 | 芯片开启了读保护 | Nodu 不解除读保护；解除会擦除整片 Flash，需使用 ST 官方工具 |
| 兼容芯片 | 可能是兼容芯片 | 显示读到的 ID；“仍要写入”需确认 |
| ROM 应答（串口） | 开发板没有进入下载模式 | BOOT0 是否接 3.3V、按复位、TX / RX 是否交叉、串口是否选对、是否接了 GND |

“Windows：安装 ST-LINK 驱动 →” 打开 ST 官方驱动页面（外部链接，在系统浏览器中打开）。

### 8.6 第一次点亮（U9）

学生的第一个工程第一次运行成功、串口出现第一行输出时，在任务条位置显示一次品牌时刻：

```
●  第一次点亮 · 你的程序正在板上运行。     下一步：把闪烁间隔改成 200 ms →
```

圆点使用“点亮黄”（品牌提案 04 的“学习里程碑”）。点击“下一步”跳到 `main.c` 中的 `HAL_Delay(500)` 一行。只出现一次，状态存在本机用户数据中；之后运行成功只显示普通的绿色状态。

## 9. 简洁与专业模式

| 区域 | 简洁 | 专业 |
| --- | --- | --- |
| 启动时的面板 | 只有编辑器 | 资源管理器、底部面板（问题） |
| 左侧栏 | 资源管理器（开关控制） | 资源管理器 / 大纲 / 搜索 |
| 问题 | Nodu 精简列表，含中文解释 | Theia“问题”视图，中文解释作为相关信息 |
| 编译输出 | 底部标签 | 底部标签 + 输出频道 `Nodu · 编译` |
| 串口监视器 | 暂停、复制、清空；其余在 ⋯ | 全部图标按钮 |
| 设备弹层 | 开发板、下载方式、芯片 | 另有备份与恢复、工具包 |
| 状态栏 | 开发板、Flash 占用 | 另有下载方式、编码、缩进 |
| 首次自动打开 | 出错时“问题”、运行后“串口监视器”，各一次 | 不自动打开（已常驻） |

切换模式时保留编辑缓冲区、光标、串口连接和正在进行的任务，与 0.1.4 一致。

## 11. 文案

### 11.1 用词表

| 用 | 不用 | 说明 |
| --- | --- | --- |
| 编译 | 构建、Build | 学生课本里的说法 |
| 运行 | 下载并运行、Flash | “运行”包含编译和下载；单独说下载时用“下载” |
| 下载 | 烧录、烧写、Program | STM32 课程常用“下载”；K210 固件更新仍叫“固件烧写”，二者不混用 |
| 下载器 | 调试器、探针、Probe | ST-LINK 的通用叫法 |
| 串口监视器 | 串口助手、终端 | 与 K210 的“串行终端”区分：串行终端带 REPL |
| 开发板 | 板子、目标板 | 界面统一用“开发板” |
| 芯片 | MCU、目标 | 说明文字中可以写 STM32F407 这类型号 |
| 备份 / 恢复 | 读出 / 回写 | |
| 工具包 | SDK、环境、插件 | SDK 只在专业模式的版本信息中出现 |
| 问题 | 错误列表、Problems | 包括错误和警告 |

### 11.2 规则

- 标题说结果，正文说怎么办：`开发板没有供电` + `开发板需要单独供电，或者把下载器的 3.3V 接到开发板。`
- 说明以动词开头，一条说明只讲一件事。
- 不写“请”“您”“成功地”“出错了！”这类词；不用感叹号。
- 编译器原文保留英文，放在中文说明之后。
- 数值带单位：`3.5 KB`、`1.8 s`、`3.15 V`。容量用 KB / MB（二进制），与芯片手册习惯一致。
- 不在界面中写过程说明（0.1.x 原则）；需要的说明放在引导卡、诊断卡和悬停提示中。

## 13. 可访问性

| 项目 | 做法 |
| --- | --- |
| 键盘 | 工具栏、任务条、设备弹层、引导卡、诊断卡均可用 Tab 到达；引导卡出现时焦点不被抢走，用 ⌘. 取消 |
| 读屏 | 任务条与监视器状态 `aria-live="polite"`；错误数变化时读出“2 个错误”；问题列表每项的可访问名称包含文件、行号、标题和解释 |
| 不只用颜色 | 状态点旁总有文字；问题图标区分 ✕ 与 ⚠ 形状；容量条附数值 |
| 对比度 | 文本 ≥ 4.5:1，图标与边框 ≥ 3:1；编译器原文的降低对比度也不低于 4.5:1。品牌提案中的 `palette.cjs` 已提供对比度计算，最终令牌合入后重新计算 |
| 动效 | 脉冲与旋转遵守 `prefers-reduced-motion`，减少动效时改为静态图标 |
| 引导卡图示 | 线框图带文字替代说明，步骤同时以文字列出 |

以上需要用 VoiceOver 与 NVDA 实测，源码层面的设计不能证明满足 WCAG。

## 15. 与品牌会话的分工

| 品牌会话负责 | 本设计负责 |
| --- | --- |
| 设计令牌（颜色、字体、圆角、间距）与其在 Theia 主题中的映射 | 使用语义令牌的新组件：开始页、向导、工具包对话框、任务条、问题列表、串口监视器、引导卡、诊断卡、设备弹层的 C 部分 |
| 品牌标志、应用图标、关于对话框、品牌时刻的视觉 | 品牌时刻的触发条件与文案（§8.6） |
| 工具栏外观（按钮样式、状态点、chip） | 工具栏的按钮配置（`NoduToolbarModel` 按项目类型返回按钮列表） |
| 图标规范与新图标的最终绘制 | 需要哪些图标及其含义 |

合入顺序：品牌会话先合入令牌与主题；C 工作台的组件只引用令牌，不写色值。若品牌会话修改 `scope-workbench.tsx` 的工具栏结构，C 工作台的唯一改动（工具栏按钮列表来自数据源）在其之后变基，冲突面仅限按钮列表的渲染函数。
