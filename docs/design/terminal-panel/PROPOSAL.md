# 底部工作台 UI 重构方案

状态：**设计提案，待评审；未修改应用实现。**

日期：2026-10-22。分支：`codex/terminal-panel-ui`。基线：`749a2a9`。

范围：用户已确认统一底部面板，覆盖运行输出、串口监视、REPL 和系统终端。

## 1. 建议方向

**把底部区域做成一个可持续阅读的工作台：四个清楚的入口、稳定的上下文、尽可能大的文本区域。**

主结构采用 VS Code 的底部标签与渐进会话管理；串口交互参考 Arduino；设备连接、运行和 Python 排错遵循 MaixPy 的使用场景；从 ZCode / Codex 借鉴项目上下文清晰、面板显隐与任务生命周期分离的交互。颜色、字体、图标仍使用 Nodu 现有设计系统。

推荐标签顺序：**运行输出 · 串口监视 · REPL · 终端**。四个标签属于同一底部容器；连接、执行、收发、Shell 的行为各自明确。切标签只是切视图，不连接端口、不停止脚本、不重新执行命令。

`zcode` 暂按 **智谱 / Z.ai ZCode** 理解，`maxipy ide` 按 **MaixPy IDE** 理解；ZCode 不等于 Zed。若用户指另一款 Zcode，只需调整参考分析，核心方案仍可评审。

## 2. 现状与需要解决的问题

已检查当前 Electron 窗口及源码；截图中的窗口为浅色主题，右侧帧缓冲打开，底部串行终端未连接。

| 当前表现 | 对使用的影响 | 本方案处理 |
| --- | --- | --- |
| 底部默认仅 160 px；内部又有标题、padding、带边框输出框和输入栏 | 真正能读的日志太少，像一个放大的表单 | 输出铺满面板；仅保留顶部分隔线，默认高度提升到约 28% |
| 简洁模式隐藏底部 Theia 标签栏 | 同时打开设备日志和多个终端时，缺少清楚的切换入口 | 两种布局共用同一套底部导航 |
| 简洁模式“串行终端”有 REPL，专业模式同一入口只有 OutputChannel | 切布局会改变功能与操作位置 | 功能、草稿、连接、滚动位置跨布局保持一致 |
| REPL 初始文本是 `print(42)`；未连接时输入灰掉 | 用户不知道为何不能输入，也容易把示例误认成已输入命令 | 空草稿、真实 placeholder、就地说明禁用原因 |
| 命令回显是 system 日志，但控制台过滤 system | 看得到结果，找不到刚刚输入的命令 | REPL 显示命令与结果的完整往返 |
| “串行终端”“串口终端”“输出”混用 | 不清楚内容属于开发板还是本机 Shell | 四个标签、每页上下文条、明确目标与操作名称 |
| 已有滚动跟随，但没有新输出数量与缓冲截断提示 | 阅读旧日志时不知道新增多少，也不知道历史已经不完整 | 新输出提示、恢复跟随、明确缓冲保留范围 |

当前设备日志是 `text / stream / time`，不是原始字节，也没有可靠的运行/命令归属。现有原始串口终端是另一条 xterm + Rust 进程路径，且有端口占用检查。设计不能把“新标签”当成“已经支持的新数据通道”。

## 4. 信息架构与布局

```text
编辑器 / 当前工作区
──────────────────── 可拖动分隔线 ────────────────────────────
 运行输出   串口监视   REPL   终端                 ⋯   最大化   收起
────────── 活动标签下划线 ─────────────────────────────────────
 当前来源 ▾    目标 / 当前状态                查找   跟随   清空
──────────────────────────────────────────────────────────────
 连续日志 / 命令与结果 / 原始收发 / Shell
 文本选区稳定；历史阅读不跳动；最后一行完整可见
                                       ↓ 新输出 24   （按需）
──────────────────────────────────────────────────────────────
 仅串口 / REPL 有发送栏；运行输出没有；Shell 使用自身光标输入
```

两层工具栏的职责固定：

- **第一行是面板导航**：四个标签，右侧为更多、最大化、收起。标签用文本和 2 px 活动下划线，不用四颗大胶囊按钮。不再重复一个“串行终端”大标题。
- **第二行是当前内容的上下文**：左侧显示来源、目标和状态；右侧显示查找、跟随、清空。低频动作放更多菜单。终端页用自己的会话工具替换阅读工具。
- **正文是主要区域**：无内嵌卡片边框、无每行背景、无聊天气泡。时间和方向只是可选的窄列，正文左对齐。
- **输入栏只在需要时出现**：REPL 明确显示 `>>>` 和“执行”；串口明确显示“发送内容”、行尾、“发送”；Shell 的 `$` / `PS>` 来自真正的 Shell。

面板沿用当前 Theia 底部停靠区域，初版不移动侧边帧缓冲与文件树。最大化只扩大底部区域，恢复后回到用户上次高度。关闭按钮语义是“收起面板”，销毁会话另有明确动作。

### 尺寸与窄宽处理

| 项目 | 建议规范 |
| --- | --- |
| 默认高度 | 工作区可用高度的约 28%，限制在 220–320 px；按工作区记忆 |
| 最小可拖动高度 | 180 px；再缩小使用收起，避免出现只剩工具栏的面板 |
| 标签栏 / 上下文栏 | 32 px / 28 px；正文与输入之间仅 1 px 分隔线 |
| 单行输入栏 | 36 px；多行可展开到 4 行，继续输入时内部滚动 |
| 正文 | 13 px 等宽字体，20 px 行高；正文左右 padding 12 px |
| 图标 | 16 px；命中区至少 28×28 px；标签和下拉命中高度至少 28 px |
| 面板宽度 ≥ 900 px | 完整设备短名、端口尾部、状态；三个阅读工具直出 |
| 600–899 px | 缩短来源名；完整端口放 tooltip；清空移入更多 |
| < 600 px | 隐藏次要路径；四标签仍可到达，极窄时“终端”入溢出菜单；不横向裁掉输入栏 |
| < 480 px | 上下文条只保留目标选择与状态，阅读工具进入更多；多会话侧栏收起成下拉 |

以面板实际容器宽度判断，不以整窗宽度判断。验收至少覆盖 1440×900、980×720，以及两侧面板同时打开后约 460 px 的底部可用宽度。

## 5. 四个页面

### 5.1 运行输出：先看程序发生了什么

```text
 运行输出   串口监视   REPL   终端                          ⋯  □  ⌄
 main.py ▾   K210 · 已连接   运行中                  查找  ↓  清空
 ── 本窗口运行 · 16:42:08 · main.py ─────────────────────────────
 Camera initialized
 fps: 24.7   objects: 1
 fps: 24.9   objects: 1
 Traceback (most recent call last):
   File "main.py", line 28  ← 可定位链接
 ValueError: invalid threshold
```

- 收纳 IDE 发起的运行输出和操作日志。来源选择器只显示真实存在的来源；未来编译、下载接入后再加入，不提前显示假的成功任务。
- 当前运行摘要是薄分隔行，包含文件、开始时间和真实状态；不把每次运行变成大卡片。仅有前端依据时写“本窗口运行”，不伪造全局运行编号或可靠归属。
- K210 `print()` 与 Python 错误出现在这里；构建/下载日志在对应来源下。REPL 命令产生的响应在可靠归属建立后进入 REPL，不混进当前脚本结果。
- 正常文本使用正文色；stderr 是错误/诊断流样式，不等价于“全是 Python 异常”。错误关键行红色，路径和行号带可点击样式，颜色之外有文本依据。
- 原始文本完整保留。展开诊断解释只能是额外信息，不能替换工具原文。
- 仅在路径、行号及源版本可核实时跳转；否则保留可复制原文。沿用现有 Traceback 版本检查。
- 无输入栏。停止程序继续使用顶层“停止”，面板收起与清空均不停止程序。

### 5.2 串口监视：明确目标，再收发字节

```text
 运行输出   串口监视   REPL   终端                          ⋯  □  ⌄
 USB Serial · COM5 ▾    115200 · 已连接               查找  ↓  清空
 16:42:10.182  RX   temperature=24.6 humidity=51.2
 16:42:10.506  TX   status
 16:42:10.518  RX   ok
 ──────────────────────────────────────────────────────────────
 发送内容…                                        LF ▾   发送
```

- 目标选择弹层集中端口、波特率及高级参数；默认界面仅露出当前端口、波特率、连接状态。
- 接收/发送使用 `RX` / `TX` 窄列与文字区分。时间戳可关闭；每块数据只能展示实际接收时间，不声称设备逐行精确时间。
- 行尾选项是无、LF、CR、CRLF，紧贴发送按钮；文本/HEX、编码、时间戳放更多菜单，均按会话保存。
- Enter 发送，Shift+Enter 换行；中文输入法组字时 Enter 不发送。发送中防止重复，失败保留草稿。
- 参数更改需要重连时，弹层按钮写“应用并重连”；不悄悄复位板卡。DTR、RTS 等行为按真实适配能力显示。
- 原始收发与 IDE 协议不能同时占用同一端口。占用时正文顶部显示“COM5 正由 K210 IDE 连接使用”，操作为“转到运行输出”和“切换为串口监视…”。后者明确告知“断开当前 IDE 设备连接并释放 COM5”；当前后端共享连接，因此使用该连接的其他窗口也会断开，不能承诺影响仅限本窗口。由用户主动执行；固件烧写期间此操作不可用。外部进程占用只提供检查/重试。
- 未实现原始字节捕获前不显示 HEX 开关；不能把已经解码的字符串转成十六进制冒充原始数据。

### 5.3 REPL：命令与结果成对阅读

```text
 运行输出   串口监视   REPL   终端                          ⋯  □  ⌄
 K210 · MaixPy ▾    已连接 · 可执行                   查找  ↓  清空
 >>> import os
 >>> os.listdir('/')
 ['boot.py', 'main.py']
 >>> print(6 * 7)
 42
 ──────────────────────────────────────────────────────────────
 >>> 输入 Python 代码…                               执行 ↵
```

- REPL 是受 IDE 管理的 Python 命令执行视图。输入 `>>>` 提示符只是视觉标识，不伪装成本机 Shell 或原始串口控制字符终端。
- 命令与响应按提交顺序连续排列；多行命令用 `...` 延续提示，不为每条命令创建卡片。
- Enter 执行、Shift+Enter 换行；多行编辑时 `⌘/Ctrl+Enter` 执行本段。该快捷键只在 REPL 编辑器获得焦点时生效，不能同时触发运行整个脚本。
- 单行输入上下键查历史；多行仅在光标处于首/末行边界时进入历史。执行后清空已提交草稿并保留历史；执行失败保留草稿。
- 运行中仍可编辑草稿，执行禁用，旁边写“程序运行中，停止后可执行”；“停止程序”是独立显式动作，点击 REPL 标签不停止程序。
- 未连接时写“连接开发板后执行 Python”，提供“选择开发板”；不支持 REPL 的设备显示实际能力说明，不提供假的可点击输入。
- 本机历史仅限当前工作区和设备会话，清空显示不自动清除历史；菜单分别提供“清空显示”和“清除输入历史”。

### 5.4 终端：真正的本机 Shell

```text
 运行输出   串口监视   REPL   终端                          ⋯  □  ⌄
 zsh · green-tracker ▾   本机                     + ▾  分屏  结束
 ~/Projects/green-tracker
 $ git status --short
  M main.py
 $
```

- 复用 Theia/xterm 的真实 PTY，不另外实现一个 textarea Shell。
- 默认会话在当前工作区目录启动。单会话只显示短名称；多会话在足够宽时显示约 150 px 侧栏，窄时用下拉切换。
- 保留新建、配置选择、分屏、重命名、结束与终端搜索。结束会话使用垃圾桶/“结束”入口，收起面板使用向下折叠图标。
- 不向 Shell 注入项目运行快捷键。Ctrl+C、Ctrl+R、Ctrl+E 应遵守当前终端类型；原始串口/网络终端的控制字节规则单独注册。
- TCP/UDP 原始终端保留在高级会话配置内，名称带“TCP 客户端”等类型；不要标成本机 zsh。

## 6. 状态、阅读与反馈

| 场景 | 界面表现 | 行为 |
| --- | --- | --- |
| 首次无数据 | 一行说明 + 当前页唯一下一步，如“选择端口开始监视” | 不显示预填 `print(42)` 或装饰插图 |
| 已连接、未运行 | 连接文字“已连接”；运行状态“空闲” | 连接绿点不代表程序正在运行 |
| 正在运行 | 来源旁“运行中”，非活动标签小状态点 | 隐藏面板后继续运行 |
| 查阅历史 | 滚动位置/文本选区保持，右下出现“↓ 新输出 24” | 点击回到底部并恢复跟随 |
| 暂停显示 | 工具态写“显示已暂停 · 接收继续”，有恢复入口 | 不发送停止或断开命令；缓冲上限仍有效 |
| 拔线 / 断连 | 保留已有文本，顶部紧凑状态条“设备已断开” | 串口发送和 REPL 执行禁用；草稿保留；不假称会自动重连 |
| 端口占用 | 显示端口和已知占用来源，提供去对应页/切换入口 | 不自动杀进程、不静默抢端口 |
| 错误到达 | 当前页错误行可见；其他页用错误徽标提示 | 不因每个 stderr 抢焦点；用户主动发起运行的首次失败可展开输出并保留编辑器焦点 |
| 用户本次已收起 | 顶层面板按钮提示错误/运行状态 | 同次运行不反复弹开 |
| 缓冲截断 | 正文最上方“更早的输出已移出缓冲” | 不编造丢失行数；导出注明仅当前保留内容 |
| 清空显示 | 清空当前页/来源的可见缓冲 | 不影响其他页，不停止采集、不删文件、不清除 REPL 历史 |

“跟随”和“暂停显示”是两个动作。默认直出跟随；暂停显示放更多菜单以避免初学者误以为暂停了设备。新输出计数只能使用真实增量；未按完整行组装前以“条”计，不把事件数写成行数。

查找使用页内查找条：关键字、匹配数、前后跳转、关闭。默认在当前保留内容中查找，隐藏旧结果时不声称搜索了完整历史。日志过滤改变可见内容，复制菜单区分“复制选中内容 / 复制可见内容 / 导出当前缓冲”。

## 7. 视觉与键盘规范

- 延续 Nodu 浅色白底与冷灰工具栏、深色芯片墨工作台；复用 `brand/src/tokens.cjs` 与 Theia 语义令牌。本文和线框图中的色值为现有令牌解析值，应用代码不新建硬编码调色板。
- UI 使用现有 Scope Plex / 中文系统字体；输出、路径和命令使用 Scope Plex Mono，正文 13/20。浅色正文与深色正文均保持可读对比度。
- 蓝色只用于选中、焦点、主要执行/发送动作与进行中状态。连接成功、错误、警告同时有文字；正常日志不铺满绿色。
- 分隔线 1 px、控件圆角 3–4 px、无大阴影。去掉终端正文周围的内层框与卡片留白。图标使用现有 Codicon。
- 底部显隐沿用 Theia `core.toggle.bottom.panel`（⌘/Ctrl+J）；全局“终端”命令按当前平台键位解析后在菜单显示，不新增冲突的硬编码组合。
- 当焦点位于输出/串口/REPL 日志区时，⌘/Ctrl+F 查当前页，Esc 关闭查找并返回原焦点。Shell 的查找与快捷键复用 TerminalService。
- 标签按 tablist 语义实现：左右方向键移动、Home/End 首尾、Enter 激活；切标签不自动把焦点送进会执行命令的输入框。
- 拖动分隔线之外，提供键盘可操作的“增大 / 缩小 / 最大化 / 恢复”；焦点轮廓 2 px；图标有 tooltip、可访问名称与开关状态。
- 高频串口内容不逐条进入 aria-live；连接/失败等低频状态可播报，原始输出仍可键盘浏览和选择。

## 8. 与已有 0.2.1 设计的衔接

现有 [0.2.1 UI-DESIGN §7](../../0.2.1/UI-DESIGN.md#7-底部面板问题--串口监视器--编译输出) 为 C 工程规定“问题 / 串口监视器 / 编译输出”。本提案是跨项目类型的统一底部工作台，待本方案确认后合并以下变化：

- “编译输出”成为“运行输出”的来源之一，避免 K210 / STM32 再造两套底部结构。
- 诊断“问题”保留 Theia 视图，出现真实诊断后通过问题计数打开；不在首版四标签中增加一个永久空页。
- C 项目不支持 REPL 时隐藏 REPL 标签；当前四入口目标不等于每种板卡都宣称支持 Python。
- 接入 STM32 原始串口监视能力后复用串口页；现阶段仅将它作为界面与交互契约，不宣称 STM32 功能已经落地。
- 本方案建议连接参数默认记在本机工作区会话；与现有设计中“写入 nodu.json”的做法存在差异。可移植的协议参数与本机端口路径应分开保存，实施前一并修订。
- 这次不直接覆盖旧文档，避免将待评审提案写成已通过的新规范。

## 9. 实施分层与能力边界

本节是后续实现边界，当前分支只交付设计文档与结构图。

| 阶段 | 范围 | 需要先证实的事实 |
| --- | --- | --- |
| A：统一容器与阅读 | 四页布局、简洁/专业一致、工具条、尺寸、搜索/跟随、禁用说明、Shell 复用 | Theia dock 与现有命令兼容；无额外端口连接 |
| B：设备日志与 REPL | 真实命令回显、历史草稿、命令/运行来源、状态分隔 | 事件拥有稳定 ID、来源与命令/运行标识；不能靠字符串匹配推断可靠归属 |
| C：串口监视器 | 参数、RX/TX、行尾、文本/HEX、占用与重连 | 原始字节通道与共享串口占用服务；IDE 与 raw 模式切换契约 |
| D：完善会话体验 | 诊断跳转、当前缓冲导出、多会话与窄宽处理 | 明确历史保留范围；不把“导出缓冲”称作完整日志归档 |

已有 `<pre>` 日志上直接加 HEX 和波特率按钮不算完成 C。将 `system` 字符串当作完整运行来源也不算完成 B。跨刷新历史、全量录制、多设备并发和 AI 自动分析暂不纳入第一轮 UI 实现。

关键集成位置：

- `desktop/scope-extension/src/browser/nodu-console-widget.tsx`：设备日志与 REPL 当前视图。
- `desktop/scope-extension/src/browser/scope-workbench.tsx`：底部显隐、双布局和 Traceback 导航。
- `desktop/scope-extension/style/layout.css`：底部隐藏标签规则和现有双层输出框。
- `desktop/scope-extension/src/browser/nodu-terminal-tools.tsx`：原始终端、占用检查与快捷键上下文。
- `desktop/scope-extension/src/browser/nodu-device-client.ts`：日志缓存、运行/执行/连接状态。
- `desktop/native/crates/nodu-protocol/src/lib.rs`：日志事件契约。

## 10. 设计验收标准

1. 新用户能从标签和上下文判断：当前看的是程序、端口、Python 交互还是本机 Shell。
2. 简洁/专业切换后仍有相同的四种能力；会话、草稿、滚动与选区不因换布局丢失。
3. 280 px 高面板中，运行输出正文至少约 200 px（10 行）；带输入栏的页至少约 160 px（8 行）。窄屏仍能发送/执行并找到更多操作。
4. 收起/展开/最大化/切标签都不调用连接、断开、执行、停止、销毁会话。
5. 中文输入法、多行草稿、粘贴长文本、重复发送、REPL 失败等有明确行为。
6. 高频输出下，选中文本可复制，上滚不被抢回底部，最后一行不被输入栏或横向滚动条遮住。
7. 断连、运行中、设备忙、不支持、端口占用分别给出准确文案；不存在不可解释的灰输入框。
8. 当前缓冲的搜索/复制/导出范围准确；已丢弃历史可见提示，不能声称日志完整。
9. 原始收发、REPL、系统 Shell 的控制字符与全局运行快捷键不串台。
10. 浅色/深色、1440×900/980×720、约 460 px 面板宽度，以及键盘导航均按同一结构验证。
