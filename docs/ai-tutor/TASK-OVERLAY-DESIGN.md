# AI 教学任务与步骤悬浮窗设计

日期：2026-10-24。状态：路线设计，首版任务窗已实现。具体已实现范围与验证结果见 [实现记录](TASK-OVERLAY-IMPLEMENTATION-2026-10-24.md)；本文件中的依赖图、任意重排、构建/真机任务类型仍是后续设计，不代表全部实现。

## 目标与现状

用户输入想完成的功能，AI 生成一个教学任务（Task）和若干步骤（Step），引导用户亲自写代码。完成一个有意义的片段后自动检查，满足本步骤条件才标记完成；教学过程中可以添加、调整和删除步骤。

当前 `common/tutor/tutor-goal.ts` 已有 draft/active/paused/cancelled/complete、计划确认、片段和检查协议；步骤只有 id/title/goal/path，id 被限定为 step-N，current 是数组索引。`nodu-tutor-widget.tsx` 在右侧展示目标和检查动作。已有范字、行检查、本地 AST、受控纯函数执行和构建/运行证据可复用。缺少独立步骤状态、动态计划变更协议和步骤悬浮窗，不应只在 UI 添加一个列表来绕过状态模型。

## 界面分工

- 编辑器：固定在 AI 指定代码位置的范字；保持灰色完整范字、上下分隔线、首行 AI 图标。失焦不消失，位置不跟随光标。品牌黄用于代码高亮及当前步骤小标记。
- 步骤悬浮窗：任务标题、完成数量、当前步骤与相邻步骤、检查/暂停。只表达现在做哪一步和进度，不放代码、长说明或聊天记录。
- 右侧对话：提出目标、计划确认、解释与评价、缺少上下文时的提问、影响较大的计划调整。取消此前重复的常驻步骤卡，保留计划消息和可打开悬浮窗的任务引用。

一个工程同时一个活动教学任务。不同工程互不污染。悬浮窗是整个主编辑区共用的应用内覆盖层，可跨越多个文件编辑器和分屏边界；切换文件不重建、不改变位置。不是操作系统置顶窗口，不能飘到其他应用。

## 悬浮窗布局

默认靠编辑区右上，距边缘 12px，宽 300px，最大高度 min(360px, 编辑区高度的60%)。位置避开当前跟写区域及浮动批注；若冲突，使用固定的底部停靠位置，不在打字时追逐光标不断跳动。允许拖动标题栏；在本窗口记住位置，并在窗口缩小时限制在可见范围。

```text
┌─────────────────────────────────────┐
│ USART1 串口输出          2/5   −  ⋯ │
├─────────────────────────────────────┤
│ ✓  配置串口                         │
│ ✓  准备消息                         │
│ ▸  周期发送                         │
│ ○  编译验证                         │
│ ○  下载并观察输出                   │
├─────────────────────────────────────┤
│ 检查当前步骤                    暂停 │
└─────────────────────────────────────┘
```

这是展开态草图。默认紧凑态只显示当前步骤及前后相邻项，点击计数展开完整列表；已完成历史可折叠。单行高28–30px、标题约13px、正文12–13px，复用项目字体/图标/颜色。主动作只保留检查当前步骤；自动检查时显示短暂 spinner 和“检查中”，不用额外横幅。

收起态为 `USART1 串口输出  2/5  ▾`，仍可拖动/展开。不提供与暂停含义混淆的“×结束”：隐藏在更多菜单，结束教学是独立操作。暂停显示“继续”，待恢复目标保持原步骤。

编辑区可用宽度小于640px时自动收为底部紧凑条，展开后使用编辑区内停靠面板，不遮挡整列代码。开启/隐藏可通过既有右上 AI 控件菜单和命令面板完成，不新增顶级入口。Esc 只收起当前展开层，不能结束任务。

点击步骤行只选中并显示其操作，不自动判完成、不强制切换当前教学。点击文件定位按钮才打开对应位置；双击当前步骤可定位其锚点。离开输入区去看步骤不隐藏范字。

## 一个任务如何生成

1. 用户在教学模式提出功能。后端读取芯片、SDK、已有 API、工程文件和当前代码。
2. AI 返回初始3–8个有意义的步骤，明确各步骤依赖、目标文件及可验证完成条件。不要“一行一步”，每个步骤可含多个1–4行范字片段。
3. 右侧对话展示紧凑计划草案和“开始”“修改”。缺硬件/接线信息先提问，不预设传感器已连接；可先推进不依赖硬件的步骤。
4. 用户开始后出现悬浮窗，选取首个满足依赖的步骤并定位已授权文件的插入区域。
5. 步骤全部完成才显示任务完成。若编译/真机验收仍缺证据，任务保留相应未完成步骤，而非提前显示100%。

初始3–8步为生成建议，保留现有24个有效步骤上限。较长工作拆为片段或另一个任务，不能无限自动扩展教学范围。

## 自动检查和完成判定

字符比对、行审阅、片段完成、步骤完成分开。正确临摹一行不等于整个步骤完成；等价实现也不要求机械复制范字。

触发时机：Enter 完成有效行、完整语句/块闭合、保存、完成已要求的编译或测试。沿用现有行审阅队列；聚合相关事件，在代码稳定约700ms后调度片段/步骤检查，该数值是待实测参数。输入法组合、每个按键、无实质变化的缩进不请求模型。去重键包括任务/步骤版本和相关代码摘要；相同证据复用，多个行审阅结果可复用，不重复发送同一份源码。

流程：本地语法与规则 → 必要的 AI 语义审阅 → 按完成条件汇总 → 后端提交状态变更。AI 返回通过/需修改/缺上下文/不可用以及具体条件判定，不能直接写步骤完成状态。仅当所有必要条件有当前有效证据时由后端标记完成。

| 步骤类型 | 最低完成证据 |
| --- | --- |
| 编写功能 | 对应锚点/跨文件内容、必要声明和语义条件通过；只表示代码步骤完成 |
| 编译验证 | 当前已保存源码对应的成功构建；旧产物或未保存修改不能通过 |
| 纯函数验证 | 对应源码摘要的受控测试通过 |
| 下载验证 | 用户主动发起下载产生的正确芯片、目标与固件结果 |
| 运行/串口观察 | 本次固件运行后相关且新鲜的观测；端口选择不等于接线证明 |
| 必须人工观察 | 用户明确确认，证据标为人工确认；AI 不冒充测量 |

一个步骤涉及多个文件时，收齐相关文件摘要和必要证据，不能因当前一个文件检查通过而完成整个步骤。模型超时/断网保留输入和当前进度，展示“检查失败”及重试；不把不可用当通过。

完成反馈：行图标变为勾、计数更新；右侧对话给一次简短评价及下一片段说明，不额外弹成功 toast。下一步骤在同文件且安全时展示新范字；跨文件时先提示“继续：文件名”供点击，不在用户输入过程中突然切编辑器。所有条件已经满足时可直接检查下一步骤，但不能循环调用模型或自动写代码。

## 步骤状态

| 内部状态 | 默认展示 | 行为 |
| --- | --- | --- |
| todo | 空心圆 | 尚未开始 |
| active | 品牌黄小标记 | 当前跟写 |
| checking | spinner | 检查中，不锁住编辑器 |
| needs-change | 小错误标记 | 对话/批注说明问题，允许修改 |
| blocked | 等待标记 | 缺依赖/上下文/实际操作，展开才显示原因 |
| done | 勾 | 条件全部通过 |
| stale | 待复查标记 | 已完成相关代码被改，原证据不再适用 |
| skipped | 跳过标记 | 用户跳过，不计入完成数量 |
| removed | 默认不显示 | 软删除，历史可追溯 |

顶部为已验证完成数/有效步骤数，不用会随增删跳动的百分比。存在跳过项时任务不能标记全部达成；用户可以结束任务，历史区分“完成”和“结束”。编辑已完成步骤相关代码只让相关步骤及必要依赖失效，不清空全部进度。

## 动态添加、修改和删除

所有变更使用步骤稳定 ID，不用数组下标或标题识别。

- 用户可在更多菜单“编辑步骤”中添加、重命名、删除、调整顺序，也可直接对 AI 说“增加 CRC 校验”“删除显示屏部分”。非编辑态不摆满加减和拖动按钮。
- 用户添加的步骤先保留原文，缺完成条件时由 AI 补全并在对话确认；不能将一个模糊句子作为可自动完成的验收标准。
- AI 可自动插入任务原范围内必要的未开始补充步骤，例如补充函数声明、恢复前置初始化。一个相关变更批量处理，右侧显示短变更记录及撤销。暂定每轮最多新增2步；超过限制转为计划修订，不无限加任务。
- 扩大目标、引入新外设/接线、删除或改写已完成/当前步骤、影响多条依赖的变更，AI 只给对话内变更建议，用户点击“应用”后生效，不每项弹确认窗。
- 用户主动删除无依赖的未开始步骤立即软删除，右下角出现“已移除步骤”及“撤销”；不改源码。删除有依赖的步骤，在编辑步骤面板内展示影响并选择重接依赖/一并移除/取消，不悄悄把依赖步骤解锁。
- 删除当前步骤先取消其检查并撤下相应范字，再选择下一个可执行步骤，保留用户已输入代码。删除最后一个步骤不能自动判任务完成，返回修改计划或结束任务的选择。
- 移除已完成步骤保留历史证据，但不再计入当前计划；撤销时重新核对证据是否仍适用。删除/改完成条件期间返回的旧 AI 结果一律不能复活步骤。
- 重排不能产生依赖环或把未满足的前置条件绕过。与代码编辑同时发生的计划修订不会移动光标、覆盖文件或清空撤销栈。

## 数据和接口

建议在现有 goal 协议上演进，而不是另建与课程/目标互相独立的进度系统。

```ts
interface TeachingTask {
  schema: 2;
  id: string;
  revision: number;
  workspaceKey: string;
  target: { mcu: string; sdk: string };
  title: string;
  status: 'draft' | 'active' | 'paused' | 'complete' | 'ended';
  activeStepId?: string;
  steps: TeachingStep[];
}
interface TeachingStep {
  id: string;                 // stable UUID
  revision: number;
  title: string;
  kind: 'code' | 'build' | 'test' | 'download' | 'observe';
  dependsOn: string[];
  anchors: { path: string; anchorId: string }[];
  criteria: CompletionCriterion[];
  status: StepStatus;
  evidenceIds: string[];
  origin: 'ai' | 'user' | 'course';
}
```

接口：`task.patch(expectedRevision, operations)`、`step.check(stepId, stepRevision, snapshotId)`、`task.selectStep`、`task.pause/resume/end`。变更支持 add/update/remove/reorder，并有changeId/撤销记录。后端验证路径授权、步骤上限、依赖无环、完成条件和模型输出 schema，原子保存后发布任务事件。重复 requestId 幂等处理。

AI 得到只允许建议计划变更与审阅代码的工具契约；不因此获得编译下载、终端、任意文件写入权限。模型给出的磁盘路径与行号必须经授权和锚点解析。

证据绑定 taskId/stepId/stepRevision、代码与依赖摘要、工具版本及构建bundle/运行身份。过期结果拒绝应用。新任务、结束、切工程时递增epoch并取消旧任务检查。

## 实现分层

- 前端任务模型：与对话、编辑器和悬浮窗共享同一快照；只负责展示和提交动作，不自行打勾。
- 悬浮窗组件/布局控制器：拖动、收起、停靠、遮挡与键盘焦点。定位信息存本窗口，不写源码。
- 检查调度器：复用逐行队列，聚合片段事件和确定性证据；编辑期间相关结果过期；限制并发和去重。
- 后端 task store/reducer：稳定ID、独立状态、依赖、patch、撤销、revision冲突与持久化。课程通过适配器映射到相同步骤投影，避免与静态课程出现两个相互矛盾的完成状态。
- 模型网关：结构化计划、变更建议和审阅结果，复用既有取消/超时/凭据隔离。
- Rust：复用现有有界 AST、符号/结构规则与受控执行；补齐多文件锚点/摘要所需查询。任务状态和悬浮窗不放进 Rust，不为悬浮窗新增原生包或运行时。

旧状态迁移生成稳定步骤 ID，保存原记录备份；原 current 前的步骤保留历史完成事实，但缺少当前证据的导入项标待复查。不能根据数组位置制造新的验证证据。窗口位置单独存，任务重启恢复在工作区绑定记录中；同工程双窗口以revision检测冲突，失焦窗口只更新状态不抢焦点。

## 开发顺序与验收

1. 状态与迁移：稳定 ID、独立状态、依赖、patch、幂等、原子存储、撤销、双窗口冲突测试。
2. 悬浮窗：展开/紧凑/收起、拖动/停靠/键盘、现有右侧重复卡替换；先用状态夹具做深浅色、窄窗与所有状态截图。
3. 自动完成：行/片段聚合、标准化证据、等价实现、相关失效、失败重试、跨文件下一步不抢焦点。
4. 动态计划：用户编辑、AI补充、影响预览与撤销；删除正在检查步骤、依赖环、最后一步、任务完成后重新开启等边界。
5. 完整产品：F103串口任务的提出目标→确认→用户跟写→自动打勾→增加错误处理→删除可选步骤→编译证据→暂停/重启恢复。硬件步骤必须由用户主动操作产生真实证据，离线验收不能假装下载或接线通过。

必须覆盖：只写一行不能完成整步；仅参考范字存在不能完成；同义代码可通过；旧回包/旧构建/旧串口不能推进；断网不丢代码；增删不重置无关完成项；修改完成代码正确待复查；删除不修改源码；Esc收起不结束；点击聊天/悬浮窗后范字仍在原位；760×500与深浅色、屏幕阅读器和不抢焦点。

完成标准是实际桌面连续教学流程和状态恢复正确，不能只以列表可拖动或单测通过宣称完成。
