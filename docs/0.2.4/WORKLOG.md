# Nodu 0.2.4：工程兼容与打开流程

## 已复现的问题

- 未打开真正的固件根目录时，工作区落入 K210 入口；旧开发板选择器仍显示 STM32 开发中。
- 缺少文件菜单的打开项目、最近项目入口。
- Keil 通用生成布局覆盖不了实际工程的 62KB 应用区、2KB 配置保留、RAM 向量/Flash 操作函数及 4KB 栈。
- GCC/newlib 与 Arm C 库的头文件（memory.h）、C11 静态断言、枚举 ABI、UTF-8 和优化设置差异导致生成的工程不能直接编译或保持行为。
- ST-LINK 驱动路径旧默认错误；用户自定义启动/链接/下载设置必须继续保留。

## 实施和验收

- [x] 将 Keil 兼容处理固化进生成器：读取实际编译/链接配置，共用 C99 语法和标准头文件检查（保留断言含义，不改写源码）、ABI、UTF-8、HAL/CMSIS 与授权自包含。
- [x] 内存布局和启动语义等价转换；不支持的构建语义提前报出具体原因，不能静默丢失。
- [x] 自动同步覆盖源码/头文件、第三方目录和链接文件变化；升级保持用户已有设置。
- [x] 文件菜单增加打开项目与最近项目；选择上层目录时能找到真正的项目根目录。
- [x] 不确定芯片由用户明确选择并持久化；不再猜为 K210 或进入过期的开发中提示。
- [x] 0.2.4 版本一致性、定向回归与 TypeScript/Rust 验证。
- [x] Windows 实际 Arm Compiler 6 / 5 编译：基础工程和完整智慧教室；独立解压与源码内容校验。
- [ ] 构建最终干净快照的 0.2.4 发布产物并进行界面验收，记录实际通过项与限制。

1:1 指同一份业务源码、外设/宏/数据 ABI、内存和持久化语义保持一致；不同编译器的机器码不要求逐字节相同。任何无法准确映射的扩展必须明确阻止转换，不能声称已支持。
