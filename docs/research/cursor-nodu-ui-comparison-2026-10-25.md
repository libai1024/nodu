# Cursor IDE 与 Nodu：逐项 UI 对照

日期：2026-10-25。范围：界面、信息层级及可见交互，不重复通用 Agent 能力比较，不修改产品代码。

## 结论

**最新 Nodu 已接近 Cursor 的聊天界面结构，但还不是同等完整的 Agent 工作界面。**

- 已接近：右侧对话区、可展开的最右会话列表、单行顶部工具栏、全宽浅边框用户消息、无大卡片包裹的 AI 正文、底部固定输入框，以及“模式 / 模型 / 附件 / 圆形发送”的顺序。
- 主要差距：会话标题与标签组织、列表的辨识信息及行操作、执行过程信息、文件改动 Review 区，以及完整 Markdown 表达。
- 不能通过改 CSS 补齐：多会话标签、重命名/归档、真正的工具执行记录、审批、代码变更审查。这些需要数据或行为支持。
- 不应为相似而删除：Nodu 的开发板、编译、烧录、串口和教学功能。它们是产品定位，不是视觉缺陷。

### 标题和“新对话”的准确解释

Nodu 保存时取保留的最近 100 条消息中的首条 user 正文，去首尾空白、合并空白、截取 60 个字符；没有有效正文时为“新对话”。当前并不是模型生成短标题，也没有独立的用户重命名字段。

仅当记录原本不存在、消息为空、原始草稿为空、上下文为空时跳过保存。因此，仅有上下文、仅有空白字符草稿或被清空的既有记录均可能留下“新对话”。现场大量同名条目值得改善，但不能仅凭截图断言重复保存故障，也不能未经用户授权直接删除。

## 7. 差异分级：应如何理解，而不是立即实施

### A. 纯视觉或信息呈现问题

- 会话标题过长，短标题辨识弱。
- 同名“新对话”太多，列表扫描困难。
- 搜索框提示、标题/预览/日期的层级还可强化。
- 浅色表面的冷暖及分隔线密度与 Cursor 不同。
- 外层功能栏让聊天区域比 Cursor 多一层边界。

### B. 需要真实数据和行为的 UI

- 多会话标签及各标签关闭。
- 重命名、归档等列表行操作。
- 执行中、等待确认、完成、失败的任务状态及时间。
- 文件变更集合、Review 和接受/撤销流程。
- 上下文使用量指示。
- 更完整的 Markdown 排版和对应安全处理。

### C. 不应机械照搬

- Agent/Plan/Debug 不应只换文案就出现在教学模式菜单。
- 没有账号/套餐系统时，不应仿造 Cursor 侧栏账号区。
- 没有真实改动集合时，不应画一个无实际用途的 Review 按钮。
- 编译、下载器、串口和教学状态应保留 Nodu 的领域语义。

**就当前 UI 成熟度，最值得优先改善的是“辨认并管理一个会话”，而不是继续重画已经接近的输入框。** 如果以后目标升级为真正 Agent，则需要独立设计过程状态和变更审查，不能藏在普通聊天段落里。
