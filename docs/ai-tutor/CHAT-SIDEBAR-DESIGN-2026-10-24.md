# AI 对话侧栏改进方案

2026-10-24，基于 Nodu 集成分支 cd16e87。本文是调研与设计，尚未修改生产侧栏。

## 结论

采用 Cursor 式紧凑对话布局，参考 Void 的输入容器、上下文引用、消息操作和会话存储边界，在 Nodu 现有 Theia/React 上实现。保留教学/提问两种模式；任务操作归共享任务窗，侧栏负责解释、评价和追问。品牌黄保留给教学高光与当前步骤，范字保持灰色。

## 调研依据

- [Cursor Agent 概览](https://cursor.com/docs/agent/overview)：侧边栏会话、停止、会话及检查点的不同职责。Nodu 本阶段不引入自主修改/执行终端的 Agent 模式。
- [Cursor 上下文引用](https://cursor.com/docs/agent/prompting)：输入框的 @ 引用、文件/目录等上下文和模型选择。Nodu 首期支持工程文件与选区，终端/串口等运行证据沿用现有可信采集链路，不冒充已支持任意附件。
- [Void 官方侧栏示例](https://voideditor.com/demos2/AgentMode.png)：中性的消息纵向排布、低对比文件操作行、底部整合输入区。它的代码应用/检查点属于自主编辑工作流，不照搬到用户亲自跟写的教学。
- [Void 仓库](https://github.com/voideditor/void)：当前公开页面显示2026-06-02归档，README声明deprecated；适合作源码参考，不宜作为持续维护的整套依赖。
- 本次读取的 Void 固定提交：`b3166e7ef2aefbdfeb139445fdf248a561b85d4d`。
- [SidebarChat.tsx](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/browser/react/src/sidebar-tsx/SidebarChat.tsx)：`VoidChatArea`整合上下文/正文/模式与模型/发送停止；`SelectedFiles`区分待发送与历史引用；`ScrollToBottomContainer`仅在底部跟随；文件定位与消息编辑独立处理。
- [chatThreadService.ts](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/browser/chatThreadService.ts)：会话状态、保存和消息生命周期。Nodu 应保留现有 Node 网关及授权，不直接移植 VS Code 的服务注册与存储实现。
- [Void 架构说明](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/VOID_CODEBASE_GUIDE.md)：React UI、编辑服务与模型调用之间的边界可参考。仓库LICENSE.txt为Apache-2.0；如后续实际复用源码，保留对应许可/通知并记录来源。本轮仅阅读，未复制其实现进产品。

Cursor网页描述存在版本差异，旧文档与最新Agent工作区不能混称一个版本。本方案使用稳定交互原则，未声称已运行本机Cursor完整验收。

## 当前代码发现

| 当前实现 | 对使用的影响 | 设计决定 |
|---|---|---|
| GoalPlan与任务窗均有检查/暂停/结束 | 重复控制、占聊天首屏 | 草案以消息显示；开始后压成一行任务引用 |
| MessageText用正则切代码块及文件链接 | 列表/强调/表格未形成完整Markdown，流中代码围栏不稳定 | 安全Markdown与CodeBlock独立组件 |
| 当前文件单个includeCode开关 | 多文件、特定选区难以表达，切文件可能改变待发上下文 | 增加明确的上下文引用列表与发送快照 |
| messages按两模式驻留内存，新对话清空当前数组 | 不能作为可浏览、跨重启恢复的会话历史 | 新建会话独立于清空/删除，增加持久化列表 |
| 有上滚停止跟随 | 用户缺少回到最新消息的入口 | 离开底部后显示小型向下按钮 |
| 所有错误均附“重连” | API认证、限流、上下文错误处理不匹配 | 按失败原因提供就地动作 |
| 消息只有整体复制 | 代码块、失败重试、发送上下文不够清晰 | 代码块复制、失败重试、上下文详情逐项补齐 |

以上来自 `nodu-tutor-widget.tsx`、`nodu-tutor-model.ts`，不是把规划中的能力当成现有能力。

## 界面布局

推荐默认宽380px，至少320px可用，沿用用户调整后的侧栏宽度。保持现有深浅色token和图标，正文13–14px、等宽代码13px、行高约1.5；无渐变、头像装饰、大空态口号、固定快捷问题卡或中点拼接说明。

```text
┌──────────────────────────────────┐
│ 串口输出教学                 历史 ＋ ⋯ │
│ USART1 周期输出          2/5    ↗ │
├──────────────────────────────────┤
│                  每秒打印一次温湿度 │
│                                  │
│ 先确认采样函数的返回值。读取成功后， │
│ 再格式化并发送数据。                │
│                                  │
│ main.c  24–31                 ↗  │
│ ┌──────────────────────────────┐ │
│ │ c                         复制│ │
│ │ …                            │ │
│ └──────────────────────────────┘ │
│                                  │
│ ✓ 消息发送已检查                  │
│ 下一步加入采样失败处理。            │
│                                  │
│                            ↓     │
│ ┌──────────────────────────────┐ │
│ │ main.c 24–31 ×   board.h ×   │ │
│ │ 输入问题或教学目标…             │ │
```

草图中的“历史/复制”等用图标或短文本；说明不作为产品常驻文案。示例中的温湿度与行号只用于布局，不宣称工程已有传感器或代码。

1. 顶栏显示会话名，新建/历史/更多采用小图标，hover和键盘焦点提供tooltip。历史是侧栏内弹出列表，带搜索和日期分组；设置、导出放更多菜单。
2. 任务引用只显示任务名、进度及打开任务窗动作。点击聚焦/显示既有共享任务窗；不复制步骤列表及暂停结束按钮。草案确认/修改仍嵌在生成计划的消息里。关闭任务窗仍可从此引用恢复，不自动恢复被用户关闭的AI指导总开关。
3. 用户消息用浅底紧凑块，AI回答直接排版，控制段落间距。代码块有语言、复制与可验证的文件定位；禁止任意模型文本直接变成执行动作。
4. 输入区固定底部，正文自然增高至约160px后内部滚动。引用胶囊在正文上方，模式/模型/添加引用/发送在底部同一行。窄尺寸模型名省略，完整名称tooltip或下拉显示。
5. 保留教学/提问模式，切换保留各自草稿与上下文。教学模式不提供一键把答案写进源码；查看范字必须经过现有授权、锚点校验与教学状态机。普通提问也不因复制代码就自动创建课程。
6. 空态仅留输入框中的短placeholder。无Key时在输入区提供“连接模型”；正常配置后消失。新建对话不重置正在进行的教学任务。

## 交互与反馈

- Enter发送、Shift+Enter换行；中文输入法组合期间Enter不发送。@打开可搜索的工程文件选择列表，Esc关列表，Tab/方向键/Enter选择。选中代码可通过命令/右键加入引用，快捷键先查项目冲突再定。
- 当前文件作为可见候选；点击固定为引用后，不随切换编辑器替换。发送时冻结路径、行范围、版本/摘要和限定大小的内容，历史消息展示当时实际发送的引用。
- 流式回答只在底部跟随。上滚保持位置，向下按钮返回最新；代码块增高、字体变化、侧栏缩窄不能强制跳到底部。
- 等待/生成用消息内短状态，发送按钮原位变停止。停止保留已收到文本及草稿，不标记完成。停止后不自动重发、不自动换模型或端点。
- 错误贴在失败消息或输入区：认证失败→模型设置；限流→可重试；网络中断→重试；文件不可用→移除/重新选取。跨工程/不可信引用不发送。一般错误不弹阻塞对话框。
- 复制成功采用短tooltip；普通保存/导出完成可用右下角短通知。移除引用不弹确认；删除会话提供可撤销恢复，清空不可恢复数据才使用确认弹窗。
- 消息操作在hover/focus显示，键盘始终可达。失败请求先支持原位置重试；编辑旧问题另存分支或新会话，不截断教学完成记录，也不回滚源码。
- 教学事件区分“代码已检查”“编译通过”“运行已观察”，依据现有证据来源渲染。没有编译/运行证据不能用通用成功图标冒充全流程完成。步骤高亮只打开对应位置与非侵入批注。

## 实现分层

保持现有NoduTutorModel入口和Node网关。新增组件不直接调用模型、操作硬件或写文件：

- `ChatHeader`：标题、历史、新建、更多。
- `ChatTimeline`：消息与教学事件、底部跟随。
- `ChatMessage` / `CodeBlock`：安全Markdown、代码复制、授权文件链接。
- `ChatComposer` / `ContextPicker`：草稿、模式/模型、引用选择及发送快照。
- `TaskReference`：打开既有任务窗，不另建教学状态。
- `ChatHistoryPopover`：会话搜索、选择、重命名及可恢复删除。
- Node侧`ChatSessionRepository`：工程隔离、模式、消息、时间、草稿、引用快照与关联目标；版本化格式、有界UTF8读取、原子写入与revision冲突处理，复用现有目录身份/授权校验。
- RPC扩充会话list/open/create/rename/archive及引用resolve；重连带conversationId和requestId，切会话迟到回包不进入新会话。终止后不重放历史pending。
- 教学检查/片段/纯函数/硬件证据维持原模块。Rust无需为侧栏排版增加新能力或包。已有AST/WASI继续经Node接口提供结果。
- Markdown先核查Theia已有服务/依赖可复用性，不能继续靠正则扩展完整语法；禁用原始HTML、远程图片默认不自动加载、限制链接协议、工程文件继续走授权解析。未流完的围栏按普通未完成代码区域展示，不执行内容。
- 多文件上下文是协议/服务端改造，不是把多个胶囊画出来就完成。接入前不展示虚假的可用按钮。

## 实施顺序与验收

| 批次 | 交付 | 验收重点 |
|---|---|---|
| 1 | 侧栏视觉草稿：空态/教学/提问/错误，深浅色及320/380/480宽度 | 与现有Nodu截图对比，取消重复任务控制，先确定结构 |
| 2 | 消息排版、代码块、紧凑输入框、任务引用与滚动体验 | 流式/停止/IME/键盘/长代码/复制失败/暗浅主题，现有教学测试不回退 |
| 3 | 会话保存与历史、新建不清教学进度 | 重启、损坏记录、双窗口revision、跨工程隔离、删除撤销 |
| 4 | @文件、选区引用、快照、失败重试 | 无效/越界/符号链接/大文件/未保存代码、发送后修改、断流迟到回包 |
| 5 | 教学事件整合与真实闭环 | 生成计划→确认→亲自跟写→评价→下一步→文件/批注跳转；编译与真机证据分别验收 |

先设计可对比的实际侧栏草稿，再替换生产组件。参考资料不是产品功能的承诺；本次未安装Void、未替换网关、未调用用户密钥、未修改真实会话/工程或操作硬件。
