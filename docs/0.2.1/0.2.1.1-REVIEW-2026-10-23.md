## 修改内容

| 项目 | 实现 |
| --- | --- |
| 编译完成提示 | 编译输出末尾保留“编译成功”；有警告时显示数量。失败、取消、编译期间源码变化各有对应结果，不再只停留在 Ninja 链接行。 |
| 左下角进度 | 显示下载方式、当前阶段、百分比及细进度条。编译按 Ninja 已完成/总任务数计算；配置阶段总量未知时显示活动条。下载按识别、备份、写入、校验、启动五个真实阶段推进，有阶段内进度时进一步细分。成功响应后才显示 100%，随后恢复简短方式名称。 |
| 设备信息 | 删除设备面板的 UID/电压小字行，保留主要芯片信息；原始识别信息仍在日志和运行记录中。 |
| 串口工具按钮 | 时间戳、暂停、HEX 使用统一的实色选中状态、普通未选中状态和禁用状态。鼠标点击后不遗留误导性的焦点边框；键盘焦点仍可见。HEX 模式下时间戳禁用。 |
| 多 ST-LINK | 自动读取目标芯片 ID 和 Flash 容量，只有唯一匹配目标时才选中。匹配不唯一或部分目标无法识别时要求明确选择，不猜测。macOS 支持用 USB 位置区分没有序列号的探针。选定后加锁，并在写入前重新检查目标身份。 |
| 串口偏好 | 修复选择“运行后不打开”后被设备刷新重新选中串口的问题。显式选择不打开会保存，首次未设置时仍可自动建议串口。 |

下载百分比表示工作流程完成度，并非已写入字节占比或剩余时间预测。无后台计时伪造进度。自动匹配也不能区分两块同系列、同容量且都符合工程条件的板子，此时需手动选 USB 位置/探针。

## F407 真机

测试工程：`artifacts/0211-f407-20261023/projects/f407-e2e`，使用 F407ZG 默认 UART 工程并增加可读取的主循环计数器，不假设开发板 LED 引脚。系统使用内部 HSI，SystemCoreClock 为 168 MHz。

同时连接两只 ST-LINK/V2，均没有 USB 序列号：

| USB 位置 | 实际目标 | 结果 |
| --- | --- | --- |
| `usb:3-1.2.1` | F103 | 识别后排除，未写入 |
| `usb:3-1.2.4` | F407，设备 ID `0x413`，1024 KiB Flash | 自动选中并完成下载 |

从桌面点击运行完成实际下载：首次备份完整 1 MiB Flash，写入 9412 字节，校验并回读，复位后进入运行。运行记录 `r-20261023-050807-0b95ff` 总耗时 12509 ms，结果为 `running`。

- 固件及回读 SHA-256：`0b47a5ce836eb0857c65de1173c16d45573c23459fbb0c07979d71d079ab7369`。
- 首次备份 SHA-256：`5d94950ba7e1708599cee9f111df6b49b0a4bf06b51fae8b39dac85dc49b62e9`，独立重新计算一致。备份保留于本机 `~/.nodu/stm32/backups/413-0018003d3033510430373735/20261023-050808/`，未纳入 Git。
- 独立读取主循环计数 64→66，系统 tick 63885→65398，证实程序持续执行；再次复位运行后计数 1→3。
- 非目标 F103 的完整 64 KiB Flash 在测试前后 SHA-256 均为 `1c5c3f60a58feeabef8d3a8bf17622aab50c0a31f547d67a6b1645c3f238774c`。

## 用户复测

1. 桌面端已打开 `f407-e2e`。修改后点击编译，观察左下角阶段与进度；完成后状态短暂显示 100%，编译输出末尾保留“编译成功”。快速增量构建可能立即完成，可用重新编译查看更多阶段。
2. 打开串口面板，分别点击时间戳、暂停、HEX，检查选中/取消与禁用状态；用 Tab 和空格操作，焦点应可见。
3. 打开设备面板，下载器保留“自动匹配目标芯片”；两只探针连接时点击识别，应识别出 F407。选择“运行后不打开”，刷新后应保留。
4. 如需再次下载，先确认工程内容和目标板，再点击运行。左下角应依次显示识别、备份、写入、校验、启动及最终运行状态。两块同类匹配芯片应要求手动选择，不能随机写入。

测试后 F407 保持运行本次验证固件，桌面端保持打开；原程序已有完整备份。
