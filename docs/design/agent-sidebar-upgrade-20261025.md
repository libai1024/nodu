# Nodu Agent 侧栏对照与升级方案

研究日期：2026-10-25。Nodu 基线：`d51b447`。

## 建议结论

采用「会话标题 → 连续消息与活动记录 → 当前教学任务摘要 → 固定输入区」的结构。借鉴 Cursor 的任务与变更审阅闭环、Void 的紧凑工具记录、Cascade 的计划与进度组织，保留 Nodu 的教学步骤、代码定位与硬件验证特色。

优先整理已有聊天和教学流程，再扩展工程上下文，最后建设真实的 Agent 执行链。未具备工具调用能力前，不展示虚假的工具过程、审批、文件变更或成功状态。

本轮交付为研究方案，未修改产品实现。当前机器锁屏，视觉基线使用同日已有 Electron 实机截图，并以最新源码核对行为。竞品依据官方资料、公开示例和源码；未把产品宣传图视为最新版本的像素规格。

## 竞品差异与借鉴

| 参考 | 已核实的机制 | 适合 Nodu 的部分 | 取舍 |
|---|---|---|---|
| Cursor | 上下文引用、可编辑计划、实时 diff、停止与检查点恢复 | 用户随时知道任务对象，能查看实际修改并纠正方向 | 不一次引入大量模式、多 Agent 和独立控制台 |
| Void | 上下文/输入/模式模型三层输入区，可折叠工具行，行内批准，输入框上方的变更汇总 | 工具过程紧凑；需要决定的事项靠近输入；BYOK 与当前架构接近 | 不能直接移植 VS Code 内部实现；接受/拒绝对初学者保留文字 |
| Cascade | 会话内 Todo、计划文件、Implement 入口、检查点、运行中排队 | 长任务只突出当前步骤和完成情况，细节可展开 | 避免把完整计划、每条工具日志和重复状态同时铺开 |

依据：[Cursor 上下文与输入](https://cursor.com/docs/agent/prompting)、[Cursor Plan](https://cursor.com/docs/agent/plan-mode)、[Cursor 实时审阅](https://cursor.com/learn/reviewing-testing)、[Void SidebarChat](https://github.com/voideditor/void/blob/b3166e7ef2aefbdfeb139445fdf248a561b85d4d/src/vs/workbench/contrib/void/browser/react/src/sidebar-tsx/SidebarChat.tsx)、[Cascade 概览](https://docs.devin.ai/desktop/cascade/cascade)。表中建议与取舍为针对 Nodu 的设计判断。

## 当前 Nodu：基础与缺口

| 维度 | 已有能力 | 升级点 |
|---|---|---|
| 会话头 | AI 对话、新建、历史、更多；超过8条时已有搜索 | 显示当前会话标题；历史补时间分组和重命名，审视现有搜索的可发现性 |
| 输入 | 自动增高、中文输入法、发送/停止、教学/提问、模型菜单 | 统一密度和命名；模式解释放菜单内部；缺少配置时保留可操作入口，正常状态不增加提示 |
| 上下文 | 当前文件、文件/选区 chips、工程选择、引用定位；发送时快照 | 增加 @ 选择；逐步支持诊断、构建输出、板卡配置、串口日志 |
| 消息 | 正文、列表、代码高亮/复制/折叠、引用、修改后再问、失败重试 | 支持标题和表格；用来源明确的结果块承载检查结果 |
| 过程 | 生成、制定计划、准备代码片段、检查状态 | 绑定真实事件的紧凑活动行，运行/失败突出，已完成折叠 |
| 教学 | 侧栏确认计划，独立任务窗管理步骤、检查、暂停、定位 | 侧栏增加共享任务摘要，减少两处查找，不复制另一套步骤状态 |
| Agent | 当前为文本流，消息仅 user/assistant | 工具事件、审批、变更集、diff、回滚、队列均须扩展底层 |

注意：当前「配置」按钮只在模型未配置时出现，并非所有会话常驻；模型菜单已有「管理模型」。优化应合并重复入口，保留首次配置的可发现性。

## 推荐的侧栏组织

```text
┌──────────────────────────────────┐
│ LED 闪烁教学 ▾              ＋ ⋯ │  当前会话；标题打开历史
├──────────────────────────────────┤
│ 用户需求                          │
│                                  │
│ 助手解释与建议                     │  连续正文，少用大卡片
│ ▸ 已检查当前片段                  │  真实活动；可展开详情
│ 当前结果 / 下一步                 │
│                                  │
├──────────────────────────────────┤
│ 跟写任务 · 2/5  GPIO 初始化    ›  │  仅存在教学任务时出现
├──────────────────────────────────┤
│ main.c:24–40                  ×  │
│ 问问这一步怎么写…                 │
│                                  │
│ ＋  教学 ▾  glm-5.3 ▾         ↑  │
└──────────────────────────────────┘
```

以上为结构示意。工程 Agent 阶段才增加「待执行操作」和「本轮文件修改」；它们按当前任务状态出现，不与教学摘要长期堆叠。

### 字体与密度

- 正文和输入统一为 14/22，保留 Scope Plex 与现有中文回退字体；元信息 12/18，代码 12–13/20。现在正文 13/1.6、面板 14/22，先消除层级漂移。
- 建议侧栏常用宽度 360–420px，保留现有 260px 最小宽度兼容。窄宽度优先截断模型名、折叠上下文，发送/停止始终可见。
- 会话头约 36–40px；内容横向留白 12–16px；消息间距约 20px；小型活动行约 28px。数值为 Nodu 的起始设计建议，并非竞品测量结果。
- 输入框保持低对比边框、约 12px 圆角，空闲时 2 行左右，随输入增高到现有 180px 上限。保留焦点边框，避免按钮和焦点同时形成多层蓝框。
- 助手消息保持连续正文；用户消息使用弱中性背景。蓝色用于主动作、焦点与当前选择，错误和待决事项按语义突出。
- 空态最多两个轻量入口，如「解释当前文件」「开始跟写」；点击填入草稿，用户发送后才开始。已有会话不插入介绍面板。
- 日常不增加提示段落。来源、模式权限、模型能力放在菜单或展开详情；失败和需要决定时才显示具体说明。

### 任务与状态

- 学生操作与 AI 操作分清：用「等待你完成第 2 步」「片段检查通过」表达真实主体，不能让模型回答完成等同于学生任务完成。
- 教学摘要绑定现有任务窗状态。点击展开或定位已有任务窗，不维护两份计划。
- 活动行只显示实际事件，例如「正在检查 main.c」；不伪造「思考」「搜索了 8 个文件」。已有后端未提供文件名时，仅显示已有真实状态。
- 检查结果显示依据：静态检查、编译结果、模拟结果、设备反馈分别标明。没有真板证据时不显示「硬件验证通过」。
- Agent 阶段：读取/搜索成功项可按一轮合并，当前执行、失败、待审批项保持可见。审批卡说明具体命令或目标；烧录包含目标板、下载器与固件，后端必须执行同一权限判断。
- 变更摘要显示文件数和增删行数，点击进入编辑器 diff；接受、拒绝和撤销要有清晰且不混用的语义。回滚需检测用户在运行期间的手工修改，不能直接覆盖。

## 分期交付

### 第一批：现有侧栏升级（高优先级）

范围：会话标题、现有历史搜索入口与时间分组、正文/输入字体统一、紧凑模式与模型菜单、适度空态、共享教学任务摘要、已有真实检查状态。

不新增通用 Agent 模式，不改现有模型调用协议；保留草稿、输入法、滚动位置、自动跟随、停止、重试、上下文快照等现有行为。

验收：

1. 260 / 320 / 400px 侧栏均无横向溢出，发送和停止可见。
2. 明暗主题、长模型名、6 个上下文、长代码块、生成中和错误状态均可读。
3. 用户阅读旧消息时流式回复不抢滚动；切换会话保留草稿与位置。
4. 教学摘要与任务窗的步骤数、当前步骤、暂停和检查状态一致。
5. 配置完整时输入区无配置提示；缺少配置时能一步打开正确设置页。

### 第二批：工程上下文与结果（中优先级）

范围：@ 与现有上下文选择共享同一入口；诊断/编译输出/板卡配置按可信类型接入；按需截取串口日志；结果块携带来源与定位。先接最常用的诊断和编译输出，再补设备数据。

依赖：服务端上下文授权、体积限制、路径和项目边界、日志截取与敏感内容处理。不能只给菜单加标签。

验收：能看到本轮实际引用的来源与时间；长输出被裁剪时明确可展开/查看原始输出；切换工程不会沿用错误设备或旧构建信息。

### 第三批：真实 Agent 闭环（独立能力建设）

先完成「只读检索 → 提出补丁 → 查看差异 → 用户确认应用 → 验证」小闭环；之后接入构建执行，再评估烧录与设备操作。

依赖：类型化运行事件、工具适配与执行器、服务端审批、文件版本/变更集、冲突保护、停止恢复、运行历史。不同模型支持工具调用的能力必须经过适配验证。

验收：停止不会继续落盘；旧审批不能批准新命令；工具失败有真实原因；修改有可定位 diff；撤销不会抹掉用户手工编辑；重启后可以识别未完成运行。排队消息放在此阶段，多 Agent 并行后置。

第一批制作高保真稿时，应同时呈现「新会话」「教学进行中」「失败恢复」三个真实状态；未来 Agent 执行/审阅稿单列并标明能力依赖。
