# Nodu 固定版 Arduino 随包环境

日期：2026-10-27。本文承接用户的最新约束：下载安装 Nodu 后就具有基本 Arduino 环境；当前不需要联网更新开发板索引，保证特定稳定版本即开即用。

## 产品约定

基础 Arduino 环境是 Nodu 安装内容的一部分。用户不安装 Arduino IDE、CLI、开发板支持包、Python 或 Homebrew，不配置路径，不点击“准备工具”。下载 Nodu 后，即使断网，也能新建 ESP32-C3/S3 项目、编辑和编译；串口烧录使用同一套随包工具。

首次打开只允许自动完成本地资源校验、展开与编辑器初始化。它不下载开发板索引，不检查最新 Core，不弹出安装向导，不保存或编译用户正在输入的源文件，也不抢占编辑器焦点。本地初始化和首次编译仍需要处理时间，不能把“无需联网安装”描述成零等待。

| 内容 | 当前固定值 / 行为 |
|---|---|
| Arduino CLI | 1.5.1 |
| Arduino-ESP32 Core | 3.3.12 |
| 首批完整流程 | ESP32-C3、ESP32-S3；Arduino 默认 |
| 常用库 | 现有 11 个固定版本归档与依赖闭包 |
| 代码补全 | 随包 ALS / clangd，沿用已验证版本 |
| 开发板索引 | 随包固定快照；没有自动更新、检查更新或版本升级入口 |
| 编译 / 烧录 / 串口 | 与 K210、STM32 共用操作位置与底部面板 |
| 新版本 | 随后续 Nodu 版本统一验收、打包；不静默改写已有项目版本 |
| 额外库 | 用户主动添加时按库管理流程处理，不触发开发板支持包升级 |

## 随包实现

发布工具把原始 CLI、Core、交叉编译器、烧录器和 CLI 所需工具归档、固定索引、原生兼容工具、许可证和对应源码材料编入按系统区分的资源包。官方下载文件名、版本、地址和 SHA-256 固定在 `desktop/scripts/arduino-release.lock.json`；制作安装包时可以获取这些固定输入，运行时不追踪上游最新版本。

运行资源路径为 `resources/arduino/offline/<host>`。正式安装包写入 `required.json`，缺少当前系统资源或资源损坏会明确报安装异常，不悄悄改用系统工具或联网下载。开发源码运行可以保留独立的开发准备路径，不能据此宣称发行包已经完整。

Arduino CLI 的 profile 安装存在两个需要明确处理的行为：

1. 即使已缓存全部压缩包，首次 profile Core 安装仍会创建临时目录并下载索引。因此发布阶段从已核验的官方 Core 归档生成可迁移的 profile Core 树及安装元数据。标识由公开的版本与索引 URL 计算，不含开发者电脑路径；不复制开发者的工程、构建缓存或个人配置。
2. CLI 生成编译数据库时，缺少某些依赖也可能返回成功退出码。环境初始化同时检查实际依赖错误和编译数据库，不能仅凭退出码或 `boards.txt` 显示“已就绪”。

首次打开使用应用私有的最小工程展开随包工具和固定库，结束后删除该临时工程。用户文件保持原样。编译操作直接进入一次正常编译，内部完成所需准备，不再先重复执行一次工程预处理。

内置库的精确版本记录会合并进本地库索引，保留其他库和版本；原始库索引可能比内置库归档旧，不能仅复制归档就认为已经可用。修改后的索引不继续使用旧快照签名。所有内置库归档仍独立校验。

开发板与工具索引每次按随包固定快照校验、恢复；仅库索引保留用户主动添加的内容。窗口关闭会取消其拥有的初始化任务，取消的排队请求不会在稍后启动；其他窗口等待同一次初始化时，退出等待不会中止拥有者的任务。显式准备和编译也检查依赖错误，准备操作要求生成新的编译数据库，避免旧文件或 CLI 的零退出码误报就绪。

苹果芯片版另带从同一 Arduino ctags 版本构建的原生 ARM64 工具，通过 Core 的 `platform.local.txt` 标准扩展点选择它。原厂归档与校验值保持原样，Nodu 的补充文件、构建来源、签名前后校验值单独记录。普通编译和串口上传无需依赖 Intel ctags / Rosetta；当前不承诺 DFU 或 SPIFFS 镜像制作等未实现流程。

## 验收口径

必须从空的 Nodu Arduino 数据目录开始，系统路径中不提供开发者的 Arduino CLI，拒绝读取已有 Arduino IDE、Arduino15 和旧测试缓存。测试进程及所有子进程禁止联网，并验证网络确实被系统拒绝。

- 打开一份尚未写完的 `.ino`，环境可以就绪、语言服务配置可用，用户源码和 profile 的哈希保持不变。
- C3、S3 的新工程实际引用全部 11 个内置库，使用随包工具完成编译，生成真实固件和构建凭据。
- 重新创建服务实例后继续编译，仍使用 Nodu 自己的 CLI。
- 苹果芯片测试禁止执行原厂 Intel ctags，确认基础路径使用 ARM64 工具。
- 资源校验失败、取消、重复初始化、旧索引缺内置版本、初始化退出码误报成功均须有回归覆盖。
- 正式包还要通过资源与源码材料完整性校验。开发环境中的断网编译通过，不等于正式安装包或其他操作系统已通过验收。

实际验证结果与初次失败证据见 [冷启动验收](esp32-arduino-offline-acceptance-20261027/README.md)。macOS ARM64 下，C3 / S3 和重新打开后的 C3 均在系统禁止联网、禁止使用旧 Intel ctags、无法读取已有开发缓存的条件下编译成功；未完成用户源码与 profile 未被改写。冷测完成时 Arduino 回归 **117/117**、打包回归 **24/24** 通过。后续固定索引恢复、取消生命周期和准备状态修复后，Arduino 与启动台合并回归 **137/137** 通过；这是后续自动化验证，没有重新执行上述完整冷测。

本机实测首次本地初始化 **60.102 秒**，C3 / S3 首次组合编译分别 **72.827 / 81.600 秒**。这是零额外下载、零手动安装的结果，并非瞬时就绪，也不是所有电脑的速度承诺。此前的缓存离线编译记录不能替代本轮空目录验收。

当前开发资源包包含约 1.95 GB 运行输入及约 427.5 MB 源码/许可材料。正式安装包未生成；25 个发布组件中仍有 20 个对应源码或依赖归档覆盖未完整，发布校验保留拒绝状态。具体缺口见 [源码材料记录](esp32-arduino-release-sources-20261027.md)。Windows、Intel Mac、真实 USB 与未实现上传方式不在本轮冷启动实测结论内。
