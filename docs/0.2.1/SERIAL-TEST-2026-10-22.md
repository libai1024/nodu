# STM32F103 串口实测与热插拔修复

日期：2026-10-22。用户已连接 ST-LINK 和 PA9/PA10 串口，授权实机测试。全部串口通信结果来自真实硬件。

## 问题与处理方案

新插入的 USB 串口不出现在已打开的列表中。原因是列表只在打开工程或设备弹层时枚举，串口监视器没有持续刷新入口。

采用面板可见时的轻量轮询：

- 串口监视器可见、页面处于前台时，每 2 秒重新枚举端口。
- 窗口重新获得焦点、页面恢复可见、点击串口监视器标签时立即刷新。
- 请求合并，上一轮未结束时不重复请求；端口集合未变化时不触发渲染。
- 保留用户选择和正在连接的串口。拔出后保留所选项并标记未连接，插回后恢复实际端口选项。不会因为列表更新而切换到另一个设备。
- 从未选择端口且只有一个 USB 串口时，自动填入该端口，但不会自动打开它。
- 隐藏面板或切至后台后停止枚举。组件销毁时清理计时器和事件监听。

沿用现有跨平台串口枚举接口，无需分别维护 macOS、Windows、Linux 的 USB 通知适配层。2 秒是刷新间隔，不是本次测得的严格最坏响应时间；繁忙系统、驱动枚举和 RPC 延迟会影响实际时间。

## 一并修复

1. 连接中修改波特率，原先只保存项目设置；现在重新配置实际串口，重配置期间禁用发送和连接参数控件。
2. GBK 模式发送原先仍按 UTF-8 编码；现在后端按所选编码发送，并拒绝无法表示的字符。
3. 十六进制显示原先重新编码已解码的文本，会丢失 NUL、换行及非法 UTF-8 字节；现在保留独立的原始字节缓冲，显示原始数据，最多保留最近 64 KiB。
4. 发送失败保留输入内容；防止重复提交。错误在面板内出现，成功发送后清除。
5. 复制包含尚未换行的内容；十六进制模式复制对应字节表示。
6. 页面刷新后同步底层连接状态，避免仍在接收但界面显示未连接。
7. 切换到无效端口失败时，底层明确报告原端口已关闭，避免界面状态与资源状态不一致。
8. 超长行分段保持输出顺序；连接按钮保留稳定的“打开/关闭”名称，忙碌时禁用并设置 aria-busy。

## 硬件与测试程序

- 芯片 STM32F103C8T6，ID 0x410，Flash 64 KiB。
- ST-LINK/V2，串口 CH340 `/dev/cu.usbserial-31230`。
- USART1 PA9 TX、PA10 RX，默认 115200、8N1。
- 独立测试工程：`artifacts/f103-ui-20261022/projects/f103-uart-e2e`。原 `f103-e2e` 工程保留。
- 测试命令包括 PING、UTF8、GBK、BINARY、BURST、LONG、STREAM、STOP、BAUD:9600、BAUD:115200；其他输入回显实际接收字节。
- 测试固件仍保留在板子上。此前用户原程序的 64 KiB 备份仍位于 `artifacts/f103-ui-20261022/device-state/stm32/backups/`。

## 实测结果

| 检查 | 结果 |
| --- | --- |
| ASCII 双向 PING/PONG | 通过 |
| CR LF、LF、无行尾的实际发送字节 | 通过 |
| UTF-8 / GBK 中文双向收发 | 通过 |
| 每字节间隔 55 ms 的中文分包显示 | 通过，无拆字乱码 |
| NUL、CR、LF、0xFF 等原始二进制 | 通过，HEX 为 `00 01 0a 0d 7f 80 ff c3 28 00 7e` |
| 非法文本字节、未换行内容复制 | 通过 |
| GBK 发送 emoji | 正确拒绝，输入保留 |
| 1000 行连续输出 | 原始接收及界面均为 1000 行，顺序正确 |
| 20000 字节长行 | 原始接收完整 |
| 5 次关闭/重新打开 | 通过，每次均能通信 |
| 9600 ↔ 115200 | 底层及界面重新配置后通信通过 |
| 自动滚动、向上阅读暂停跟随 | 通过 |
| 页面刷新后的连接恢复 | 通过，无需重新点击打开 |
| 串口打开时连续 3 次 ST-LINK 下载 | 通过，每次收到启动输出且运行分隔/历史保留 |
| USB 串口物理拔插 | 用户拔出 5 秒后重插；列表自动更新、自动重连，PING 返回 PONG，旧记录保留 |
| 切换无效端口后状态恢复 | 正确关闭，重新打开真实端口可通信 |
| 第二进程抢占串口 | 正确返回 portBusy，原连接仍可通信 |
| 关闭后发送 | 正确返回 notOpen |

波特率切换的过渡瞬间，设备与主机尚未同时切换时出现乱码属两端参数短暂不一致；测试以两端完成切换后的 PING/PONG 验证实际生效。

第一轮测试脚本曾在分包中文的最后一个字节刚到达时立即发送下一条命令，测试固件仍在延迟/发送换行，导致后续命令丢字。将断言改为等待完整响应及短暂空闲后，全部通过；未将这一测试程序时序问题归因于产品收发。

## UI 复核

保留 Nodu 的颜色、字体、按钮和输入框。连接状态简化为“已连接/未连接/等待重连/下载中”，参数分别为串口、波特率、编码；发送区为输入、行尾、发送按钮。未添加常驻解释、二级标题或“·”拼接文案。参数行允许换行，串口/波特率/编码宽度受控；本次截图宽 1134 px，无控件遮挡。此前选择的 IDEA 02 新建项目布局保持不变。

既有串口面板满足本次日常收发及下载联调使用。旧设计稿还包含时间戳、日志导出、独立暂停按钮、分隔折叠、Shift+Enter 多行发送等扩展，当前面板未全部实现，本轮不将这些记为已完成。实际暂停跟随通过向上滚动实现。
