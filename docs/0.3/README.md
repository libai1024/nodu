# Nodu 0.3：账号、AI 服务商与设备授权

设计日期：2026-10-23。状态：调研与拟议设计，尚未实施。AI 教学功能由 Claude 继续开发，本方案不修改其代码。

**推荐：基于 New API 二次开发云端；Nodu 提供“官方服务 / 自定义服务商”两条 AI 启用路径。官方服务需登录账号并具备可用额度；自定义服务商需先用一次性授权码绑定运行 Nodu 的电脑，再配置协议、地址、端口和模型。**

一次性的是授权码的首次兑换，不是每次启动只能使用一次。兑换后生成可续租、可撤销、可换绑的设备许可证。自定义服务商的 API Key 留在本机，模型请求直接到用户配置的服务商；云端仅负责软件授权。

关键边界：

- 未登录或未激活时，编辑、编译、下载、串口、本地确定性检查仍可用；关闭的是模型辅助功能。
- 官方账号和自定义许可证相互独立，不能把自定义授权码当充值码，不能因云余额不足自动使用用户的密钥。
- “绑定硬件”默认指运行 Nodu 的电脑，不是 STM32、ST-LINK 或 USB 串口。
- 硬件标识、设备签名和短期许可可防普通复制；没有硬件证明时不能保证完全防伪造，更不能保证开源客户端无法被修改绕过。
- New API 的网络服务开源义务需要按锁定版本评估；若二开服务必须闭源，优先重新评估 MIT 的 One API 或获得合适商业授权。

本次只完成设计与资料核对，不部署云服务、不生成真实授权码、不收费、不使用已有测试密钥进行额外请求。
