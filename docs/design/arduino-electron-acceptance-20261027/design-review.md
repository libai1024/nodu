## 本轮已关闭的两处问题

1. **[已关闭 / P2] 已保存但离线的上传端口仍显示绿色设备状态。** `scope-workbench.tsx:324` 仅用 `selectedPort` 是否非空决定 `connected`；设备弹层已能列出“未连接”端口，两处状态互相矛盾。重新打开旧项目或拔掉设备后可触发。用当前 `ports` 是否存在所选路径决定可用状态，并将“串口可用 / 未连接 / 未选择串口”等实际状态放进 title 和可访问名称；不要把持久化选择当作连接成功。复核结果：当前实现已使用 `ports.some`；aria/title 明确显示“串口可用 / 串口未连接 / 未选择串口”，并新增离线端口回归用例。

2. **[已关闭 / P2] 首次准备工具前无理由禁用板卡选择。** `nodu-arduino-device.tsx:25` 用 `!project.ready` 禁用“开发板”，但随包 `boards-3.3.12.json` 已提供板卡与选项，且同屏高级参数可以修改。用户应先选自己的板卡，再准备所需环境。将禁用条件收窄为操作忙碌 / 项目尚未读取 / 无可用选项，沿用已有菜单与后端校验。复核结果：禁用条件已改为 `locked || !project`，无菜单项时仍由共享 NoduSelect 自行禁用。

## 已通过的设计检查

- Arduino / ESP-IDF 同时保留 Logo 与名称，新建默认 Arduino；未额外创建一个 ESP32 专用工作台。
- 库位于左侧，与现有文件、搜索入口同属工作台；设备与高级参数沿用原设备弹层；编译、烧录、运行、停止沿用既有工具栏图标与位置。
- 库筛选、版本、开发板、板卡参数、端口、波特率和编码均复用 `NoduSelect`，没有引入系统下拉框。共用组件提供键盘选择、焦点和弹层边界处理。
- 新增区域的字号、边框、间距、深浅色来自现有主题与紧凑工作台；没有大卡片、大面积装饰或常驻流程解释。
- 库内容只显示名称、作者、用途、版本和操作；高级板卡参数默认折叠。错误仅在实际发生时出现。
- 真实编译错误进入常驻问题页，成功后清零；串口仍在同一底部面板，行尾直接显示 `\r\n`。
- 已核对 root 最新修复：库版本 / 操作 / 移除保持同一行；串口设置使用独立 `monitorSettingsLocked`，编译中锁设置但不锁已有串口收发。这两点比现有旧截图更新，不重复要求修改。
