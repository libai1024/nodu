# AI 教学完整评审方案

2026-10-23，设计分支 `codex/ai-tutor-design`。状态：待共同定稿。本文是产品与 UI 评审入口；不是已经落地的功能清单。配套 [交互草稿](ui-prototype.html)、[详细交互协议](INTERACTION-DESIGN.md)、[工程实施方案](IMPLEMENTATION.md)、[开源复用选型](OPEN-SOURCE.md)、[实施路线图](ROADMAP.md)。

## 1. 推荐组合

一个 AI 右栏，教学与提问两个模式。教学时，当前步骤留在右栏顶部，代码高光、浮动批注和虚影直接作用在编辑区。保留项目原有组件风格、字号、边框、蓝色与深浅主题。

右上角仅一个 AI 分体入口；步骤浮窗可选、默认关闭。逐行检查自动进行，整步检查由按钮触发。主界面不放常驻说明段、重复二级标题或中点拼接文案。

推荐以 Theia AI 为基础，优先评估同版本聊天组件的受控复用，Nodu 自定义教学布局和编辑器辅助。开源侧边栏能够减少聊天基础工作，但不能直接提供本项目的教学闭环。

## 2. 右栏结构

```text
┌─────────────────────── Nodu ────────────── [AI 教学 ▾] ┐
│ 文件 │ sht30.c                         │ [教学] [提问] × │
│      │                                │ 7/13 读取数据   │
│      │ 高光：通信返回值判断             │      [检查本步] │
│      │  ⤷ 批注标记                    │ sht30.c:7       │
│      │                                │ 全部步骤     ⌄ │
│      │ 灰色代码虚影，学生从这里敲入     │                │
│      │ 输入一行 → 自动检查             │ 教学对话       │
│      │                                │ 引用与短反馈   │
│      │                                │                │
│      │                                │ [输入问题…   ] │
│      │ 编译输出 / 串口                 │ 引用       发送 │
└────────────────────────────────────────────────────────┘
```

右栏建议默认 360 px，可调 320–480 px；当前草稿约 350 px。普通按钮高 28–32 px，正文 13 px，间距 6–12 px。聊天正文占剩余空间，输入框固定底部。模型配置、历史会话等低频设置放在现有设置或面板的更多菜单中，不挤进每条回复。

教学模式顶部只保留当前任务、进度、定位、检查按钮和简短条件。全部步骤默认折叠，不逐条铺满。提问模式隐藏课程区，聊天获得全部高度。

980 px 桌面窗口优先收起文件树，保持代码可读；更窄的浏览器以可关闭抽屉展示 AI。浮窗在空间不足时变成编辑器顶部短条。以上尺寸为评审基线，真实 Monaco 的缩放和遮挡需要实施时验证。

## 3. 两种模式

| 行为 | 教学 | 提问 |
| --- | --- | --- |
| 主要用途 | 围绕目标，分步骤学会写代码 | 解释代码、报错、接口和概念 |
| 对话 | 随时追问当前步骤，不必切模式 | 自由提问，可引用当前文件或选区 |
| 当前步骤 | 显示，整课折叠 | 隐藏，不推进学习进度 |
| 高光 / 批注 | AI 可提出受控展示对象 | 首期仅提供代码引用和点击定位 |
| 代码虚影 | 显示真实待输入代码 | 隐藏 |
| 行检查 | 完成一行自动检查 | 不自动检查 |
| 源码 / 设备 | 学生写代码，原有按钮编译和运行 | 同左 |

两种模式分别保存草稿和对话上下文。切模式不丢进度、不携带整份历史；学生可以主动引用当前步骤或选中代码。切到提问或暂停教学时停止新教学请求，旧结果不能在切回后突然覆盖代码。关闭面板只收起布局，仍启用的教学在编辑器继续。

## 4. 三种代码辅助

### 代码高光

AI 讲解哪段，就浅色强调哪段。默认一处关注点，必要时最多三处关联代码。保留语法颜色，不制造真实选区，不移光标、不自动滚动。点击对话引用才跳转。教学标记与编译错误波浪线使用不同样式。

### 浮动批注

对应行旁放一个轻量标记。悬停或键盘展开后显示 1–3 句解释，可继续追问、钉住和关闭；一次只打开一条。优先放在代码旁或下方空白处，空间不足转行下展开区或右栏。

批注是教学元数据，不写入 `.c` 文件，不进入复制或保存内容。相关代码变化后立即失效，重新核对位置再展示，不能一直贴着旧行号。

### 虚影跟写

实际代码以灰色显示，与源码同字号、同基线。输入的字符变正常，未输入后缀仍为虚影。学生亲手敲；不提供 Tab 一键接受。

Enter 完成一行后自动检查。正确只留轻量确认，错误给一个具体修改方向，无法独立判断则显示“待上下文”。例如未闭合的 `if` 不应立即报错，等块完成再核对。

AI 按上下文和学习目标检查语义，接受合理的变量名、条件方向和等价写法。学生输入不同写法时隐藏不匹配后缀，通过后按实际代码生成下一行。网络等待不能锁住编辑器；旧版本响应不能贴回新源码。

## 5. 为什么还需要“检查本步”

行检查回答“这一行目前是否合理”；整步检查回答“这一目标是否完成”。两者都需要。

例如每行 CRC 判断都合理，工程仍可能缺少湿度校验、头文件声明、错误测试或新的编译结果。点击“检查本步”汇总当前代码、行检查、已有编译与测试证据，给出待完成项；不会顺便执行编译、下载或复位。

仍有行检查在队列中时显示“行检查未完成”，不再重复提交。整步满足条件后出现“下一步”，由学生继续，不能因某一行通过就跳课程。

## 6. 步骤浮窗与右上角开关

建议步骤浮窗默认关闭。它服务于收起 AI 右栏后专注写代码的场景，只包含进度、当前任务、检查本步和关闭。允许钉在空白边角；小窗口改为单行条。不让聊天、批注和步骤三个浮窗同时追着光标移动。

右上角采用一个分体按钮：

| 操作 | 效果 |
| --- | --- |
| 点击 `AI 教学` / `AI 提问` 主体 | 展开、收起同一个右栏 |
| 点击箭头 | 展开虚影、高光、批注、步骤浮窗的显示开关 |
| 暂停教学 | 停止自动检查，隐藏虚影，保留当前进度与输入 |
| 继续教学 | 按最新源码恢复，相关变化重新检查 |

收起面板和隐藏虚影不会停止自动检查；暂停会。按钮短标签显示当前模式或暂停状态，让用户无需猜测。不会同时增加左侧 AI 图标、悬浮球和新的顶级页。

## 7. 更直观的教学设计

先做四件事，不再增加一套学习模式：

1. **讲解与代码对应。** 点击对话中的文件行号定位，高光和批注解释眼前这段代码。
2. **关键处预测一次。** 比如“通信失败会走哪个分支？”点选后强调对应路径。只在关键概念出现，明确是示意而非实机轨迹。
3. **跟写后小改写。** 跟写温度 CRC 后，尝试自己写湿度 CRC；“自己写”临时隐藏虚影，随时可以继续跟写，不强制撤掉辅助。
4. **结果回到代码。** 测试失败显示期望值与实际值，定位对应断言/代码。串口输出只有具备来源映射时才能精确跳源码，不凭文本猜测。

参考 [Raspberry Pi 教学原则](https://www.raspberrypi.org/teach/pedagogy) 中的代码阅读、示范与改写，以及 [EEF 反馈综述](https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/feedback) 对具体反馈的建议。产品效果仍需学生试用；不以抄写速度、相似度或每行通过数量代替理解评价。

## 8. 前后端分工

| 层 | 负责的能力 | 主要复用 / 新增 |
| --- | --- | --- |
| UI / React | 双模式右栏、消息、草稿、当前步骤、快速开关 | 现有 Nodu 组件；Theia 聊天基础候选 |
| Monaco | 高光、行旁批注、浮层避让、虚影、完成行事件、行状态 | decorations、content widget、view zone；新增教学 controller |
| Node / TypeScript | 会话、上下文、流式回复、行队列、展示工具校验、计划与记录 | Theia AI + Nodu TutorService / ModelGateway |
| Rust | C 语法/依赖定位、局部规则、构建与串口证据适配、受控纯函数测试 | 现有 serde、sha2、ts-rs 等；新增 tree-sitter，按需 Wasmtime 测试组件 |
| 课程内容 | 芯片 / SDK / 接线、目标、候选代码、正确与错误样例、验收条件 | 首条 F103C8T6 温湿度课程；F407 独立移植验收 |

AI 通过结构化 `showCodeFocus` / `showCodeNote` 请求展示内容，前端核对源码版本后渲染。行结果绑定行身份、源码快照、步骤版本和模式代次。Node 保存状态；Rust 不再建立一套模型连接或课程进度存储。

## 9. 实施与验收

先共同确定本页 UI，再做 M0 小样验证开源组件可裁剪性。M1 做双模式与编辑辅助，M2–M4 建立本地检查、板上证据和纯函数测试，M5 接模型与逐行审阅，M6 做课程、平台与真实学习验证。详细任务和依赖见 [路线图](ROADMAP.md)；当前估算 48–72 人日，M0 后校准，不是已承诺的交付日期。

UI 必测：两模式草稿恢复；高光不抢光标；批注鼠标/键盘可达；虚影与真实字符对齐；不同有效写法；未完成代码块；修改后旧结果失效；步骤检查不重复排队；收起与暂停不同；窄窗口、深浅主题、缩放和输入法。教学验证另看学生能否解释、改写和定位错误，不能用静态交互稿代替模型或课堂测试。

## 10. 本轮希望共同确定的 UI 决定

| 决定 | 推荐 | 备选 |
| --- | --- | --- |
| 步骤位置 | 右栏顶部固定，浮窗手动开启 | 默认钉住浮窗 |
| AI 入口 | 右上角短文字分体按钮，能看出模式 / 暂停 | 纯图标，状态放浮层 |
| 行反馈 | 正确轻标记，有问题时展开一条短反馈 | 每行都展开解释，会更密集 |

当前交互稿用于讨论这些取舍，点击场景按钮可看教学、批注、专注写代码和窄版。所有 AI 回复、行检查与编译状态均为固定示例，尚未接入模型或硬件。
