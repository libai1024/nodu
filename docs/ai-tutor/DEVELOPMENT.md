- 工具栏不渲染 AI 分体按钮；切到简洁模式时关闭已打开的 AI 侧栏。

Browser 实测（端口 4201）：专业模式到简洁模式，AI 入口、侧栏、编辑器标记均消失，命令不可用，`send` 无请求；切回专业模式后入口和侧栏恢复，工作区授权仍在。`test:tutor` 67/67。课程进度和聊天偏好不受影响。

### Browser 实测（Node 24，独立配置目录 `/tmp/claude-501/nodu-tutor-p0`，端口 4201）

测试工程是 `examples/stm32-sht30-tutor` 的临时副本，课程按测试目标 STM32F407VET6 迁移为 schema 2；仓库内示例未修改。使用真实 GLM Coding Plan（glm-5.3）。

实测中发现并修复三个问题：

1. 后端启动报错 `construct Symbol(NoduTutorStore) in a synchronous way`：inversify 把绑定的 Promise 当成异步依赖。改为在 holder 对象里保存 `ready` Promise。
2. 编辑器切换文件后侧栏不显示当前文件，“检查本步”一直不可用：`updateBuffer` 不通知面板。现在路径变化时通知，不在每次按键时重绘。
3. 一次 Enter 生成两条行检查：`deltaDecorations` 会同步派发 Monaco 积压的光标事件，重入 `enqueue`；控制台还会报 `Invoking deltaDecorations recursively`。加入重入保护，并且先移出 `changed` 再入队。修复后一次 Enter 只生成 1 条任务，控制台没有错误。

| 场景 | 结果 |
| --- | --- |
| 逐行检查进行中提问 | 发送按钮可用，问题立刻发出，两条请求同时进行；回答正常完成，行检查得到 `ok` |
| 停止 | 消息变为“已停止”，按钮立刻恢复为“发送”；6 秒后仍是“已停止”，没有迟到的回复覆盖；之后再提问正常回答 |
| 两条通道都在进行时切到提问 | 对话和行检查都被取消，教学消息落为“已停止”，行任务标为“检查已取消”；课程区和行标记隐藏 |
| 草稿 | 教学和提问的草稿分别保留，切回后各自恢复 |
| 暂停 | 行检查被取消，发送不可用并显示“教学已暂停”，暂停期间按 Enter 不会发出请求；继续后可以发送 |

本轮共发出约 12 次真实模型请求（5 次对话，其中 2 次被停止；其余为逐行检查）。

仍存在：重新打开同一文件会生成新的 EditorWidget 和新的控制器，旧行结果不会迁移过去；行状态的样式和悬停反馈仍是初稿，按计划在 P3 处理。Electron 版本、钥匙串 ABI、SSE 边界情况尚未验证。本批没有操作硬件。

## 2026-10-23 第二批：存储恢复与会话接口

在 `codex/ai-tutor-foundation` 上继续 M1-02。本批实现迁移恢复、Node 学习记录存储、学习操作归约和按连接隔离的接口层；保持课程、存储、协议、界面分离。

### 实现范围

| 模块 | 职责 |
| --- | --- |
| `tutor-course-repository.ts` | 迁移前持久化 `.migration.json`；启动读取时收尾或恢复。目标文件已存在时保留它，缺失时从实际移出的 recovery 文件恢复；不猜测旧备份 |
| `common/tutor/tutor-learning-state.ts` | 纯函数处理选步、自查、选择方案、提示、参考、重开和重置；必需依赖控制可开始状态，自查只能产生 self-checked |
| `common/tutor/tutor-storage-protocol.ts` | 共享会话、迁移、状态与事件类型；只接收后端分配的工程/会话标识 |
| `tutor-progress-store.ts` | 本机学习记录、课程历史、顺序事件、摘要链、冲突比较、重试去重和有界重放 |
| `tutor-storage-server.ts` | 按连接持有工程授权和会话；冻结的无原型白名单 facade；跨窗口通知、关闭/撤销和迟到写入检查 |

存储目录由宿主提供，示例布局为 `应用数据/tutor/<projectKey>/state.json`、`events.jsonl` 和 `plans/<hash>.json`。工程键由规范路径及目录 dev/ino 身份摘要生成；复制工程或在同一路径重新创建目录不会继承旧学习会话。旧 localStorage 数据只能一次导入到空白学习记录，原始输入不删除；课程变化会开始新的进度投影，历史课程和事件保留。

### 提交与恢复语义

- 事件日志是学习记录的持久事实源。追加事件并同步后才发布通知；`state.json` 是可重建的缓存，通过临时文件、同步和替换更新。
- 日志写入失败返回错误，不发成功通知。日志已经持久化、缓存写入失败时仍可返回已保存；重启由日志重建缓存。若提交结果不明，调用方使用同一 requestId 重试或重新拉快照。
- 记录带连续序号和摘要链。只丢弃没有完整换行的尾部残片，并追加 recovered 事件；完整行损坏、顺序断裂、摘要不符或已提交日志缺失会报错并保留数据，不静默重置。
- 最近 256 个事件支持增量重放和请求去重；更大的序号缺口返回全量快照。超出重试窗口的旧请求仍受 expectedSequence/planHash 约束，不能重复修改当前状态。
- 同一 Node 后端中的多个窗口/Store 实例串行写入。独立后端进程同时写同一学习目录尚不支持，不能把本批结果解释为跨进程数据库事务。
- 学习记录上限 100 MiB；单事件上限 512 KiB，进度对象上限 256 KiB。读取日志分块进行，不一次载入整个日志；内存只保留最近 256 个事件。
- 撤销工程授权后，未开始提交的学习操作和迁移被拒绝；已经进入持久提交的动作不会强行半途回滚。关闭连接移除通知订阅和会话。

### 审查发现与修复

1. 迁移对象的紧凑 JSON 合法，但格式化保存可能超过 512 KiB。预览即校验最终序列化字节数，防止保存成功后无法再次读取。
2. 直接写最终备份文件可能留下半文件并阻塞重试。改为临时文件写入、同步、独占发布，再同步备份目录和父目录。
3. 最后一次摘要检查与替换之间存在外部保存窗口。先保留实际移出的文件，再检查它的摘要，随后使用不会覆盖现有文件的链接发布；冲突时只在目标缺失的情况下恢复。
4. 外部编辑器可能仍持有旧文件句柄。保留 `backups/recovery-*.json` 承接晚写，原始摘要备份为单独文件；新课程不受晚写影响。
5. 非法 UTF-8 原先可能被替换字符静默解码。现为严格拒绝，避免备份与输入字节不一致。

这里的事务保证包含同进程协作写入和已测试的外部保存窗口，不宣称通用文件系统原子 CAS。迁移存在短暂的活动文件缺席窗口；进程恰在该窗口退出时，数据保留在备份目录，启动恢复和结果确认仍是 M1-02 待实现项。因此当前 repository 不接 RPC/UI，也不迁移用户现有项目。Windows 的链接、目录同步、打开文件共享语义尚未实测。
