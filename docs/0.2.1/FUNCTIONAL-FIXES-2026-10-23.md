| 问题 | 当前实现 |
| --- | --- |
| 新建 C 模块 | 项目菜单新增“新建 C 模块…”，一次创建 `App/name.c` 和 `App/name.h`，打开源文件。只适用于 Nodu 管理的 CMake 工程，下一次编译自动收集。校验名称、保留名称和目录边界；任一文件已存在都不覆盖，创建失败回滚本次新文件。外部 CMake 工程仍按其自身构建规则添加源文件。 |
| 工程设置 | 项目菜单及设备面板可进入。提供 Debug / Release、`printf` 浮点、芯片来源、F103C8 可选自动下载配置。先验证全部选项，再一次性保存，避免部分更新。保存本身不下载、不复位、不连接串口。 |
| 串口辅助功能 | 新增时间戳、独立暂停/继续、保存日志。暂停只冻结显示，后台继续接收；继续后显示保留缓冲区内的新数据。复制和保存取当前视图快照，包含未换行文本；HEX 保存原始字节的十六进制文本。清空同时清理文本、解码残留和 HEX。保存取消不写文件，失败显示原因。 |
| 工具包信息 | 项目菜单“STM32 工具包…”及设备面板“详情…”。显示组件版本、许可声明、存在的许可正文、实际文件字节数、总占用与检查状态，支持主动完整校验。校验放在工作线程，串口控制请求不被哈希计算阻塞。不会补造开发版工具包中没有附带的许可正文。 |
| 兼容芯片 | 工程设置选择“兼容芯片”，每次下载/恢复前明确确认。取消不会进入下载；后端也拒绝缺少单次确认的请求。确认不绕过设备 ID、Flash 容量、读保护、备份 UID 和读回校验。无法仅凭某些兼容芯片复用的设备 ID 自动认定厂商，需用户如实指定来源；不等于已兼容所有非 ST 芯片。 |
| DTR/RTS 自动下载 | 默认关闭，仅允许 STM32F103C8T6。显式配置 DTR 控制 BOOT0、RTS 控制 NRST 的有效极性并确认接线。自动 ISP 在一个串口句柄内完成进入 ROM、识别、首次备份、按页擦除、写入和读回，避免外部下载器反复打开端口改变控制线。校验成功后才请求切回用户程序并复位；错误时不追加运行复位。串口监视器打开、恢复和重连使用配置的空闲电平。界面只报告“已请求运行”，不把发出复位等同于已证明程序运行。**仅通过模拟测试，实物电路待验收。** |
| 旧编译问题 | 编辑器内修改（包括未保存）、磁盘源码/构建配置变化后显示“已过期”，清除旧编译标记及错误计数，保留旧列表供查看。编译期间发生未保存修改也将结果标为过期，不能用于本次运行；重新编译替换结果。clangd 的实时诊断独立保留。 |
| 设备面板 | 按目标芯片显示内核、Flash、RAM；删除中点拼接和常驻解释。备份统一称“首次备份”，新记录使用 `firstBackup`，旧 `factory` 记录兼容显示，不再暗示是厂商预装程序。 |
| 既有下载帮助 | 保留菜单分隔、弹窗、状态栏方式/实际阶段进度和信息图标入口。补充可选自动 ISP 的范围与未实测状态；打开帮助仍不触发硬件操作。 |

指定开发板 LED、F103 板型核对已从本期必选验收中移除，以芯片默认工程为准。F407 实物、Windows 发布等未验证项目仍保留原待测状态。断点调试、AI 教学、串口绘图未纳入本轮。

## 醒后测试：先不下载，约 10 分钟

打开当前浏览器工作台（`http://127.0.0.1:4215/`）。原串口测试工程路径为 `artifacts/f103-ui-20261022/projects/f103-uart-e2e`；纯界面/编译测试工程为同目录的 `functional-review`。页面已恢复到原串口工程，监视器保持关闭。不要给当前只有 TX/RX 的连接启用 DTR/RTS 自动下载。

1. **模块创建**：在 `functional-review` 的项目菜单选择“新建 C 模块…”，填 `sensor2`，按 Enter。应生成两个文件并打开 `.c`；编译成功。再次创建同名模块应拒绝，原文件内容不变。
2. **工程设置**：勾选 `printf 浮点支持（%f）`，保存，再打开确认保留。切换 Debug / Release 后编译应成功。保存设置不应让板子复位或串口连接。
3. **旧诊断**：在测试模块临时加入 `int test_error = ;`，编译，应出现错误。编辑该行但先不保存，应立即出现“已过期”，旧编译错误计数撤下。修好并重新编译，过期标记和旧列表应清除。
4. **工具包**：打开“STM32 工具包…”，确认版本、占用和许可可读；查看一个许可正文并返回；点“完整检查”，最终显示检查通过。用 Tab/Shift+Tab 遍历、Esc 关闭，焦点应回入口。
5. **帮助与状态栏**：分别从下载下拉菜单底部和状态栏信息图标打开帮助；鼠标悬停信息图标能看帮助。关闭后当前下载方式不变，不应新增下载记录、复位或连接串口。用键盘 Enter 打开、Esc 关闭也应正常。
6. **现有程序通信**：回到 `f103-uart-e2e`，BOOT0 保持 0，USART1 原接线不变。监视器选择 USB 串口、115200、UTF-8、CR LF，点“打开”，发送 `PING`，应收到 `PONG`。本步骤不需下载或手动复位。
7. **暂停和日志**：发送 `STREAM`，每约 100 ms 有序号输出；开启时间戳。点“暂停显示”，等 3 秒再点“继续显示”，应看到暂停期间保留的数据。上滚不应持续被拉回底部。复制、保存日志并比较末尾内容；暂停时保存应与冻结视图一致。发送 `STOP` 停止输出，再清空。
8. **HEX 和编码**：打开 HEX，发送 `BINARY`，应出现 `00 01 0a 0d 7f 80 ff c3 28 00 7e`；此时不添加文本时间戳。回到文本，UTF-8 下发送 `UTF8`；切换 GBK 后发送 `GBK`，中文应正常。结束恢复 UTF-8。
9. **热插拔回归**：只拔 USB 转串口，等待 5 秒再插回。列表应更新，已打开的监视器应恢复；再次 `PING`。ST-LINK 保持连接。此项需要你操作，本轮未重做实物测试。

串口显示保留最近 10,000 行；HEX 保留最近 64 KiB。暂停不是无限存档，保存日志导出当前可见模式的缓冲快照，不是持续录制整个会话。

## 醒后测试：下载与硬件，按需进行

1. **ST-LINK 回归**：原工程选择 ST-LINK，BOOT0=0，点击运行。底部状态栏应显示 ST-LINK 及当前识别/写入/校验阶段；有真实进度事件时显示百分比。成功后程序启动、`PING` 有应答，不必预先手动复位。
2. **手动 ISP 回归**：自动下载保持关闭。选择串口 ISP，BOOT0=1、BOOT1=0，按复位后下载。下载结束按提示 BOOT0 改回 0，再复位。原监视器自动让出端口并恢复；启动文本使引导收起，`PING` 有应答。
3. **浮点输出**：在已初始化 USART1、已重定向 `printf` 的测试程序中增加 `printf("FLOAT %.1f\r\n", 1.5);`。开启浮点选项，编译下载，串口应输出 `FLOAT 1.5`。测试完恢复源码。此前自动测试已经验证真实 ELF 链接包含 `_printf_float`，此步验证板端输出。
4. **兼容芯片确认**：先在测试工程设置中选“兼容芯片”，点运行后选择取消，应不编译下载、不接触探针。实际非 ST 芯片只有在核对型号和手册后才确认继续；不支持的 ID、容量或保护状态仍应拒绝。完成后把正常 ST 工程来源恢复为 ST。没有兼容芯片时只验收取消流程，实物兼容性继续待测。
5. **DTR/RTS 电路**：只有 USB 转串口确实引出 DTR/RTS、且电路确认可独立控制 BOOT0/NRST 时才进行。核对 3.3V 电平、控制线是否反相，BOOT1=0，移除与控制线冲突的 BOOT0 固定跳线。在工程设置填写对应有效极性，确认接线后启用。使用可恢复的 F103C8 测试芯片，点击串口下载，应自动进入 Bootloader、备份、写入、读回成功后自动复位；随后 `PING` 验证运行。连续下载两次、打开/关闭监视器及重连后确认没有意外复位或卡在复位状态。驱动开关端口可能产生控制线瞬态，须用实际电路验收；不满足条件就保持关闭，继续手动 ISP。

本轮没有实物证明 DTR/RTS 电路或非 ST 芯片工作正常，验收表分别标为 `passed_host_pending_hardware`，不能作为已验证硬件支持发布。自动下载只提供 DTR 控制 BOOT0、RTS 控制 NRST 的配置，不覆盖交叉耦合等其他下载电路。

## 代码与依据

- `nodu-project-dialogs.tsx`：模块、工程设置、工具包弹窗。
- `nodu-embedded-model.ts` / `nodu-embedded-panel.tsx` / `nodu-monitor-log.ts`：诊断过期、串口快照与日志。
- `project.rs` / `service.rs` / `toolkit.rs`：模块原子创建、设置校验、确认门禁、工具包详情。

串口 ROM 命令格式按 ST 的 [AN3155 USART Bootloader 协议](https://www.st.com/resource/en/application_note/an3155-how-to-use-usart-protocol-in-bootloader-on-stm32-mcus-stmicroelectronics.pdf) 核对，模拟测试覆盖分页擦除、四字节填充、ACK/NACK、完整读回和错误后不运行。本轮未更改选项字节或解除读保护。
