## 实现

- 把同一产品工具栏在极简模式移入52px左侧栏，专业模式移回顶部，保留编辑器、面板、串口和终端对象。

- 新增 `nodu.c.flash`，只使用已保存且有效的当前固件；缺构建、已过期、未保存构建输入、被篡改产物均拒绝；延用后端芯片/摘要/备份验证。
- K210直接运行/停止，不开放扇形。ESP构建与K210后台运行状态隔离。
- 用户先要求Keil参考透明PNG，后实看认为过于复杂，最新决定恢复简洁SVG：编译用锤子，烧录用向下箭头和托盘，运行使用标准三角形并执行编译及烧录。生成素材仅保留在设计记录 `icons-keil-v1/`，不进入产品包。圆形44px主按钮；最新改为三个独立44px圆形选项，沿以主按钮为圆心的右上圆弧排列，不绘制扇区底板。

## 解锁后桌面回归与取消等待修复（2026-10-24 15:28）

用户已明确没有接 ST-LINK 或 USB 转串口，本轮仅验收界面、离线编译和无设备错误，不做真机烧录/复位。

真实 Electron 复现了另一处问题：旧串口等待状态点击“停止”后仍保留进入 Bootloader 引导，导致选择控件锁定。`stop()` 先让下载 intent 失效，下载异常分支随之跳过；原逻辑只清理 `exitBoot`，漏了 `enterBoot`。修复后，取消请求、worker 收尾和已结束的遗留引导分别处理；旧 run 的迟到事件不得复活引导；写入过程仍等待 worker 安全结束，检测过 ROM 的情况保留恢复 BOOT 引导。停止 RPC 失败可重试，切工程或新操作不会被旧取消响应覆盖。

还补齐系统串口的隐式继承保护：蓝牙/系统调试口不作为默认 ISP 目标；用户显式选择和 USB 热插拔记忆保留。此次预览里的 Bluetooth 可能是历史显式选择，未证明它来自自动选择。通过设备 UI 将此测试窗口改成不打开串口，确认原系统端口监视器关闭；重载后空选择保持。

## 目标芯片面板密度与连接逻辑（2026-10-24）

根据用户“空间浪费很多、仔细梳理功能逻辑”的反馈，极简模式下的 STM32 设备弹层改为与设置弹层一致的紧凑表单。外框宽 304px，圆角 8px，常规行高 32px；芯片型号与刷新同排，内核、Flash、RAM 汇为一行。无设备、无备份的生产组件内容实测为 302×211px，无水平溢出。专业模式保留原分区布局，K210 不采用这个 STM32 紧凑分支。

本轮同时修正连接与恢复的状态边界：
- 指定的 ST-LINK 掉线仍保留为“未连接”，不静默切到自动或另一个下载器；实际用于识别的下载器消失时撤销旧芯片身份。
- 切换工程目标、下载方式、下载器或 ISP 端口后清理旧识别结果及其备份上下文；ST-LINK 下只切换监视串口不撤销芯片身份。
- 刷新、识别、备份加载均复核工程、连接及请求顺序，迟到响应不覆盖新选择；保存、下载、BOOT 引导和监视器切换期间限制冲突操作。
